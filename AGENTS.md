# Live Documentation: working notes for agents

This is the one place agents are told how to work in this repository. Vendor-specific files (`CLAUDE.md`, `.github/copilot-instructions.md`) only point here.

## What this is

Live Documentation turns a folder of source files into a map you can look at. It writes one markdown file per source file describing what that file exposes and what it is wired to. The Explorer (a static web page), the CLI, and the VS Code panel are renderings of those files and nothing more. It exists so a person can see how a system's pieces connect without reading the code or drawing the diagram by hand.

The full statement of intent is [the vision](.mdmd/layer-1/vision.mdmd.md). Read it before proposing features.

## How to work here

- **You own the code.** This is a single-owner repository where nearly every line was written by an agent. Nothing is "pre-existing" or "not my code." If a file can't be justified, delete it.
- **Stop at forks.** When there are two reasonable ways forward, or an assumption would decide the design, stop and ask. Do not pick one and keep going. An assumption at a design fork is a no-go: "stop generating implementations and discuss" (2026-03-23, re-affirmed 2026-10-01).
- **Plan in the chat, then execute with low chatter.** Describe the broad set of intended changes in the chat, get the owner's yes, then work with high agency and few check-ins: surface blockers and forks, not progress reports. Write progress down before reading more, so a compaction cannot take it (2025-10-31, 2025-11-10, re-affirmed 2026-10-01).
- **Fix causes, not gates.** Never lower a threshold, exclude a path, skip a test, or add a workaround to make a check pass. If a check is wrong, fix the check and say so. A passing suite is not the goal; being correct is. An excluded path is a cheat window the next agent will climb through, and a test that cannot fail is a hallucination: test nontrivial inputs and the edge cases as they are learned (2026-01-16, 2026-03-23, re-affirmed 2026-10-01).
- **No workarounds; do it the right way.** Take the higher-effort, unambiguously more correct path; a workaround is acceptable only when the owner asks for one. A wall is where to pause and discuss, not a thing to route around: "obstacles are almost always where joyous real development happens" (the owner's Copilot instructions, 2025-10-19 to 2026-02-23, re-affirmed 2026-10-01).
- **Say what's true.** Disagree with the owner when the text says otherwise. Don't flatter. Don't invent deadlines or time estimates. Report failures with their output. In a disagreement about what a picture shows, the owner's eye decides; in one about textual facts, correct them (2026-02-23, re-affirmed 2026-10-01).
- **Prefer the simplest complete, correct form.** “A thing should be as simple as possible, *and no simpler*.” Delete duplication and unnecessary machinery; preserve the behavior, evidence and distinctions the task requires. When simplification sacrifices correctness, completeness or legibility, it has gone too far. This applies to code, documentation and design alike.
- **Leave a clean workspace.** Clean up temporary and intermediate artifacts from your work. When you encounter questionable tracked or untracked files, take initiative: inspect their contents, consumers, git history and relevant chat provenance, then remove them if no justified purpose remains. Missing chat provenance is a reason to investigate, not sufficient evidence for automatic deletion; captures have gaps and useful generated files need not have individual chat citations. Preserve source captures and unique findings under the documentation rules. Record consequential deletions and their reasons in the root session record; use ordinary deletion commits for tracked cruft. A problem predating the current context is still ours to understand and fix.
- **The root agent owns delegated cleanup.** Subagents are welcome, at most five running at once, and some will halt before handing back, so the root re-checks their unfinished work (2026-10-01). Subagents work within their assigned scope, report files created or changed and unfinished work, and leave unrelated cleanup and shared history/memory maintenance to the root agent. The root reviews their artifacts, carries forward useful findings, and removes disposable outputs. The new-chat bootstrap and conversation-record routines below belong to the root agent; subagents read applicable guidance and task context without starting another archive/handoff cycle.
- **Read the whole file** when asked to read a file. No sampling. A summary's claim that a file was read is not a reading, and "the user can always tell" (2025-11-11, re-affirmed 2026-10-01).
- **Bootstrap new chats from the recent story.** After reading this guidance and Memory, read the five most recent session summaries in full, oldest to newest (all available if fewer than five). Then create or finish the immediately preceding session's summary if its captures are available and it is missing or incomplete. Follow the [handoff routine](AI-Agent-Workspace/ChatHistory/README.md#session-handoff-routine), respect an explicit user override, and continue the requested work. When asked what comes next, rank against the vision's order of work and direction.md's Next, not against the last session's open ends: the recent story is context, not the arc (2026-10-07). Summarize the current chat when the user asks at chat end; compaction resumes the current record instead of starting this routine again.
- **Keep the conversation record as you work.** At the beginning of each user turn, preserve the newly received user messages and any preceding visible root-agent response not yet recorded. Keep only the root agent's conversation with the user; do not persist subagent conversation histories. Separate verbatim messages from authored interpretation; never reconstruct missing wording as a quotation. Maintain stable turn references, checkpoint consequential work, and record outcomes before finishing. After compaction, consult the session's resumption notes and relevant source turns before continuing. Never attempt to extract reasoning or hidden analysis from any agent trace in any harness. When recovering messages from logs, admit only explicitly user-facing message types; exclude reasoning, tool payloads and subagent threads before emitting or saving text. The purpose is continuity and an audit trail of what was said and done. Follow the [ChatHistory convention](AI-Agent-Workspace/ChatHistory/README.md#recording-as-work-proceeds).
- **Look at what you built.** After changing the Explorer, build it, open it and take pictures of the change into `AI-Agent-Workspace/Screenshots/<date>/`, named in that folder's README, so that a sense of the UI accrues in the workspace; the owner wants the tool to be "a reliable panopticon of itself" (2026-09-29). If the Explorer was unhelpful for looking, ask why and whether that could be fixed. Playtest a visual change by eye until it is right, then write the Playwright tests that keep it; tests written before the looking lock in the wrong picture (2026-03-26, re-affirmed 2026-10-01).
- **Git needs care.** Never run bulk `git checkout`, `git restore`, or `git clean`. Commit when you are confident in the commit's safety and quality; that is the owner's standing grant (2026-09-27), and they push. Commit messages must make sense to an outsider: no internal IDs, no "Option C."
- **Keep the product separate from this workspace.** This repo's own conventions (the `.mdmd` root, `layer-4`, the `.mdmd.md` extension) come from `.live-docs.config.json`. Product code reads configuration; it never hardcodes these.

## Workspace facts

- Linux devcontainer, bash, Node 22 (`.nvmrc`), TypeScript 5.
- npm workspaces: `packages/engine` (configuration, language adapters, source analysis, the Live Doc grammar and the graph derived from the docs), `packages/explorer` (the static bundle builder and the browser client), `packages/generator` (the Live Doc generator), `packages/cli` (not yet publishable). CLI entry points are `scripts/live-docs/*.ts`. Pathfinding is in the engine (`live-docs/pathfind.ts`); `inspect`'s input and output code, and the SlopCop and documentation-link audit libraries, sit beside their scripts under `scripts/`.
- Live Docs for this repo are generated into `.mdmd/layer-4/`, one per tracked source file. Shipped defaults are `.live-documentation/source/*.md`. The graph index derived from them is written to `.mdmd/index.json` (`<root>/index.json` in general), gitignored; every consumer derives it afresh from the docs.
- `.mdmd/layer-1` through `layer-3` are authored docs; each says in its first lines whether it is current or historical.
- `AI-Agent-Workspace/Probes/` holds dated records of design probes: the brief, each builder's findings and a few screenshots. The probe pages themselves are disposable and never committed. The layout lab's run reports also live here (the owner's choice, 2026-10-06), under the day's folder; its captures of the page are rebuilt on demand and not committed.
- `AI-Agent-Workspace/Screenshots/` holds dated pictures of the built Explorer, taken by the agent after changing it, each named in the folder's README. The probe records keep their own pictures.
- `AI-Agent-Workspace/Gallery/` holds the representative pictures of the same subjects in every view and probe, copied under subject and view names with their origins named, and side-by-side sheets that its `sheets.sh` rebuilds, so that a comparison across views starts from one folder rather than a search (the owner's suggestion, 2026-10-01). The dated screenshots and probe records stay the evidence; the gallery is the comparison set.
- `AI-Agent-Workspace/Research/` holds dated surveys of formats and prior art, gathered for a design step, with a source for every claim. A survey records what existed on its date and decides nothing.
- `AI-Agent-Workspace/ChatHistory/` is the development system of record. Preserve raw captures; summaries provide a stable, harness-neutral path from a file's provenance to the conversation and verified commits. The naming, source-coverage rules and session handoff routine are in [its README](AI-Agent-Workspace/ChatHistory/README.md). Historical statements are evidence of what was said, never automatically current facts. Never extract private reasoning blocks.
- The workspace mount is case-insensitive (a Windows-backed volume), so a file-existence probe must check the directory listing: `Account.py` finds `account.py`.

| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |

| `npm run live-docs:inspect -- --from A [--to B] [--direction inbound\|outbound\|both] [--json]` | Dependency pathfinding. Run it before and after risky edits                                        |
| `npm run live-docs:board -- <board.md>`                                                         | Read a board, check it, join it to the docs and print its things, doors and wires with their bases |
| `npm run oracle:index -- <fixture>`                                                             | Write a fixture's compiler-resolved edges to its `expected/` (needs its language's indexer)        |
| `npm run oracle:compare -- <fixture>`                                                           | List where the shipped generator disagrees with a fixture's expected edges                         |
| `npm run live-docs:visualize`                                                                   | Build the static Explorer into `dist/explorer/`                                                    |

| `npm run layout:lab -- <capture\|sweep\|restarts\|verify> <bundle/scope>`                         | The Local Map layout lab: capture a deck scope's cards from the built page, sweep the layout's levers headlessly, tabulate the order step's starts against the page's costs, verify a configuration in the page with the deck's instrument |
| `npm run safe:commit`                                                                           | The full pre-commit chain. CI runs the same chain as `ci-check`                                    |

After changing source, run `live-docs:generate` and commit the regenerated docs with the code. For local verification, run the fullest applicable suite with `npm run safe:commit -- --e2e`, including Playwright; the owner prefers the additional machine time for stronger verification (2026-09-30). Keep CI's existing default without Playwright. Report failures and environment blockers explicitly rather than silently falling back to a narrower pass.

## Documentation rules

- Markdown is canonical. Everything the Explorer or CLI shows must be derivable from the Live Docs. If a picture needs a fact the docs can't carry, grow the doc format rather than add a side channel. The graph index is derived from the docs and never committed; consumers read the graph, not the markdown. Headless and UI are peers: whatever a person can learn or do by clicking, they can also do by a command or take out as data, markdown or JSON, and both know what the Live Docs know, "no more, and no less" (2025-11-08, 2025-11-24, re-affirmed 2026-10-01). Agents are served through what a person exports, not through doors of their own (2026-10-03).
- Never hand-edit a `LIVE-DOC:BEGIN` … `LIVE-DOC:END` region. Fix the generator. The parser refuses anything outside the grammar, so a hand edit fails lint.
- Authored `Purpose` and `Notes` explain what a file is for and what a maintainer must know. Write them for a new reader, not as a changelog. When provenance explains an origin or consequential choice, link the relevant summary turn; its source references and verified commits make that history auditable. Such a citation is optional.
- Every authored doc is either current or historical. Historical docs say so in their first lines. Current docs may cite them as provenance but never depend on them for facts.
- Before deleting an authored document, find out why it was written (`git log`, and the chat record under `AI-Agent-Workspace/ChatHistory/`) and carry forward anything still true that lives nowhere else.
- Anything carried forward from the chat record or a retired document is written as dated history or as an open question, never as a current decision, unless the owner re-affirms it. Old certainty is the easiest thing to import and the hardest to notice.
- No requirement-ID schemes (`CAP-`, `REQ-`, `UC-`, `LD-`). Name things in plain words.

## Explorer client (`packages/explorer/src/client/`)

- **Preserve orientation.** A person following connections, changing scale, opening evidence or returning to a place must be able to keep their bearings. Maintain recognizable subjects and context, and use transitions to explain spatial changes. Inspect journeys in motion as well as still pictures; a good screenshot does not establish continuity. The Explorer is the owner's window into the software as it is built (2026-09-30).
- **Design the interface grammar across scales.** File symbols and system endpoints share the problem of showing exposed interfaces, relevant connections and selectively revealed contents. The owner reopened the 2D/3D split and separate-view assumption on 2026-09-30; existing layout conventions below describe the current designs, not a prohibition on exploring alternatives. Competing design suggestions are variables to test together, not successive architecture decisions. Compare boundaries by what can improve independently and how the vision's existing stretch goals would cross them. Preserve useful distinctions and orientation; no replacement has been selected. See [the clarification](AI-Agent-Workspace/Memory/direction.md#the-september-2026-reframe).
- **Make visible text earn its space.** Avoid decorative taglines, redundant subheadings and repeated explanatory callouts. Keep names, necessary control labels, relevant evidence and honest indications of hidden content; put optional instruction in help or contextual disclosure. Use recognizable icons for repeated actions when they communicate the operation, with accessible names, keyboard access, state and hover/focus tooltips; visible text is not required on every button. Preserve readable entity names and evidence. Do not shrink text to make room. The owner identified excess callouts on 2026-09-30 and specifically requested icon controls for card actions on 2026-10-01.
- Layout math lives in pure modules with Vitest tests; DOM modules render from them. No jsdom tests: they pass when the UI is wrong. Visual behavior is verified with Playwright.
- Design faults that geometry can name are tested: `tests/e2e/design-audit.ts` finds labels that collide and text that is cut off, and each state a view can be in gets an audit spec, over this repository and the estate sample (the owner's ask, 2026-09-29). A view keeps its own words apart; the World Map settles its movable labels after every camera move so the audit holds under zoom.
- The visual language is consistent across scales: inputs enter on one side and outputs leave on the other, colour-coded the same way everywhere: blue is the side that offers (a file's symbols, a system's routes and tables) and green the side that uses them, inside a system and between systems (the owner's word, 2026-09-29). Inside a system what a file uses enters on the left and what it offers leaves on the right. Fade the irrelevant; never boost the relevant. No emoji anywhere in the UI.
- Prefer a symbol's origin file over a barrel re-export when resolving links.
- View-specific doctrine (the Membrane Map's pin spectrum, font-size invariance) lives in `.mdmd/layer-3/membrane-map.mdmd.md`, and the vision's "one crafted rendering per scale" may revise it. Don't treat either as settled.

## Correctness

- Ground truth is never filtered. Whatever produces benchmark expectations, its output is not trimmed to fit the analyzer; adapter blocklists may remove only true framework or builtin names; a filter that can only raise false negatives is a bug.
- Adapters are the product, oracles are the ground truth, and nothing grades itself. A "precision" that compares an analyzer to a re-run of the same analyzer is not a measurement.
