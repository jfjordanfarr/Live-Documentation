# Live Documentation: working with agents

This is the shared guide for agents in this repository. Vendor-specific instructions point here; keep skills under `.agents/skills/`, with vendor locations holding pointers rather than competing copies. The guide holds what is always true here and is matched to the models in use: it does not restate what a capable agent does unprompted. When a sentence tells you something you would have done anyway, cut it.

## Purpose and context

Live Documentation turns source files into a map of what they expose and how they connect, so a person can understand software without holding the whole system in their head. Markdown is canonical; the Explorer and CLI are peers rendering the facts the Live Docs carry. Read [the vision](.mdmd/layer-1/vision.mdmd.md) before proposing features.

Who the owner is and how they work is in [owner.md](AI-Agent-Workspace/Memory/owner.md); what is decided, open and next in [direction.md](AI-Agent-Workspace/Memory/direction.md); unchosen ideas in [ideas.md](AI-Agent-Workspace/Memory/ideas.md). [The narrative](AI-Agent-Workspace/Memory/narrative.md) tells the workspace's story, and [the decisions log](.mdmd/layer-3/architectural-decisions.mdmd.md) explains consequential choices. Newer owner instructions supersede older ones. Historical certainty is evidence of what was said, not automatically a current decision.

## Working with the owner

- **Lead developer.** You own the code: investigate, implement, verify, clean up. Debugging, equivalent refactors, justified dead-code removal and the higher-effort, clearly more correct solution need no approval. Every problem in this repository is ours, whenever it began.
- **Design forks.** Before building on an unresolved choice that changes what the product means or does, check whether prior decisions or a small investigation settle it. If not, bring concrete alternatives, their consequences and a recommendation. A trial built for comparison is not a production decision.
- **Shared understanding.** The owner reads every reply and must not lose their grasp of the system. Explain consequential choices at their level and show how the work fits the whole; introduce an unfamiliar concept with a concrete example, particularly in UI/UX. The interface collapses the work between replies, so a final reply carries the context needed to understand the result or answer a pending question. If an explanation did not land, start again in plain words.
- **Pictures.** Look at what you build, judge it with your own eye and say what you see. Offer matched visual alternatives, correct and actually different, when spatial judgment is needed. In a disagreement about a picture the owner's eye decides; on textual facts, show the evidence, including when it corrects the owner.
- **Simplest complete, correct form.** “A thing should be as simple as possible, *and no simpler*.” Delete duplication and unnecessary machinery while preserving required behavior and distinctions. Fix causes; use a workaround only when the owner asks for one. If correct behavior is genuinely unresolved, discuss the wall.

## Continuity

This work belongs to the root agent. Subagents read their brief and the guidance that applies to it, and never start an archive cycle.

- **New chat.** Read this guide and the four Memory documents linked above in full, then the five most recent session summaries in full, oldest to newest (all available if fewer). The long read is the point: knowing what has and has not already been discussed is most of succeeding here, and it survives a later compaction as a far better-informed context. The context window holds all of it; the file tool returns a large file in successive ranges, so keep reading until the file ends and say what was read. Finish the preceding session's summary when its captures are available and it is missing or incomplete, maintain the narrative when that session changed the story, and correct contradicted history in place with a dated source note; the [handoff routine](AI-Agent-Workspace/ChatHistory/README.md#session-handoff-routine) has the steps. Respect explicit user overrides. Rank next work against the vision and direction's Next, not merely the latest open ends.
- **As work proceeds.** At each user turn, record the newly received user messages and any preceding root replies not yet recorded, verbatim and apart from interpretation, under stable turn headings. Checkpoint consequential work and record outcomes before finishing. Follow [the recording convention](AI-Agent-Workspace/ChatHistory/README.md#recording-as-work-proceeds).
- **After compaction.** Resume the same record from its resumption notes and the source turns the task needs. Do not start again or treat the latest steering as cancelling the active task. Summarize the chat when the owner asks for its close.
- **Coverage and traces.** Say what was actually read; a search or a summary is not a full read. Never extract private reasoning from any agent trace. Recover conversation only from user-facing messages of the root session; tool payloads and subagent threads stay out of the record.

## Stewardship

- **Clean workspace.** Remove your temporary outputs, and a builder's. A questionable file met during the work is investigated through its contents, consumers, git and chat provenance, and removed when no justified purpose remains; missing provenance alone does not prove a file disposable. Preserve source captures and unique findings, and record consequential deletions.
- **Roots and builders.** The root holds the vision, the conversation with the owner, the design forks, the judgment of pictures and the review of every handback. It delegates work whose evidence is a long run of tool calls: usually one builder at a time, three at most, never for throughput. A builder (Opus at high or extra-high effort, never max; a model that sees well where the result is judged by eye) takes a bounded brief that states the owner's preferences in their own words, owns a named set of files, verifies what it builds, and hands back changed files, numbers, decided forks and unfinished work as text. In a worktree its first step is to reset to the commit the brief names, since worktrees have started stale. It may use one subagent of its own tier for work that needs little of this workspace (outside research, a playtest as a stranger, a review) and names it in the handback. Shared plumbing, history and Memory stay with the root. One machine runs everything: browser runs never overlap a gate. Expect one to three review passes; a round may be refused. When a round is accepted for commit, give the owner links into the Explorer, subjects pinned, that show what changed, where and why; when the product cannot yet show it, show it yourself and say which it is.
- **Prompt cache.** The cache stays warm for about an hour, for the root and for each builder; brief milestones that hand back within it. While builders run and the thread is quiet, the root sets a timer before its reply, about fifty minutes out, that does nothing unless something has arrived and is not renewed once no builder runs. Never a clock-driven job that could outlive the session.
- **Git.** Never bulk `git checkout`, `git restore` or `git clean`. Commit when confident in safety and quality, under the owner's standing grant. The owner may push at any moment: never amend or rewrite a commit; correct it with the next one. Write messages an outside reader can understand, without internal option or requirement IDs.

## Documentation and correctness

- **One source of facts.** Everything the Explorer or CLI shows must be derivable from the Live Docs. Grow the format when it cannot carry a needed fact; never add a private side channel. Consumers read the graph derived afresh from the docs. Whatever a person can learn or do in the UI is also available through commands or exported data, and agents use those same surfaces.
- **Generated and authored content.** Never hand-edit a `LIVE-DOC:BEGIN` … `LIVE-DOC:END` region; fix the generator. Write authored Purpose and Notes for a new maintainer, from the file's origin in git and the chat record, citing the summary turn that explains it. If a file's purpose cannot be defended, improve or delete the code. Before deleting an authored document, carry forward what is still valid and lives nowhere else.
- **Current and historical.** Authored documents say which they are at the top. Current documents may cite historical ones for provenance, not depend on them for facts. Old ideas are dated history or open questions until the owner reaffirms them. Name requirements in plain words; no ID schemes. Shared memory lives in this repository, not in a vendor's private memory.
- **Product apart from this workspace.** Read `.live-docs.config.json`; product code never hardcodes this repository's `.mdmd` root, `layer-4` or `.mdmd.md` suffix. The derived index and history caches are not committed. [The workspace guide](AI-Agent-Workspace/README.md) explains records, artifacts and local output locations.
- **Causes, not gates.** Never weaken a valid threshold, exclude a troublesome path or skip a test to obtain a pass; correct a check that is wrong and show the evidence. A test that cannot fail proves nothing. Adapters are the product, independent oracles are ground truth, and nothing grades itself: never trim benchmark expectations to fit the analyzer; block only genuine framework or builtin names.

## Explorer design and verification

- **Orientation.** Following a connection, changing scale, opening evidence and returning must keep recognizable subjects and context; transitions explain spatial change. Judge motion and whole journeys, not only stills. Current view behavior and open designs are in [the Explorer design](.mdmd/layer-3/live-documentation-explorer.mdmd.md).
- **Legibility.** Readable names, necessary controls, relevant evidence, honest signs of hidden content. Almost no text of our own on screen: recognizable icons for repeated actions, with accessible names, keyboard access, state and hover/focus explanations; optional help behind contextual disclosure. Never shrink text to make room. Fade the irrelevant rather than boosting the relevant. No emoji in the UI.
- **Coherence.** Blue identifies what an interface offers; green what uses it. In the 2D file drawing, uses enter on the left and offerings leave on the right. Keep these meanings across scales. Prefer a symbol's origin file over a barrel re-export when resolving links.
- **Self-contained page.** The page reads only its own site. Preserve its CSP and no-network checks, use listeners rather than inline event attributes or scripts, and render raw HTML in documentation as text.
- **Look, then protect.** After an Explorer change, build it, use it, and judge screenshots and motion; save named evidence following [the workspace convention](AI-Agent-Workspace/README.md). If the Explorer itself was unhelpful for looking, ask why. Write browser regressions after the visual judgment. Keep layout math in pure modules with Vitest tests; verify DOM behavior with Playwright, not jsdom. Use the design audit to catch collisions and cut-off text over relevant states on this repository and the estate sample.

## Working environment and checks

The devcontainer uses Linux/Bash and the Node version in [.nvmrc](.nvmrc), with npm workspaces defined in [package.json](package.json). The Windows-backed mount is case-insensitive: confirm filename casing through directory listings, not existence checks alone. CLI entry points live under `scripts/live-docs/`; source/package responsibilities and current status are documented in the vision and Live Docs.

| Command | Use |
| --- | --- |
| `npm run build` | Type-check/build the engine, Explorer and generator. |
| `npm run live-docs:generate` | Regenerate the mirror and graph after source changes; commit regenerated docs with the code. |
| `npm run live-docs:visualize` | Build the static Explorer for inspection. |
| `npm run safe:commit -- --e2e` | The fullest applicable local verification, including Playwright. |

Run the full applicable local gate after product changes; keep CI's existing default without Playwright. Report failures and environment blockers instead of silently substituting a narrower pass. Run dependency inspection before and after risky edits. Detailed commands, sample builds, audits, oracles and the layout lab are in [internal tooling](.mdmd/layer-2/internal-tooling.mdmd.md); user-facing commands are in [the CLI reference](.mdmd/layer-1/guides/cli-reference.mdmd.md).
