**The Membrane Map's docs hold three, each in no current document and not in the code's comments:**

1. **Why a mixed folder's files leave the treemap.** [layout.ts.mdmd.md](../../../../.mdmd/layer-4/packages/explorer/src/client/views/membraneView/layout.ts.mdmd.md), line 19, and [browse-renderer.ts.mdmd.md](../../../../.mdmd/layer-4/packages/explorer/src/client/views/membraneView/browse-renderer.ts.mdmd.md), line 19: in a folder holding both files and folders, the files are drawn as a card grid below the folder tiles, "solving the area-crushing problem where files at weight=1 were dwarfed by directories at weight=N". The code says what, not why ([layout.ts](../../../../packages/explorer/src/client/views/membraneView/layout.ts), lines 174 to 176). The fault was the owner's find: "**directories which contain both files and other directories do not render the files at the size expected by the view seen when a directory contains only files**. This makes pinning symbols impossible in several views." ([2026-03-27.1.md](../../../ChatHistory/2026/03/2026-03-27.1.md), line 412, the owner), and the choice theirs: "Please pursue Solution C." (line 946). The other three ways weighed that day, a size floor, a separate shelf for files and logarithmic folder weights, are in that transcript only (lines 863 to 942). `membrane-map.mdmd.md` does not mention mixed folders; the only other written account is the Development Journey ([Project Development Journey.md](../../../Notes/Project%20Development%20Journey.md), line 1017), which the bearings class as bathwater as a source.
2. **Why a membrane lets its contents out.** [membrane.css.mdmd.md](../../../../.mdmd/layer-4/packages/explorer/src/client/styles/membrane.css.mdmd.md), line 18: `.membrane` is `overflow: visible` because an earlier `overflow: hidden` "clipped card grids". The stylesheet line has no comment ([membrane.css](../../../../packages/explorer/src/client/styles/membrane.css), line 37). Layer 3's "Two-Phase Sizing Model" ([membrane-map.mdmd.md](../../../../.mdmd/layer-3/membrane-map.mdmd.md), lines 121 to 129) holds the design and not the failure it replaced. The doc credits "visual playtesting"; the reason was the owner's, and it is in no current document: "No matter what, you're going to have to make it so that the directories which bound and compound and grow as we "zoom" (scare quotes) in are _squishy_ and _wobbly_ and capable of expanding to very large sizes if their cumulative contents demand it. For pathfinding (multi-pinning of symbols along many node hops), the horizontal space will overflow no matter what, and we will expect the users to drag and pan by mouse or by finger on mobile." ([2026-03-23.1.md](../../../ChatHistory/2026/03/2026-03-23.1.md), line 6197, the owner). The same turn asks for pinch zoom on a phone to equal the wheel on a desktop, and for panning with "the natural gliding that they are used to".
3. **Why the pin-active columns are a fixed width.** [pin-active-renderer.ts.mdmd.md](../../../../.mdmd/layer-4/packages/explorer/src/client/views/membraneView/pin-active-renderer.ts.mdmd.md), line 20: 320px columns "so card dimensions remain stable when the column gap slider is adjusted". The source sets the width without a comment ([pin-active-renderer.ts](../../../../packages/explorer/src/client/views/membraneView/pin-active-renderer.ts), line 150). The same line's "inner band grids also use fixed widths" has been false since 2026-03-30 (`4fb58d69`): they use `1fr` (lines 242 and 262).

**Reasons in the docs that live elsewhere too**, so nothing is lost if the docs go: the back trace as a PCB's back copper (`routing.ts`'s doc, line 18; [membrane-map.mdmd.md](../../../../.mdmd/layer-3/membrane-map.mdmd.md), line 53); one pin model instead of Browse, Explore and Compare modes (`pin-state.ts`'s and `detail-levels.ts`'s docs; layer 3, line 59); the tile badge thresholds (`browse-renderer.ts`'s doc, line 18; its source, line 254); the column gap set on the root so both views see it (`tuning.ts`'s doc, line 18; its source, line 70); persistent against transient hover classes (`focal-overlay.ts`'s doc, line 24; its source, line 797).
