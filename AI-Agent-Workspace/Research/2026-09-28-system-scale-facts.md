# System-scale facts: what exists to parse, borrow, or write

_A survey gathered on 2026-09-28 by a subagent with web access, for the design of openings and the basis of an edge (see [openings.mdmd.md](../../.mdmd/layer-3/openings.mdmd.md)). It records what existed on that date, with a source for every claim; it decides nothing. The judgements at the end of each section were read by the agent and match what was built that day: a small SQL scanner rather than a library, a hand-written project reader, contract files as a second source, and a declared block that no existing format carries._


Package versions, publish dates and licences below were read from the npm registry API (`https://registry.npmjs.org/<name>`) on 2026-09-28; the linked `npmjs.com` page shows the same record. The tool already ships `web-tree-sitter`, `@vscode/tree-sitter-wasm` and the TypeScript compiler; anything else named here would be a new dependency.

Judgement. The estate carries no contract file: its WCF contracts are C# interfaces and the Web API 2 gateway has no swagger.json, so contract files are a second source, not the first. When they exist, OpenAPI is the one to parse first, and the choice is between @scalar/openapi-parser (widest version coverage) and @readme/openapi-parser (a fork of the incumbent with 3.1); both are MIT and current. Whatever is chosen must resolve `$ref` from files only: swagger-parser v12.0.0 removed "the ability to request internal urls in the default http resolver", which is the right direction for an offline tool (https://github.com/APIDevTools/swagger-parser/releases). WSDL is worth reading only when a `.wsdl` is checked in or generated as a build artefact; `soap` reads local files and gives ports and operations without a network call. Nothing to write from scratch here beyond the mapping into the doc format and one shared path-template normaliser used again in items 2 and 3.

Judgement. Everything in this section must be written; no JavaScript library extracts .NET routes, and the commercial tool that does (CAST, item 7) is not borrowable. The work is small because the grammar is already loaded: one query over `attribute_list` on class and method declarations for Route, RoutePrefix, the seven Http verbs, AcceptVerbs, ServiceContract and OperationContract; `string_literal` and `verbatim_string_literal` give the text, anything interpolated or concatenated is recorded as an opening with an unresolved template and the vision's "declared" tier. Verbs come from the attribute or the method-name prefix. Convention routes need one extra pass over `WebApiConfig.cs` for `MapHttpRoute` templates, expanded by the `ApiController` subclasses in the same project. For the estate this yields exactly the gateway's `api/payments` and `api/payments/{paymentId}` and the hub's `IPaymentHub.PostPayment` and `GetPayment`, which are the server ends of the two remote hops the hand-verified file records.

Judgement. For the estate the consumed side is mostly configuration, and configuration is plain XML: parse `Web.config` and `App.config` with fast-xml-parser and record every client endpoint (name, address, contract, binding), every service endpoint with its base address resolved, every appSettings value that parses as a URL, and every connection string's server and database. In C# the joins are short and worth doing exactly: `ChannelFactory<T>("PaymentHub")` to the client endpoint of that name; `ConfigurationManager.AppSettings[Key]` through the constant `Key` to the appSettings entry (the portal's `Globals` pattern is a two-hop constant lookup inside one repository); `new Uri(baseUrl, "api/payments")` and `"api/payments/" + paymentId` to a template `api/payments/{...}`; `SqlQuery` and `CommandText` literals beginning `EXEC` or `EXECUTE`, or `CommandType.StoredProcedure`, to a procedure name; `base("name=PaymentsDb")` to the connection string. On the SQL side, adopt no JavaScript parser yet: the two candidates do not document `CREATE PROCEDURE` or four-part names and the third is GPL; a hand-written scanner for `CREATE PROCEDURE`, table names after `INSERT INTO`, `UPDATE`, `DELETE`, `FROM` and `JOIN`, four-part identifiers and `OPENQUERY(server, ...)` covers the fixture, and ScriptDom can be the oracle for it since the devcontainer has the .NET SDK. Record `Web.*.config` transform values as additional candidate addresses tagged with the configuration name rather than pretending the checked-in host is the deployed one.

The academic comparison is also a method to copy: the fixture's `hand-verified-edges.json` already is the oracle shape those papers use, and the runtime tools (Application Map, Tempo) observe the ground truth an estate could hand over later as a declared import.

- Whether node-sql-parser or @derekstride/tree-sitter-sql accept `CREATE PROCEDURE` or four-part linked-server names: neither README says, the tree-sitter grammar is split across files, and nothing was run.
- The extent of OpenAPI 3.1 support in @apidevtools/swagger-parser: the README says 2.0 and 3.0, the v12.1.0 release note says "3.1.2", and issue 169 is closed without a visible resolution.
- What @azure/bicep-rpc-client contains: its npm README is empty and the repository it points at (Azure/bicep-deploy) does not mention it.
- CAST's exact linking rules: its documentation pages are script-rendered and were read only through search summaries.
- prophet2's supported frameworks beyond what the 2024 comparison paper states; the repository page did not render its README.
- An official Microsoft list of legacy `ProjectTypeGuids` for old-style .csproj files; only community lists exist (https://github.com/VISTALL/visual-studio-project-type-guids).
- Whether the per-role JSON in MicrosoftDocs/azure-docs may be redistributed inside the tool; the docs licence was not checked.
- The exported helper names of @backstage/catalog-model (parseEntityRef and kin): the reference page returned 404.
- strong-soap's licence from its README; the registry record says MIT.
- Whether cdxgen can build a complete .NET or Java SBOM offline; its README says it detects and uses maven, gradle, sbt and dotnet.
