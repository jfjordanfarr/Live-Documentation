  When a Live Doc is a poor idea:
  1. Derived files. These are produced from other tracked files by a tool: lock
     files (already excluded), build outputs, generated code. Their intent lives
     with their inputs, so a doc would only say "generated". The .wasm is
     borderline: document its recipe files fully, and the .wasm only as an asset
     that names its source.
  2. Secrets. A committed file whose values must never reach a bundle, such as
     credentials in a .env. (upstream.env here just pins an upstream commit.)
  3. Bulk files with no meaning one by one. Hundreds of similar fixtures or
     pictures, where the folder is what has a meaning. Live Docs are per file,
     and there's no folder-level doc yet. That's why the agent workspace's 736
     pictures are excluded.

  High-churn temporary files that are tracked are, to my mind, a finding in
  themselves: either they matter, or they should be ignored. Documenting them
  forces the question, which I'd count as a benefit.

  Proposed rule: every tracked, non-excluded file gets a Live Doc, except
  derived files and secrets, each excluded by a named rule. The simplest first

  most: the .sln's project list, markdown links, workflow run steps.
