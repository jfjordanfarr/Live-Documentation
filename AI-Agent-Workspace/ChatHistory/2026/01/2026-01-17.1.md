## Current Statistical Model (Problem Analysis)

### How significance is currently computed

The coActivation.ts code uses **hypergeometric tail tests** for edge significance:

```typescript
const pValue = hypergeometricTail(totalTests, sourceTestCount, targetTestCount, edge.sharedTestCount);
```

This asks: "Given that file A is tested by X tests and file B is tested by Y tests, what's the probability of seeing ≥K shared tests by chance?"

**The implicit background:** A uniform distribution where every test is equally likely to target any file. This is computed from `totalTests` (71 in our case) divided among files.

### The Problem

The current model treats the **files** as the universe, not the **edges**. This means:
- Hub files (barrel exports like index.ts) with 17+ connections are treated with the same expected edge probability as peripheral files
- The "expected edge count" calculation uses a **global edge probability**:
  ```typescript
  const globalEdgeProbability = significantEdges.length / totalPossibleEdges;
  // For 622 nodes: totalPossibleEdges = 622*621/2 = 193,131
  // 1285 significant edges → globalEdgeProbability ≈ 0.0067
  ```
- This uniform background makes high-connectivity hub clusters appear artificially significant

### Bioinformatics Analogy

In MEME/motif enrichment, the **correct background** is:
- NOT: all possible k-mers uniformly
- BUT: the actual k-mer frequency distribution in your genome/proteome

Similarly, here the correct background should be:
- NOT: uniform probability of any edge existing
- BUT: the actual edge frequency distribution across all markdown links

## Proposed Edge-Based Background Model

### Core Insight

Use **all observed edges (markdown links)** as the background distribution, not all possible file pairs.

### What changes:

| Aspect | Current Model | Edge-Based Model |
|--------|--------------|------------------|
| **Universe** | All file pairs (N×(N-1)/2) | All observed edges |
| **Expected probability** | edges/pairs ≈ 0.67% | Per-edge frequency based on hub degree |
| **Hub correction** | None | High-degree files expected to have more edges |
| **Test: "Is this pair special?"** | Compares to uniform | Compares to expected given degree distribution |

### Mathematical Formulation

For an edge between files A and B, instead of asking:
> "Is this edge unlikely under a uniform model?"

We ask:
> "Is this edge more likely than expected given the out-degree of A and in-degree of B?"

**Degree-corrected null model** (configuration model from network science):

$$P(edge_{A,B}) = \frac{d_A \cdot d_B}{2E}$$

Where:
- $d_A$ = degree of file A (number of edges)
- $d_B$ = degree of file B
- $E$ = total edge count

For test co-activation, we'd use:
$$P(shared\_test | A, B) = \frac{tests_A \cdot tests_B}{T}$$

But now the expected count is **conditioned on the actual edge density of the graph**, not a uniform assumption.

### Implementation Plan

**Step 1: Compute degree distribution from all edges**
```typescript
// Build degree map from all dependency edges
const degreeMap = new Map<string, number>();
for (const doc of stage0Docs) {
  for (const dep of doc.dependencies) {
    degreeMap.set(doc.sourcePath, (degreeMap.get(doc.sourcePath) ?? 0) + 1);
    degreeMap.set(dep, (degreeMap.get(dep) ?? 0) + 1);
  }
}
const totalEdges = stage0Docs.reduce((sum, d) => sum + (d.dependencies?.length ?? 0), 0);
```

**Step 2: Compute expected edge probability per pair**
```typescript
function expectedEdgeProbability(nodeA: string, nodeB: string): number {
  const degA = degreeMap.get(nodeA) ?? 0;
  const degB = degreeMap.get(nodeB) ?? 0;
  return (degA * degB) / (2 * totalEdges);
}
```

**Step 3: Use degree-corrected significance test**
Instead of hypergeometric with uniform background, use:
- **Poisson approximation** for expected co-activation count
- Or **exact test** comparing observed vs expected under degree distribution

