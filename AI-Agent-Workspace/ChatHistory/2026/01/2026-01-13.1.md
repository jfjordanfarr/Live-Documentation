## How SCIP/LSIF Artifacts Are Actually Generated

### The Reality: It's a Sourcegraph Ecosystem

SCIP (Source Code Intelligence Protocol) is **Sourcegraph's successor to LSIF**. They maintain open-source indexers for major languages:

| Language | Indexer | Output |
|----------|---------|--------|
| **TypeScript/JavaScript** | https://github.com/sourcegraph/scip-typescript#%3A~%3Atext%3D%20%20%20%20%2Cissues%20when%20indexing%20large%20codebases | `index.scip` |
| **C#/VB.NET** | https://github.com/sourcegraph/scip-dotnet#%3A~%3Atext%3D%20%20%20%20%2CScipDotnet%20--%20index%20--working-directory%20PATH_TO_DIRECTORY_YOU_WANT_TO_INDEX | `index.scip` |
| **Java/Scala/Kotlin** | https://sourcegraph.github.io/scip-java/#%3A~%3Atext%3D%23%23%20scip-java.%20%23%23%20scip-javaJava%20indexer%2Cthe%20sources%20in%20the%20repository. | `index.scip` |
| **Go** | `scip-go` | `index.scip` |
| **C/C++** | `scip-clang` | `index.scip` |
| **Python** | `scip-python` | `index.scip` |
| **Ruby** | Community `scip-ruby` | `index.scip` |
| **Rust** | `rust-analyzer` exports LSIF natively | `.lsif` |

### What CI Generation Looks Like (Practical Example)

**GitHub Actions for TypeScript:**
```yaml
- name: Generate SCIP index
  run: |
    npm install -g @sourcegraph/scip-typescript
    npm install
    scip-typescript index
    # Output: index.scip at repo root
```

**GitHub Actions for .NET:**
```yaml
- name: Generate SCIP index
  run: |
    dotnet tool install --global scip-dotnet
    scip-dotnet index
    # Output: index.scip at repo root
```

### Where The Output Goes

By default, both tools write **`index.scip`** to the **project root**. This is the file our parsers would consume.

**The typical Sourcegraph workflow is:**
1. CI generates `index.scip`
2. CI uploads it to Sourcegraph's hosted service via `src code-intel upload`
3. The file is **not committed** — it's a build artifact

### The Gap For Our Use Case

Sourcegraph's workflow assumes you **upload to their service**. Our workflow would be:
1. CI generates `index.scip`
2. CI **commits** it (or stores as artifact and downloads locally)
3. Our tooling **consumes** it

This creates **two legitimate paths**:
