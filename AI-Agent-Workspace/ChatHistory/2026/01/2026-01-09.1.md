## Implementation Plan: Download Options Enhancement

### Current State

**What exists:**
- Single "Download All (N docs)" button in Knowledge Sources panel
- `downloadAllDocs()` creates a single flattened markdown file containing:
  - All Live Docs (with `<!-- SOURCE: ... -->` separators)

**What's incorrect:**
- UI text says "ZIP archive" but downloads a single `.md` file

### Technical Constraints

1. **No JSZip in browser bundle**: Previous attempt (2026-01-03) showed that JSZip can't easily be bundled with esbuild's current config. CDN loading is possible but adds complexity.

2. **Two modes to support**:
   - **Server mode**: Fetch docs on demand via `/doc` and `/bundled-docs` endpoints
   - **Static mode**: Use embedded `staticDocs` and `bundledMarkdown` maps

### Proposed Solution

#### Option A: Multiple Markdown Downloads (Simpler, No ZIP)

Replace the single button with a dropdown or button group offering:

| Button | Content | Filename |
|--------|---------|----------|
| "Download Live Docs" | All Live Documentation files | `live-documentation.md` |
| "Download Related Docs" | All Related Documentation files | `related-documentation.md` |
| "Download All" | Both combined | `all-documentation.md` |

**Pros**: No new dependencies, works identically in both modes
**Cons**: Still flattened markdown, not true ZIP

#### Option B: ZIP via CDN (More Complex, True ZIP)

Load JSZip from CDN at runtime, then create proper ZIP archives:

```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/jszip/3.10.1/jszip.min.js"></script>
```

Each download creates a ZIP with proper folder structure:
```
live-documentation.zip
├── packages/
│   ├── shared/
│   │   └── src/
│   │       └── index.ts.md
│   └── ...
└── README.md
```

**Pros**: True ZIP with folder structure, professional output
**Cons**: External CDN dependency, slightly larger initial load

#### Recommendation: Hybrid Approach

1. **Default to flattened markdown** (no CDN needed, works offline)
2. **Offer ZIP option if JSZip is available** (progressive enhancement)

For this implementation, I'll go with **Option A first** (clean UI with 3 download options as flattened markdown) since it's the simplest path forward and fixes the UI text discrepancy.
