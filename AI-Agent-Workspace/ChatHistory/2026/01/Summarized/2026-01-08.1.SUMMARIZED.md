- **Copilot**: Provided comprehensive architectural assessment:
  
  **Single source of truth**: All four views (Force Graph, Circuit Board, Local Map, Knowledge Sources) consume the same `graphData: ExplorerGraphPayload`.
  
  **Why Related Docs don't belong in `graphData`**:
  - `ExplorerNodePayload` is designed for Live Docs (source-code-backed)
  - Has `codePath`, `publicSymbols`, `dependencies` — none apply to bundled markdown
  
  **Recommendation**: Keep `graphData` pure for Live Docs. Add parallel data structure for related docs:
  ```typescript
  const relatedDocNodes: RelatedDocNode[];
  const relatedDocLinks: RelatedDocLink[];
  // Force Graph merges when checkbox is ON
  ```
  
  **Node ID prefix recommendation**: Use `related:` prefix with transparent handling — helpers like `toRelatedNodeId()`, `fromRelatedNodeId()`, `isRelatedDocId()`.

## Turn 06
- **User**: Reported that Related Documentation nodes are **not visible** in the Force Graph despite checkbox being checked. Attached screenshots.

- **Copilot**: Investigated and found the issue:
  
  **Root cause**: In server mode, `serverBundledDocs.relatedDocLinks` is only populated when `/bundled-docs` is fetched. But that endpoint is only fetched lazily when user opens Knowledge Sources panel — not when toggling the checkbox.
  
  **Fix**: Updated checkbox handler to load bundled docs before rendering:
  ```typescript
  filterToggleRelatedDocs.addEventListener('change', async () => {
    // ... update state ...
    if (newValue && !isStaticMode) {
      await ensureServerBundledDocsLoaded();  // NEW: await before render
    }
    renderGraph();
  });
  ```
  
  Rebuilt and tested — `/bundled-docs` endpoint now called when checkbox is clicked.
