## Turn 03
- **User**: Ran server and reported:
  > "...looks like download is working from the server mode (woohoo!!), and the markdown rendering is _not_ yet working. I only see an empty 'Purpose' section in the Detail Panel for our example file of `column-factory.ts`."

- **Copilot**: Debugged by fetching the `/details` API directly via PowerShell:
  
  ```powershell
  Invoke-RestMethod -Uri "http://localhost:3000/details?docPath=..." | ConvertTo-Json
  ```
  
  **Found the bug**: The `authored` field contained only `"### Purpose"` — the lazy regex quantifier `[\s\S]*?` was stopping at the first opportunity instead of capturing everything up to `## Generated`.
  
  **Root cause**: Regex `/^## Authored\s*\n([\s\S]*?)(?=^## Generated|$)/m` with lazy `*?` captured minimally.
  
  **Fix**: Replaced regex with index-based slicing approach:
  ```typescript
  const authoredStart = raw.indexOf('## Authored');
  const generatedStart = raw.indexOf('## Generated');
  // ... extract via substring between markers
  ```
  
  Build succeeded. Noted server restart required for fix to take effect.

## Key Decisions & Insights

1. **CSS-safe Unicode over emojis**: Used geometric symbols (`◆`, `✓`, `◎`, `○`) for archetype badges to ensure consistent rendering across platforms without emoji quirks.

2. **Index-based string slicing over regex**: After the lazy quantifier bug, switched to explicit `indexOf()` + `substring()` for more predictable section extraction.

3. **Combined markdown export**: For bulk download, opted for a single combined markdown file with `---` separators rather than ZIP archives, avoiding client-side dependency complexity.

4. **Server lifecycle awareness**: User explicitly managed terminal/server lifecycle to avoid Copilot's tendency to inadvertently terminate servers when running commands in the same terminal.
