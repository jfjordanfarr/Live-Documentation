## Discoveries & Decisions

### Oracle Fusion Architecture
The session established that:
- SCIP captures semantic edges (imports, type references)
- Tree-sitter captures syntactic edges (any identifier match in AST)
- Neither produces false positives — they have complementary false negative profiles
- UNION of both tools provides richer oracle for benchmarks

**Architecture Decision:**
- **Benchmark time:** `expected.json = SCIP ∪ tree-sitter` (fused oracle, dev-time only)
- **Runtime:** `heuristics ∪ tree-sitter` (what we ship to users)

### "Public Symbol" Semantics
User asked: "What does 'Public Symbol' mean for Go (package-scoped) or Ruby (everything public)?"

**Answer:** Our model is correct — "Public Symbol" = "symbol that crosses file boundaries" regardless of language visibility rules. A Go unexported function used within the same package still creates a cross-file dependency edge. The term "public" in our context means "not private to this file," not "exported from the package."

### Sync/Async Interface Challenge
The `FallbackHeuristic` interface is synchronous (`initialize()` and `evaluate()` are both sync), but tree-sitter requires async WASM loading. Three options identified:
- **Option A:** Make heuristic interface async (breaking change)
- **Option B:** Pre-load tree-sitter before heuristic creation (async wrapper)
- **Option C:** Use tree-sitter only for benchmark oracle generation, not runtime

Session ended with Option C implemented (oracle fusion for benchmarks), with runtime integration deferred.

## Lessons Learned

### localeCompare is Locale-Dependent
The `localeCompare()` function orders characters differently across locales. In some locales, underscore (`_`) sorts before period (`.`), causing `processor_test.go` to appear before `processor.go`. Use explicit ASCII comparison (`<` operator) for deterministic cross-locale ordering.

### Tree-sitter WASM Eliminates Native Binding Fear
The better-sqlite3 trauma (11/15 work loss incident) created institutional hesitation around native bindings. `@vscode/tree-sitter-wasm` sidesteps this entirely — pure WASM, no native compilation, works identically across all platforms.

### UMD Export Workaround
The `@vscode/tree-sitter-wasm` package has a UMD export bug where the factory function returns an object instead of mutating the `exports` parameter. Requires VM-based patching in CommonJS environments.
