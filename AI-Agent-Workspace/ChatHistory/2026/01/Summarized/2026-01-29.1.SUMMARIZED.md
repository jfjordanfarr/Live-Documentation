## Key Accomplishments

### 1. Go Heuristic Precision: 76.8% → 90.9%

Added `stripCommentsAndStrings()` to prevent false positives from license header comments, plus a `GO_COMMON_VARIABLE_NAMES` blocklist with 30+ common identifiers (`err`, `match`, `value`, `result`, etc.).

**Result:** go-mux false positives dropped from 13 → 4 edges, achieving 90.9% precision (above 70% threshold).

### 2. LanguageSyntax Interface Created

Created `packages/shared/src/languages/` module with async-first design supporting 9 languages:
- Go, C, C#, TypeScript, Python, Rust, Ruby, Java, PowerShell

Each implementation provides:
- `stripCommentsAndStrings(content: string): Promise<string>`
- `frameworkTypes: ReadonlySet<string>` (conservative built-in types)
- `isFrameworkType(identifier: string): boolean`

Registry lookup by ID, extension, or file path enables unified access.

### 3. Tree-Sitter Zero-FP Verification

Created a rigorous audit script comparing SCIP vs tree-sitter edges across all benchmark fixtures. **Key finding:** Tree-sitter has ZERO false positives — all 31 tree-sitter-only edges verified as TRUE POSITIVES.

This discovery led to the critical insight that aggressive filtering was counterproductive.

### 4. LanguageSyntax Simplification

Renamed `ignoredIdentifiers` → `frameworkTypes` across all 9 language files. The lists were reduced to only true framework/built-in types (React, Express, Angular, String, Task, etc.) rather than aggressive blocklists that were causing false negatives.

## Architecture Insights

### Adapter vs Heuristic vs Oracle Roles

Chat Archaeology clarified the distinct purposes:
- **Adapters** = Production runtime (Live Docs generation)
- **Heuristics** = Benchmark inference (FallbackHeuristic)
- **Oracles** = Ground truth generation (SCIP/tree-sitter)

### Oracle Fusion Architecture

The intended data flow is:
- `expected.json = SCIP ∪ tree-sitter` (ground truth, no filtering)
- `inferred.json = heuristics ∪ tree-sitter` (runtime)

### Why Conservative `frameworkTypes`

The user challenged aggressive filtering: "if tree-sitter only produces false negatives, why filter?" With verified zero FPs, the blocklists should only remove true framework noise (React, Express, String, Task) rather than potential cross-file references.

---

## Key Decisions

1. **Keep heuristic blocklists separate from LanguageSyntax** — Heuristics need conservative, purpose-specific blocklists that differ from AST noise reduction
2. **Rename ignoredIdentifiers → frameworkTypes** — Semantic clarity that these are framework/built-in types, not general "ignore" patterns
3. **Skip aggregate thresholds for custom-threshold fixtures** — Aggregate becomes meaningless when some fixtures have acknowledged limitations
4. **Bootstrap packages/testing** — Separate test-time infrastructure from runtime shared package

## Lessons Learned

1. **Tree-sitter verified zero FP** — No filtering needed for tree-sitter outputs
2. **LanguageSyntax blocklists serve AST, not heuristics** — Different purposes need different blocklists
3. **SCIP subdirectory indexes require path prefix** — When indexer runs in subdirectory, paths need prefix adjustment
4. **Aggregate thresholds inappropriate for mixed fixtures** — Skip aggregate when some fixtures have custom thresholds
