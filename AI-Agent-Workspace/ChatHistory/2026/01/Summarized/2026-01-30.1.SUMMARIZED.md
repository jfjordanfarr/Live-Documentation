## Turn 08 (Fork-in-the-Road: stripComments)
- **Copilot**: Identified architectural decision point:
  - Current: `stripCommentsAndStrings()` strips both comments AND string literals
  - Proposed: `stripComments()` strips comments only
  
  **The critical insight**: String stripping causes false negatives because interpolated strings (C# `$"..."`, Python `f"..."`, JS `` `...` ``) contain executable code inside `{...}`.
  
  **Options presented:**
  1. Accept behavioral change (strip both)
  2. Create `stripCommentsOnly()` variants
  3. Keep local implementations

- **User**: Asked for Chat Archaeology to find previous incidents of this issue.

- **Copilot**: Found key evidence from 1/29 chat (line 2183):
  > "109 FN attributed to string stripping"
  
  Discovered the root cause: Interpolated strings like `$"Total: {Helpers.Helpers.Format(report.Total)}"` get their code references destroyed when replaced with `""`.

## Turn 19 (Import-Aware Tree-sitter)
- **Copilot**: Rewrote tree-sitter heuristic to be **import-aware**:
  - Extracts import statements from source files
  - Resolves imports to target files using language-specific patterns
  - Only emits edges for resolved imports (not symbol matching)
  
  Added specialized resolution for:
  - TypeScript/JavaScript: Relative imports, module resolution
  - Rust: `crate::`, `self::`, `super::` prefixes, mod.rs resolution
  - Go: Package paths
  - Python: Relative imports, `from . import`
  - Java: Package imports
  - C#: Using directives
