## Turn 07
- **User**: CI failed — flaky timeout on `acknowledgeDiagnostics.test.ts`. Requested **Chat Archaeology** to find prior occurrences.

- **Copilot**: Searched chat history for "flaky test", "acknowledgeDiagnostics", "waitFor.*timeout". Found key reference in **2025-12-13.1.md** (lines 1830-1930) — same symptom:
  > "The pattern is stark: **US3 runs with `(no feeds)`** while US2+ runs with `(feeds: configured=2, healthy=2)`."

  **Root cause identified**: The `acknowledgeDiagnostics` test is the **only test** that sets a custom `storagePath`:
  ```typescript
  await config.update("storagePath", storageDir, vscode.ConfigurationTarget.Workspace);
  ```

  This triggers `onDidChangeConfiguration` → `syncRuntimeSettings()` → `void knowledgeFeedController.initialize()`.

  **The `void` prefix fires-and-forgets!** So:
  1. Config change fires
  2. `syncRuntimeSettings()` starts `initialize()` but doesn't await it
  3. `initialize()` **immediately disposes existing feeds** (sets `configuredFeedsCount = 0`)
  4. Test calls `waitForLanguageServerReady()` → queries feeds → gets 0
  5. Test proceeds with no graph → no diagnostics published → timeout

- **User**: Asked what copilot instructions would recommend.

- **Copilot**: Per instructions ("Do it the Right Way", "Complete Problem Solving"):
  > **Option B (server-side fix)** is the clear choice. The `void` prefix on `initialize()` is the actual bug.

  **Fix applied to main.ts**:
  ```typescript
  // BEFORE
  function syncRuntimeSettings(): void {
    // ...
    void knowledgeFeedController.initialize({...});
  }

  // AFTER
  async function syncRuntimeSettings(): Promise<void> {
    // ...
    await knowledgeFeedController.initialize({...});
  }
  ```

  Also reduced test timeouts from 90s→45s, 30s→15s since root cause was fixed. Test now completes in **2.5 seconds** instead of timing out.
