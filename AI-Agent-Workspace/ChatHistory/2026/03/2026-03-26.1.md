I've identified **three compounding bugs** that make all animations invisible:

### Bug 1: Container transform invalidates FLIP math

## The Design Principles

1. **Membrane = directory**: always. If `treeSitter/` has children in 3 columns, the membrane spans all 3. No fragmentation.

2. **LCA is the outer shell**: the outermost visible membrane is the Lowest Common Ancestor of all visible nodes. Parents above the LCA appear as the breadcrumb/header but don't need spatial membranes (they'd be full-width and add visual noise without information).

3. **Hop distance → x-position, not rigid columns**: files are still positioned left-to-right by hop distance, but without hard column boundaries. This lets a membrane like `treeSitter/` be a natural horizontal band containing files at various x-offsets.

4. **Siblings stack vertically**: `treeSitter/` and `heuristics/` stack as horizontal bands within `inference/`. `fallbackHeuristicTypes.ts` (a loose file in `inference/`) sits between or beside the sibling membranes.

5. **Column headers dissolve**: instead of "PINNED | DEPENDENTS | 2-HOP", the **membrane labels** become the primary wayfinding. Hop distance is encoded spatially (left = closer to origin) and can optionally appear as subtle column guides or hop badges on individual cards.

## The Hard Part

The layout algorithm needs to solve a 2D bin-packing/constraint problem:

- **X-axis**: dependency hop distance (minimize backward/cross-column connections)
- **Y-axis**: directory grouping (siblings of the same directory are vertically adjacent)
- **Membrane sizing**: width = span of min-hop to max-hop of children; height = sum of child card heights

This is essentially a **layered graph drawing** (Sugiyama-style) where the layers are hop distances, but with the added constraint that nodes sharing a directory must be enclosed in a common rectangular region. The constraint is similar to "cluster" constraints in Graphviz's `dot` layout.

A practical incremental approach:

1. Compute hop columns as today (assign each file an x-layer)
2. Find the LCA of all visible nodes
3. Group files by their immediate directory
4. For each directory, compute its column span (min-hop to max-hop of its children)
5. Position directory groups as horizontal bands, sorted by their leftmost column
6. Within each band, position files in their hop column
7. Outer membranes (LCA ancestors) wrap the bands

This avoids a full constraint solver while still getting the cross-column membrane spanning correct. Thoughts?

## Resolution Strategies

### Strategy A: Allow Membrane Gaps (non-contiguous)

```
  Hop 0    Hop 1         Hop 2       Hop 3
           ┌─ dirB/ ─┐               ┌─ dirB/ ─┐
           │ b1.ts   │               │ b3.ts   │
           │ b2.ts   │               │         │
           └─────────┘               └─────────┘
                        ┌─ dirC/ ─┐
                        │ c1.ts   │
                        └─────────┘
```

Pro: Honest — membranes don't lie about containment.
Con: The same directory name appears twice. "Which dirB is which?" We already rejected this for your screenshot (treeSitter appearing 2x).

### Strategy B: Push Outliers to Avoid False Containment

When a non-member node (c1.ts) sits in a column spanned by a membrane it doesn't belong to, displace it vertically outside the membrane's band:

```
  Hop 0    Hop 1         Hop 2       Hop 3
           ┌─ dirB/ ──────────────────────────┐
           │ b1.ts                     b3.ts  │
           │ b2.ts                            │
           └──────────────────────────────────┘
                        ┌─ dirC/ ─┐
                        │ c1.ts   │
                        └─────────┘
```

Pro: Each membrane is one contiguous rect. No containment lies.
Con: Connection from b1→c1 and b2→c1 must cross _out_ of dirB's band and back. Still correct — the line visually exits the membrane, which is what happens in real architecture.

**This is the strategy I think works best.** It's what my first diagram proposed: membranes are horizontal bands that never overlap, stacked top-to-bottom by their primary hop column. Files not in the band's directory sit outside it.

### Strategy C: Nested Membranes at the LCA Level

Rather than per-column membranes, use the LCA membrane to honestly enclose everything, and only draw child-directory membranes when their children don't interleave:

```
  ┌─ inference/ ─────────────────────────────────────────┐
  │  ┌─ treeSitter/ band ──────────────────────┐         │
  │  │ loader.ts    extractors.ts   index.ts   │         │
  │  │              languages.ts               │         │
  │  └─────────────────────────────────────────┘         │
  │                                              ┌─ heur │
  │                 fallbackHeur...               │idx.ts│
  │                                              └──────│
  └──────────────────────────────────────────────────────┘
```

When interleaving makes a child membrane impossible to draw as a clean rect (Case 4), **promote the conflicting files up to the parent membrane level** — they lose their child-membrane border but keep their parent membrane. The LCA membrane is always truthful.

### My Recommendation: Strategy B + C Hybrid

1. Lay out files by hop distance (x-axis) — unchanged from today
2. Compute the LCA of all visible nodes — draw it as the outermost membrane
3. For each child directory, check if its hop range **exclusively contains** its own files at each hop column (no interleaving). If yes → draw a contiguous rectangular band
4. If interleaving occurs → the directory membrane still draws as a band, but **non-member files at conflicting hops are displaced vertically outside the band** (Strategy B)
5. Back-trace stubs handle backward edges, exactly as today

The column headers ("PINNED", "DEPENDENTS", "2-HOP") can remain as subtle visual guides for hop distance, or fade out as you suggested — but the **membrane labels** become the primary orientation. The user reads "treeSitter/" and knows every card inside that border shares a directory.

## On the Escher Inevitability

You're right that it can still happen. Any dependency graph with enough fan-out will produce layouts where some connections run backward or cross many columns. The key insight: **we don't need to eliminate backward edges, we need to price them correctly.** The BFS hop assignment already minimizes the total backward edges (it assigns each node to its minimum distance from any pinned node). This is exactly "Strategy B with row partitioning" — and it falls out naturally from the band-stacking algorithm, because directories with no shared edges to other bands naturally separate.
