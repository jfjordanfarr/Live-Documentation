## Turn 8 — Namespace-mode toggle for C#

**User** (L786–L982): Acknowledges C# nested classes were already a known gap. Reveals personal stakes: _"all of the places I currently intend to actually **run** this software and apply its outputs for genuine real-world benefit are.... That is an impressive analysis."_ Proposes the key question: _"whether or not we stand to **benefit** from providing some alternative namespace-based... organization strategy to optionally toggle for C#. **Copilot** (L792–L982): Performs deep C# adapter analysis (reads `csharp.ts` — 387 lines). Identifies three C# challenges:

1. **Nested classes**: `OuterClass.InnerClass` not currently tracked as distinct symbols — needs brace-depth tracking
2. **Hierarchical pins**: Nested types produce multi-level pins (not flat), requiring nested containment within card rendering
3. **Namespace ≠ directory**: Most impactful for the membrane model

Proposes namespace-mode as a simple hierarchy-function swap:

```
pathToHierarchy("src/Helpers/ServiceHelper.cs") → ["src", "Helpers", "ServiceHelper.cs"]
namespaceToHierarchy("App.Services") → ["App", "Services"]
```

The membrane layout engine doesn't care which hierarchy function is used — it's the only moving part. Both modes use the same layout algorithm, the same edge bundling, the same pin rendering. A toggle in the UI switches between directory view and namespace view. Data for namespace mode already exists: the adapter extracts the namespace declaration from every C# file.

| Rung | Test First                                                                       | Then Implement                                                  |

| 5    | Browse-mode DOM snapshot tests                                                   | Browse renderer                                                 |
| 6    | Explore-mode DOM snapshot tests (focal expansion, pin wiring, membrane-piercing) | Explore renderer                                                |
| 7    | Compare-mode tests (two focal nodes, LCA membrane)                               | Compare renderer                                                |
| 8    | Path-mode tests (sequential hop, numbered badges, path breadcrumb)               | Path renderer                                                   |

Key insight: _"The phase-based plan is organized by feature; the zipper pattern organizes by **confidence**. The naming question (Browse/Explore/Compare/Path) can marinate through Rungs 1–4 since those don't touch user-facing labels.
