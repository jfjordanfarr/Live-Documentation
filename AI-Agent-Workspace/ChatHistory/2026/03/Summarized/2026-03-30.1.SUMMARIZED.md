## Turn 5 — User pressure-tests bundle-edge design assumptions (L843–L989)

**User** (L843): Challenges the browse-mode bundle-edge idea directly. Raises the problem of edges spanning to directories that are neither sisters nor children of the current directory, asks how progressive membrane wrapping could help, and presses on interaction design questions: hover vs. click, redraw/disorientation costs, drill-in behavior, and parity across desktop and mobile.

**Copilot** (L845–L989, spanning compaction at L857): Re-reads `browse-renderer.ts`, `index.ts`, and `focal-overlay.ts`, then reasons from the actual implementation.

The analysis reaches several important conclusions:

- The treemap is a space-filling spatial layout; drawing cross-directory bundle edges in browse mode produces visually orphaned lines that point to off-screen or non-materialized remote directories
- The right question is not whether treemap geometry can show remote topology cleanly; it is **what interaction should transition the user from spatial browsing into relational exploration**
- Badges already function as a low-information relational hint (`15 out`, `8 in`) without layout disruption

Copilot proposes a **badge-popover** model:

- click the tile body → drill in normally
- click a connectivity badge → open a compact popover listing the top dependency target directories
- from the popover, click a target to navigate there or click a control that enters a stronger relational mode

The core rationale is minimal surprise:

- no treemap reflow on hover
- no hidden hover-only interaction required for mobile
- progressive disclosure from spatial tile → relational hint → full relation view

Copilot explicitly argues **against** always-on bundle edges in browse mode and against hover-driven membrane growth, framing both as disorienting and incompatible with the treemap's geometry contract.

## Turn 10 — URL-state refresh bug traced to two competing URL systems (L2429–L2697)

**User** (L2429): Reports the next problem after manually testing in the Playwright browser: Membrane Map state visible in one screenshot is lost after refresh in the next. Asks Copilot to investigate what URL-based sharing was intended to do.

**Copilot** (L2431–L2697, spanning compaction at L2522): Searches the workspace for URL-state design and reads the persistence files. The diagnosis is that the Explorer has **two URL-state systems that are not talking to each other**:

1. **Legacy `url-state.ts`** — reads `?view=` and `?node=` via `parseInitialState()`
2. **Compressed `compressed-url-state.ts`** — writes and reads the Membrane Map state via `?s=`

The Membrane Map already persists its rich state to `?s=` (view, selected node, pins, expanded directories, transform, filters), but the outer client shell uses `parseInitialState()` which only recognizes the legacy query parameters. That means a refresh sees no recognized URL state and falls back to localStorage or the default `sources` view.

Copilot fixes the restore path in three places:

- `parseInitialState()` checks `?s=` first and minimally decompresses it to recover the view and selected node
- `url-state.ts` gains explicit `"membrane"` handling in the view-name mapping helpers
- `local-storage.ts` accepts `"membrane"` as a valid persisted view

After rebuilding and regenerating the static Explorer, Playwright verification confirms that a deep Membrane Map URL with `?s=` now correctly restores:

- active Membrane Map view
- focused directory
- expanded directory path
- selected node context

- outer pin-active layout uses fixed `320px` columns
- inner `.pa-band-inner` grids also use fixed `320px` columns
- but those inner grids sit inside membranes with padding and border, so they overflow their containing bands by the padding/border width

The real repair is architectural rather than cosmetic:

- in `pin-active-renderer.ts`, inner band grids switch from fixed `320px` columns to `1fr`
- `membrane.css` keeps a `max-width: 100%` guard on `.pin-active-card` as a defensive constraint

- **Browse-mode navigation improved**: a breadcrumb bar provides direct ancestor navigation in browse mode, and collapsed directories with cross-boundary connectivity now expose `Explore ⇗` to jump into relational inspection.
- **Compressed URL-state restore fixed**: the outer Explorer shell now recognizes `?s=` state, so Membrane Map refresh/share URLs correctly reopen the intended view and location.
- **Playwright E2E infrastructure created**: dedicated config, Chromium-backed test runner, shared helpers, and 16 regression tests covering containment, card interactions, dimming, band rendering, focus layout, font invariance, hybrid mixed-content layout, and URL persistence.
- **Pin-active overflow repaired at the real source**: inner band grids switched from fixed `320px` columns to `1fr`, and `.pin-active-card` received a defensive width guard, eliminating the membrane-overflow failure.
- **Safe-commit extended for browser falsifiability**: `safe-to-commit.mjs` gained `--e2e` / `--no-e2e`, and SlopCop asset scanning was taught to ignore generated Playwright reports.
- **Authored Live Docs added for the new E2E surface**: all 10 E2E files gained Purpose/Notes with provenance, so the new browser-test layer is fully represented in the documentation graph.
