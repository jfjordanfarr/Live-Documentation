## Research Summary: `safe.directory` in Devcontainers

### Key Findings

1. **This is a known, recognized issue** — Microsoft's VS Code team acknowledged it in issue #7628 as a **bug** caused by git's CVE-2022-24765 security fix (git >= 2.35.2).

2. **The Dev Containers extension now automatically handles this** for the main workspace folder — chrmarti's fix (Jan 2023) adds the repository root as a `safe.directory` automatically when:
   - Container user ≠ owner of repository root folder in container
   - Local user = owner of repository root folder on host
   - This is single-container cases only (Docker Compose needs separate handling)

3. **Recommended workaround pattern** (used widely before the fix was merged):

   ```json
   "postStartCommand": "git config --global --add safe.directory ${containerWorkspaceFolder}"
   ```

4. **The security consideration**: chrmarti initially questioned whether auto-adding would "reintroduce the vulnerability" but joaomoreno's response captured the key insight:
   > "There's an argument somewhere around this suggestion being specific to dev containers and **their inherent strange permission conventions**."

### The Verdict

The VS Code team's fix essentially validates our `safe.directory '*'` approach:

- **Devcontainers break the ownership model by design** — files mounted from Windows hosts have different owners than the container user
- **The vulnerability protection is semantically meaningless** in this context because there's no "untrusted other user" who could have planted malicious hooks
