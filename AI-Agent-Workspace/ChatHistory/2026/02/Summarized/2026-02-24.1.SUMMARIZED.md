## Turn 23 — User asks about pathfinding path selection

**User**: _"When there are multiple paths matching {shortestPathLength} number of hops, which is chosen to be rendered, and why are we not rendering the others? Are there any {shortestPathLength+1} or {+2} paths that we think should be drawn?"_

**Copilot**: Traces through both BFS implementations:

- **CLI** (`pathfind.ts`): Standard BFS with `Map<string, string>` parents — first-visit-wins. Path selection determined by JavaScript `Set` insertion order (depends on Live Doc parse order — essentially arbitrary).
- **Explorer** (`pathfind.ts` client): Same algorithm — BFS with single-parent map, first-visit-wins.

Identifies what's lost: diamond dependencies, parallel chains through different intermediaries, and (most critically) symbol-divergent paths through the same file. Proposes three enhancements:

1. **All-shortest-paths**: Modified BFS recording `Set<string>` of parents per node, backtracking to enumerate all paths of equal length
2. **Near-miss (+1)**: After finding all shortest paths of length $k$, enumerate paths of length $k+1$ to reveal skipped intermediaries
3. **Symbol-divergent paths**: Port `searchSymbolPath` from CLI to client to show different data flows through the same file

## Technical Outcomes

**Product Identity Resolution**: The session crystallized the product identity as **"Codebase Cartography"** — Live Documentation is a polyglot codebase mapping tool. The map (dependency graph + topology) is the primary value; authored annotations are first-class enrichment but not the raison d'être. The mission statement ("What other files will be impacted by this change?") aligns with this framing.

**Three-View Architecture**: Map View (hierarchical drill-down replacing Circuit Board), Force Graph (emergent topology, preserved and elevated), and Local Map (file-level focus + impact tracing). The universal card component serves all three views.

**Multi-Path Visualization Design**: Three planned enhancements to pathfinding rendering:

1. All-shortest-paths as merged DAG (divergent nodes stacked within hop columns)
2. Near-miss +1 paths rendered with dashed/dimmed styling
3. Symbol-divergent paths through same file showing distinct data flow chains

**Server Retirement Case**: Comprehensive analysis showing the HTTP server provides no capability the static build lacks. The `/open` endpoint is broken (wrong API, fails in containers), refresh latency is marginal (12s vs 3s), and the clean architecture is CLI outputs → static site inputs.

**CLI Consolidation Proposal**: Kill server mode, rename `visualize:static` → `visualize`, make lint emit structured JSON, add `--precompute` to generate. Three-layer pipeline: Source (committed markdown) → Cache (gitignored JSON) → Distribution (build artifact HTML).

**User-Use-Case Census**: 93 entries extracted from 2,588 user prompts across 102 chat files, covering the full project history from Oct 2025 through Feb 2026. Includes three external use cases (PCI-DSS payment portal, Brain Simulator III, Unity game) that collectively demand the "run it cold on someone else's codebase" capability.
