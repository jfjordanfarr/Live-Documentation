## Turn 06 (The Taxonomy Mismatch Discovery)

- **Copilot**: Found the root cause:

  > "The `mapRelation` function at line 449-460 **transforms ALL relations to "references"** (except "implements")... c-libuv oracle has `relations: ["includes"]`, but ALL edges now have `relation: "references"`. Therefore ALL edges get filtered out → 0 edges in inferred.json."

  **Root cause chain:**
  1. Inference produces edges with `kind: "includes"`
  2. `buildEdgeRecords` calls `mapRelation()` which transforms `"includes"` → `"references"`
  3. `filterEdgesByOracleRelations` filters edges where `relation` is in `oracle.relations`
  4. c-libuv has `oracle.relations: ["includes"]`, but edges have `relation: "references"`
  5. All 1095 edges filtered out → 0% recall

## Turn 11 (Race Condition Fix)

- **Copilot**: Diagnosed the race condition:
  1. Multiple Vitest worker processes call `loadTreeSitter()` concurrently
  2. Each has its own `patchedLoaderPath = null` (module state not shared across workers)
  3. All workers race to create the patched file
  4. File writes overlap, causing corrupted module loads

  **Fix implemented:**
  1. Promise-based mutex (`initializationPromise`) to prevent concurrent initialization within a process
  2. Atomic file write pattern (write to temp file, then rename) to prevent cross-process race conditions
  3. Module validation to fail fast with clear error if load fails
