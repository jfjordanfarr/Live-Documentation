## Inspect CLI Symbol Pathfinding Assessment

### Current Architecture

The inspect CLI operates at the **file-artifact level** only:

| Component | Current State |
|-----------|---------------|
| **Graph nodes** | Keyed by `codePath` (file path) |
| **Graph edges** | `dependencies: Set<string>` — file-to-file only |
| **rawDependencies** | Contains `anchor` and `sourceAnchor` fields — **symbol info exists but unused** |
| **resolveArtifactIdentifier()** | Only handles file paths, no symbol syntax parsing |
| **searchGraph()** | BFS on file nodes only |

### Key Discovery: Symbol Data Already Exists in Edges

Looking at `ParsedDependency`:
```typescript
interface ParsedDependency {
  codePath?: string;
  docPath?: string;
  anchor?: string;           // Target symbol on destination file
  sourceAnchor?: string;     // Symbol on source file that declares this dependency
  label?: string;
  raw: string;
}
```

And in liveDocGraph.ts, type references inject symbol data:
```typescript
typeRefDependencies.push({
  codePath: targetCodePath,
  sourceAnchor: symbolName,  // e.g., "MyClass"
  anchor: typeRef.targetAnchor,  // e.g., "BaseClass"
  label: `${typeRef.role}: ${typeRef.typeName}`,
  ...
});
```

#### 2. **Symbol → Symbol** (Most Important)

**Complexity: Medium** — Graph structure already supports this, needs:

1. **New input syntax**: Parse `path/to/file.ts#SymbolName` or `path/to/file.ts:SymbolName`

2. **New resolution function**: `resolveSymbolIdentifier(input: string)` returning:
   ```typescript
   { codePath: string; symbolName: string | undefined }
   ```

3. **New graph query**: Filter `rawDependencies` to find edges where:
   - `sourceAnchor === fromSymbol` AND `anchor === toSymbol`
   - Or chain file-level hops but only traverse edges matching symbol anchors

4. **New BFS variant**: Symbol-aware search that:
   - Starts from a symbol (file + symbolName)
   - Only traverses edges where `sourceAnchor` matches the current symbol
   - Terminates when `anchor` matches the target symbol

**Key insight**: This is tractable because `rawDependencies` already carries `sourceAnchor` and `anchor`. The BFS just needs to filter neighbors by symbol match.

**Complexity: Low-Medium**

Same as Symbol→Symbol, but:
- Start at file level (any symbol on that file can be a starting point)
- Target is a specific symbol
- Search terminates when reaching the target file AND the edge's `anchor` matches

#### 4. **Symbol → Artifact**

**Complexity: Low-Medium**

- Start from specific symbol (filter outbound edges by `sourceAnchor`)
- Target is any arrival at the destination file (any anchor)
