### The Core Problem

The Local Map was built from the ground up for **exactly 3 columns**. This isn't a superficial limitation — it's embedded in:

| Layer | Hardcoding |
|-------|------------|
| **CSS** | `grid-template-columns: repeat(3, max-content)` |
| **Types** | Single `LocalSubgraph` with one `center` node |
| **Anchor Registry** | Keys are `columnRole:nodeId` — no hop index |
| **Connection Drawing** | Only iterates one `currentSubgraph.links` |
| **Pinning State** | Single `pinnedSymbol: string \| null` |
| **Render Function** | Creates exactly 3 columns, always |

The 12/17.3 attempt failed because it tried to **bolt multi-hop onto** this architecture. The correct approach requires **rebuilding from the type system up**.

---

### Directional Pathfinding

Your observation about bidirectional BFS is spot-on. The screenshot shows a path that implies dependency direction opposite to what's actually rendered. The fix:

1. **Forward BFS**: Follow outbound edges only (FROM's dependencies)
2. **Reverse BFS**: Follow inbound edges only (TO's dependents, traversed backwards)
3. **Return both paths**: Let the user see the directionality clearly

This way, if you ask "how does `A` reach `B`?":
- Forward: Shows `A → X → Y → B` if A depends on something that depends on something that B also depends on
- Reverse: Shows `A ← X ← Y ← B` if B depends on something that depends on something that A also depends on

## The "Independently Improvable" Lens

The key question: **Can I improve Module A without touching Module B?**

For that to be true, modules need:
- **Stable interfaces** — Contracts that don't change when internals change
- **Unidirectional dependencies** — A depends on B, but B doesn't know A exists
- **Testability in isolation** — Can run tests without spinning up the whole system
- **Substitutability** — Could swap implementations behind the interface
