## Development Trajectory: A Verbal Summary

### The Arc in Three Acts

**Act I: Foundations (October – Early November)**
The project began as "Link-Aware Diagnostics" — an LSP-powered VS Code extension backed by SQLite to detect broken markdown links and missing documentation references. Early work established benchmark discipline through polyglot fixture suites (TypeScript, Python, C, Rust, Java, Ruby, C#). The key architectural insight was treating markdown as a lightweight AST: headers become anchors, relative links become dependency edges, and the whole corpus forms a navigable graph.

**Act II: The Live Documentation Pivot (Mid-November)**
Around November 8-9, the project underwent a significant pivot. Instead of purely detecting broken links, the extension would now **generate** documentation — "Live Docs" that mirror every tracked workspace artifact with deterministic markdown. Each Live Doc contains:
- **Authored sections** (Purpose, Notes) — human-written context
- **Generated sections** (Public Symbols, Dependencies, Observed Evidence) — machine-extracted from source code

This pivot transformed the mission: the extension now provides the definitive answer to "What other files will be impacted by this change?" by grounding analysis in versionable markdown that can be regenerated locally, published to wikis, and consumed by CLI, UI, and LLM surfaces alike.

**Act III: Visualization Epoch (Late November – December)**
With Live Docs as the canonical data layer, focus shifted to visualization. The Explorer evolved through three major views:
1. **Circuit Board** — Treemap-style overview showing all files grouped by directory clusters
2. **Local Map** — Symbol-level 3-column view (Dependencies, Center Node, Dependents) with bezier connectors
3. **Force Graph** — (Rough) 3D force-directed graph

December saw intensive refinement: type reference extraction, barrel file resolution, omnisearch, hover highlighting, the "French Corset" self-loop visualization, and ultimately the **Static Explorer** (enabling GitHub Pages deployment).
