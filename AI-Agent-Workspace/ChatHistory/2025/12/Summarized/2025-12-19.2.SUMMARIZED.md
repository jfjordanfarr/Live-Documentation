## Design Insights

### Pure Function Extraction Pattern
The key to successful controller.ts refactoring was the **pure function extraction with runtime passed in** pattern:
- Extract logic into pure functions that receive runtime, options, state as parameters
- Controller becomes a thin coordinator that calls these pure functions
- Each extracted module can be unit tested without DOM mocking
- This follows the precedent established by 12/18 extractions (`state.ts`, `layout-math.ts`, `connection-geometry.ts`)

### Folder-Based Organization
Rather than flat module extraction, the revised architecture uses domain-based folders:
- `bootstrap/` — Application initialization
- `persistence/` — State persistence (URL, localStorage)
- `panels/` — UI panel initialization
- `inspect/` — CLI pathfinding and output

### Naming Conventions That Inform
Specific naming patterns make module purposes immediately clear:
- `pathfind-*.ts` — Graph traversal variants
- `emit-result-*.ts` — Output formatting variants
- `*-factory.ts` — DOM element creation
- `*-builder.ts` — Data structure construction

### Tests That Verify Behavior, Not Coverage
The 72 new unit tests verify:
- Mathematical invariants (e.g., "point under cursor stays fixed" for zoom)
- Graph semantics (e.g., inbound/outbound classification correctness)
- Edge cases (e.g., empty graphs, bidirectional edges, case normalization)
