## Turn 12: UTF-8 Binary Detection Bug Discovery
- **Issue**: Graph audit failed — new modules weren't appearing in the graph snapshot.
- **Copilot**: Created debug script to trace the issue.
- **Root Cause**: `isLikelyBinaryFile()` in workspaceIndexProvider.ts only accepted ASCII printable characters (bytes 0-127). The new modules contained **box drawing characters** (`─`, U+2500) in comment separators, which are valid UTF-8 but have bytes in the 0x80-0xF4 range.
    ```
    [DEBUG] constants.ts flagged as binary: ratio 0.6170212765957447
    [DEBUG] Non-printable bytes: 0xe2 0x94 0x80 (UTF-8 for '─')
    ```
- **Fix**: Updated `isLikelyBinaryFile()` to allow UTF-8 multi-byte sequence bytes (0x80-0xF4):
    ```typescript
    // Before: b <= 0x7e
    // After: b <= 0x7e || (b >= 0x80 && b <= 0xf4)
    ```
- **Result**: Graph snapshot grew from 999 → 1010 artifacts, all new modules properly indexed.

## Key Insights & Design Decisions

1. **Barrel Exports for Library Modules** — Barrel re-export files are the right choice for modules with a defined public API surface. They provide encapsulation, deliberate exports, and backward compatibility.

2. **Capability-Oriented Module Splits** — When refactoring large files, ask "what are the independently evolvable capabilities?" rather than "how do we split this file?" This leads to natural module boundaries that support progressive enhancement.

3. **Each Plan Builder = One Capability** — The five plan builders (Component, Interaction, Workflow, Testing, CoActivation) represent distinct analytical strategies that can be enhanced, replaced, or A/B tested independently.

4. **Rendering is Cohesive** — Section renderers share the same output contract and change together when output format evolves. Splitting them gains nothing.

5. **UTF-8 Awareness in Heuristics** — Binary file detection must account for valid UTF-8 multi-byte sequences to avoid false positives on files with Unicode characters.
