## Turns 09-10: Document Root Detection Implementation
- **Copilot**: Implemented `findDocumentRoot()` algorithm:
    1. Start at source file's directory
    2. Walk up to workspace root
    3. At each ancestor, check if `ancestor/relativePath` exists
    4. First match = effective document root
- **Copilot**: Added test for this scenario.
- **Result**: `site.css` (at `workspace/styles/site.css`) now resolves from `/styles/site.css`.

## Design Decisions

### Document Root Detection Algorithm
When resolving server-root-relative paths like `/images/banner.png`:
1. Walk up from source file directory to workspace root
2. At each ancestor, check if `ancestor/images/banner.png` exists
3. Also check common static directories: `public/`, `wwwroot/`, `static/`, `dist/`, `assets/`, `web/`, `client/`
4. First match = effective document root

### Binary Asset Stub Live Docs
- **Purpose**: Enable graph edges TO binary assets (images, fonts, videos)
- **Content**: Minimal — `Asset` archetype, no public symbols, no dependencies
- **Effect**: "Total panopticon visibility" — deleting `banner.png` now shows `index.html` would be affected

### Chat Archaeology for Authored Content
Three pieces of context required for each Live Doc:
1. **Chat history** — When/why was the source file created?
2. **Source file** — Full contents
3. **Current Live Doc** — Full contents (unabridged)
