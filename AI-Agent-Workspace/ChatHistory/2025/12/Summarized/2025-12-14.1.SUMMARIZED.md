## Design Insights

### CLI-First, Marketplace-Agnostic Architecture
The user's vision reframes Live Documentation as **portable file analysis software** that:
1. Runs anywhere (CI, Docker, local terminal, PCI-DSS secured environments)
2. Analyzes arbitrary codebases (no VS Code required)
3. Outputs versionable markdown + SQLite (git-trackable truth)
4. Happens to have a VS Code extension (convenience, not necessity)

The VS Code extension is a **UX wrapper** around the CLI, not the product itself. This architecture supports:
- Dual marketplace publishing (Microsoft Marketplace + Open VSX for VSCodium/Gitpod)
- NPM package publication (`@live-documentation/cli`)
- Complete independence from any corporate platform

### Security-First npm Readiness
Informed by the 2025 npm supply chain threat landscape (Shai-Hulud worm, s1ngularity Nx attack, etc.), the user prioritizes:
1. **Dependency minimization** over version pinning (reduce attack surface)
2. **Internet-free guarantee** (core operations never access internet)
3. **No lifecycle scripts** (already validated ✅)
4. **Localhost-only LLM access** (opt-in, defaults to none)
5. **Open VSX dual-publishing** (marketplace independence)

### MDMD Convention Separation
MDMD is a useful workspace-specific convention but completely unknown outside this project. The user correctly identifies that:
- MDMD has zero bearing on consumers of Live Documentation
- MDMD filename contamination (mdmdParser.ts) in production code creates confusion
- Live Documentation can power MDMD as a base layer, but MDMD does not dictate Live Documentation's shape
- Others can reconfigure Live Documentation defaults to their heart's content

### Rigorous Auditability Requirements
When authoring Live Docs for renamed files, the user demands:
1. Full unabridged code file reads (no sampling)
2. Full Live Doc reads (spot-check accuracy)
3. Chat Archaeology to determine original creation date and intent
4. Pattern matching against existing Live Docs (workspaceIndexProvider, snapshot-workspace)

This rigor reflects the PCI-DSS secured environment context: **the software must be auditable, traceable, and correct**.
