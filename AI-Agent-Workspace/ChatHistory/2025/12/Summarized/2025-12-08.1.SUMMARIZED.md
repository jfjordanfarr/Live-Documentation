## Turn 12: Internals Pseudo-Symbol Highlighting Bug
- **User**: "Can you help ensure that symbol-level highlighting occurs even when the symbol is a pseudo-symbol (the 'Internals' pseudo-symbol row)? We get highlighting _from_ a real symbol _to_ an internals pseudo-symbol, but we don't get the reverse."
- **Copilot**: Deep-dived into `controller.ts` `highlightSymbolConnections` logic.
- **Copilot**: Discovered edge direction semantics:
    - Outbound (dependencies): `sourceId = center`, `targetId = neighbor`
    - Inbound (dependents): `sourceId = neighbor`, `targetId = center`

### Root Cause 1: Edge Direction Filter Incomplete
- **Issue**: For center Internals hover, code only checked `edge.targetId === centerId` (inbound edges).
- **Fix**: Added check for outbound edges where `edge.sourceId === centerId && isInternalsEdge(edge.sourceSymbol)`.

### Root Cause 2: Symbol Normalization Mismatch
- **Issue**: `normalizeEdgeSymbol` (simple lowercase + strip "symbol-" prefix) vs `normalizeSymbolIdentifier` (complex normalization with namespace stripping, etc.) produced different outputs.
- **Fix**: Unified to use `normalizeSymbolIdentifier` for both edge symbols and row symbols.
