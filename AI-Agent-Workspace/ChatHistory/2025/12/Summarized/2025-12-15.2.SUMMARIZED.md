## Design Insights

### Multi-Layer Network Security Evidence
The security implementation provides **defense in depth**:
1. **Static audit**: Proves code doesn't contain unaccounted network calls (but doesn't prove runtime behavior)
2. **safeFetch wrapper**: Enforces localhost-only at the API level (but doesn't cover dependencies' internal calls)
3. **CI audit**: New code is checked on every commit (audit could have false negatives)

For true air-gapped/PCI-DSS environments, `docker --network none` provides the definitive proof, but GitHub Actions constraints mean this must be run manually.

### CLI Package Architecture Decision
The decision to create a single `@live-documentation/cli` package (vs. scoped monorepo) reflects:
- Tight coupling between CLI/server/shared in practice
- Single contributor = zero coordination overhead
- Can always split later if use cases diverge
- Simpler onboarding for reviewers

### Branding vs. Descriptive Naming
Key insight from user: "Link-Aware Diagnostics" is branding (should become "Live Documentation"), but `linkDiagnostics` as a code identifier is descriptive and can stay. This surgical distinction avoids unnecessary churn while ensuring user-facing consistency.
