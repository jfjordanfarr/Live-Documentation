## Design Insights

### NotebookLM Critique Analysis
The AI-generated critique identified real tensions (heuristics maintenance, SCIP/LSIF integration, headless showcase priority) but proposed solutions that ignored already-executed pivots:
- **SCIP/LSIF integration**: Already implemented via Polyglot Fixture Oracles (different architecture than external SCIP consumption)
- **LLM value proposition**: Already deprioritized ("map + freshness engine" is the core, not docs→code write-back)
- **"Gamma Internals" as debt indicator**: Made-up label (code uses "⬛ Internals"), and the feature conflates tracing with debt scoring

Key insight: long-context models can identify architectural tensions accurately but often propose solutions that ignore prior pivots. Chat archaeology provides the definitive disambiguation.

### Knowledge Sources as Onboarding
Making Knowledge Sources the cold-start default solves the "what is this?" problem before users navigate to Local Map or Circuit Board. The view provides:
- Epistemic grounding: "where does this data come from?"
- Health warnings: "what should I be cautious about?" (barrel files, hub modules)
- Improvement guidance: "how can I make this better?"

This isolates uncertainty to one view, allowing other views to be trusted without constant second-guessing.

### Barrel File Visualization Challenge
The screenshot of `packages/shared/src/index.ts` (576 nodes, 2244 links, 782 missing deps) demonstrates the visual explosion that barrel files cause. This validates:
- Per-edge provenance badges would add noise, not clarity
- "Internals" pseudo-symbol needs higher confidence before instrumenting as debt sensor
- Knowledge Sources view is the right place for graph health warnings
