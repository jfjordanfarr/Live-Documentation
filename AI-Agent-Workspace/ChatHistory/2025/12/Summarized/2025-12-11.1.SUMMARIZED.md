## Turns 07-08: JSDoc Tag Extraction Bug Fix
- **Root Cause**: `parseSymbolSection()` in parse.ts was matching ANY bullet with backticks (e.g., `- \`@param\`` in Remarks sections), not just H4 symbol headings.
- **Fix**: Restricted symbol extraction to H4 headings only: `/^####\s+\`([^\`]+)\``
- **Result**: Symbol precision 92.19% → 99.85%

## Turns 09-10: Disambiguation Suffix Bug Fix
- **Root Cause**: Live Docs append type suffixes like `LayoutConstants (interface)` to disambiguate same-named exports, but the analyzer returns bare names.
- **Fix**: Added stripping regex: `/\s+\((interface|const|type|class|function|enum)\)$/i`
- **Result**: Symbol precision 99.85% → **100.00%**

## Turns 17-20: Root Cause Discovery (Simpler Than Expected)
- **Copilot**: Created analysis script to compare expected vs inferred edges.
- **Discovery**: 40 of 43 FN were from files **outside the sparse checkout scope** (`LanguageVersion.cs`, `CSharpCompilationOptions.cs`, etc.).
- **Root Cause**: The C# oracle used path prefix matching (`startsWith`) for include patterns, which doesn't work with glob syntax like `"FlowAnalysis/**/*.cs"`.

## Turns 21-23: Glob Pattern Fix
- **Fix**: Added `minimatch` dependency for proper glob pattern matching.
- **Fix**: Added explicit `include` patterns to Roslyn fixture oracle config.
- **Fix**: Regenerated expected.json: 295 → 255 edges (40 out-of-scope removed).
- **Result**: Roslyn recall 85.4% → **98.8%** (43 FN → 3 FN).

## Design Insights

### VS Code Extension Architecture
The project is structured correctly as:
- `shared` + `server` = Standalone NPM capabilities (NO VS Code dependency)
- `extension` = Thin VS Code UI layer

This enables:
- CLI-only usage without VS Code
- NPM package publication (`@live-documentation/core`)
- Benchmarks that run in pure Node.js

### Threshold Philosophy
> "The thresholds are sensors, not gates."

Raising thresholds is how work is discovered:
1. Raise threshold → Tests fail
2. Investigate failures → Find bugs
3. Fix bugs → Tests pass
4. Repeat

Lowering thresholds to pass tests violates the core principle: **being correct is the goal, not passing CI**.

### scip-dotnet for Future
While not needed for the immediate Roslyn fix, `scip-dotnet` remains valuable for:
- Semantic C# analysis beyond regex capabilities
- Knowledge Feed integration for richer workspace understanding
- Future polyglot expansion with compiler-grade accuracy
