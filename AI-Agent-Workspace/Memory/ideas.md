## Asked for or loved by the owner

- **Reachability.** Told that about 40% of the non-test lines were unreachable from any user command, they said: "Man oh man, I wish our tool had the capability to tell me that." (2026-09-26) This is the vision's `reachable`. A related finding from dogfooding `inspect` (2026-09-27): `--direction inbound` without `--to` returns every path, capped at 200, which explodes through hub modules; the question "which files does my change reach, and at what hop distance?" wants the set, not the paths.
- **Prose reference report.** Resolve backticked names in markdown against the file index, the symbol index, npm scripts and configuration keys, and report the ones that resolve to nothing, per document. A report, never a gate, because shell fragments, placeholders, configuration values and deliberately historical names all look like dead references. They called it "a wonderful hard problem" (2026-09-27).
- **The graph over time.** On 2026-09-28, after the graph index landed: "I hope one day I am able to run our software against different git states to track the inflation and deflation of the universe of this workspace. I suspect that unification will be very noticeable in the force-directed graph." One state is already cheap: check a commit out into a worktree, run the generator, read its `index.json`. Nothing yet compares two graphs or draws the difference. Related to the animated flyover they named and deferred in [direction.md](direction.md). Told later that day that the vision's snapshot mechanism could hold one system at two commits though nothing is designed for it: "Yes, excellent! Muhaha! Good. I'd hope one day to see the evolution of our software from its own git commits through its own lens." Two snapshots of one system on the board, with the doors and wires that differ between them, is the shape that would give them that.

- **Motion on the Local Map.** (2026-09-28) "I absolutely adore the motion from outputs to inputs across the dangling connectors in your world map demo. I would love that gentle data flow motion on the local map too." An input to vision step 3, with the reduced-motion target under the Explorer section below.
- **Cruft you can see.** (2026-09-28) For what a system stands on once it has gone stale: "overgrown vines or some other indication of dangling cruft", which joins their earlier "dangling vines off the cube's underside, or a cruft of barnacles". Wants the built-on layer (fork 13 in the probe record) and a reading of SBOM files. Corrected the same evening, when the agent proposed age as the number behind the vines: "That's not what I'd want to represent. I would want to be able to look at the underbelly of a system and, based on its SBOM (and whether that SBOM included vulnerability information), know with great confidence that there is a vulnerable library in said system. The vines -- the cruft -- these are _passengers_ that come along for the ride with a piece of software. We should know to what degree we are exposed by this when we are building system diagrams in the world map." So the number is exposure, not age: what an SBOM's vulnerability section says, and how far to trust it when the SBOM carries only components.
- **The disagreement as a nudge.** (2026-09-28) On a configuration value that names one system while the deployed configuration names another: a correction drawn on the World Map is valuable, "Even better, though: using the annoying signal you're fighting as an indication that you need to clean up your web.config and use something like key vault or azure configuration service to get the value _or_ fixing the value in the web.config!" A declaration that contradicts a scan is a finding to report, not only a wire to redraw.
- **The shared thing carries the tool.** (2026-09-28) Asked who writes a board's positions, the owner pointed at a shape the options table lacked: Jonathan Blow "ships his games with the full engine tooling inside them", and a scanning tool they built had to emit an HTML report containing "The entire script to run the output shown in the report" and "The full log of that script execution", both collapsed by default, so that "the system contained the means to perpetuate itself." One reading: the static bundle as a single file that holds the docs it was drawn from, the tool that draws them, the board, the configuration and the log of the run, collapsed under the picture, and that saves a new copy of itself when a person moves or declares something, as TiddlyWiki has since 2004 and as draw.io embeds a diagram's XML in its exported PNG. It dissolves "who writes positions": the shared thing writes itself, and the board stays plain text inside it.
- **A board as a thing on another board.** (2026-09-28, 20:59 UTC) "A world map, being a file (or part of an HTML bundle), could maybe perhaps be a... 'thing' on the board? Maybe? Worth it? Dumb? Same question with recursive directories versus user-defined groups -- levels of abstraction the user wants to see (should a group be a black box?), that kind of thing. I know Obsidian Canvases handle layered groups really well with cool ways to simplify the view at varying degrees of zoom. Very worth understanding their solutions, I suspect." Then, minutes later: "That's probably a stretch goal on my part. I see you resolved tensions on directories so that's probably sufficient." The agent's reading: a thing that holds things, drawn closed, shows on its boundary the doors its members serve to the outside, and a board named as a thing's source would be the same rule one file deeper; the survey of how canvases and diagram tools collapse groups is under `AI-Agent-Workspace/Research/`.
- **The World Map as context for an agent.** (2026-09-29) "Humans are the primary consumer of the explorer, no doubt, but you could imagine an AI use for seeing some semblance of a wider-world-architecture even if they're just scoped to a single slice of it while working in a repo. There are plenty of times that a wider view of the architecture immediately preempts and answers a whole slew of 'why' questions before they ever arrive. (Asterisk - who knows if the world map is something you should necessarily give an agent access to as context - I'm just positing that it is a functional possibility that there is some valid utility to agents despite the human UI/UX focus of the overall experience)." The `live-docs:board` report is the text form of the same picture.
- **Declaring on the picture.** (2026-09-29) "It certainly makes me wonder about the authoring experience, and how one declares the IPSEC tunnel, etc., through UI." Today a declared connection is a line in the board text; the single self-saving file proposal in the probe record is where declaring by hand on the picture would live.
- **Infrastructure files as a source of estate facts, and a library of precomputed indexes.** (2026-09-28) "If we, one day, had a website with precomputed indexes for popular open source software, so that you could slap down an ARM template or BICEP file or whatever and, based on what the resource actually is, get to see inside its black box despite its authorship coming from outside any directory that is open. Probably a fair bit further in the future. Internet calls are things I really do want to do without if I can." And: "IAC files probably can answer some of these questions and quite well. Would be slick as heck to know that Resource A utilizes Mangaged Identity A, which has only read permissions into Resource B, and Resource B carries Managed Identity B which can only do operations C,D,and E against Resource F, so on and so forth. The EntraID model is so ripe for being able to know stuff like that all the way down. BUT -- that's just an idea." Two halves. The first is the vision's snapshots: a published snapshot of a well-known system's docs, downloaded into the board's folder, keeps the tool free of network calls; the website is only where snapshots are kept. The second is a manifest Live Doc for an ARM or Bicep file: resources, their identities, role assignments and network rules are literal in the file, so a district, a tunnel and an edge labelled with what the identity may do are observed from configuration, not declared. Built-in Azure roles map their GUIDs to names and allowed operations through a static table the tool could ship; custom roles carry their operations in the file. New in it for the doc format: an edge that says what is permitted, not only that a call exists. Told the same evening that a template states such an edge in full, the owner: "Stretch goal. Would be awesome but not a hill I'll die on at this juncture."

## The Explorer as found on 2026-09-26

Inputs to the consolidation (vision step 3), not a backlog:

- The default Membrane Map screen is mostly an empty tile; the emoji navigation icons render as boxes; dark theme only; unusable at phone width; five views overlap in purpose.
- `explorer-data.json` was 16.6 MB, 11.4 MB of it chat transcripts. The transcripts are now excluded from the bundle.
- The client still calls endpoints of the HTTP server removed on 2026-03-10 (`/bundled-docs`, `/details`, `/doc`, `/open?codePath=`) from `dataLoader.ts`, `detailPanel.ts`, `download.ts` and `index.ts`; on static hosting they return 404 and the client falls back to bundled data. Dead paths to remove.
- The page template loads the force graph's library from a CDN at run time, a network call the vision forbids; keeping the force graph offline means shipping its library, a dependency to weigh. To resolve in the retirement of the older views (2026-09-28).
- Accessibility targets stated in December 2025 and not re-affirmed since: WCAG 2.1 AA, contrast (1.4.3), name/role/value (4.1.2), reduced motion for the force view. Raise them when the views are redesigned.
- A February 2026 idea: colour force-graph nodes by a deterministic cluster. The co-activation code is gone; the idea does not need it.
- The multi-path rendering design (every shortest path merged into one DAG, near-miss paths dashed, symbol-divergent paths colour-coded) survives in [the Explorer doc](../../.mdmd/layer-3/live-documentation-explorer.mdmd.md) and does not depend on any one view.
- **The three probes of 2026-09-28** are the newest inputs: `AI-Agent-Workspace/Probes/2026-09-28/README.md` holds the verdict on depth by scale, the scale ladder with its transition rules, the list of facts the docs cannot carry, and six forks for the owner. Two findings there bear directly on this section: on this repository the barrel is not the membrane (80 of 95 wires into `packages/engine/src/live-docs/` bypass `core.ts`), and one wall pin per neighbouring folder with a count reads where the reverted hover arcs did not. The record's later section holds the two estate pages after the owner's "pretty mid" verdict and the rule "2D inside the black box of a software system, and 3D outside of one": the interior as a crisp HTML panel in the Local Map's grammar placed in a three-dimensional world by CSS3D, which is the technique to carry into step 3.
- **Inside a large folder the map is dense at rest** (2026-09-29). Eighty cards' wires cross in the engine's `src/live-docs`, as the folder probe warned ("the interior is a hairball at rest"); it reads on hover, when the unrelated fade. The owner's reading, the same day: "If we just open to the Membrane Map, the mess of wires should be gone, as Membrane Map wraps directories", that is, directories as membranes with cross-membrane wires bundled at their boundaries and no wires until symbols are pinned. That is the open fork on the inside. And a folder that serves many things gets one wall wire per served row, which is honest and heavy.
- **No wall for the outside** (2026-09-29). What a folder uses beyond the workspace, `node:fs`, a package, has no pin inside a thing; the folder probe's finding that "the picture wanted a wall for 'outside the map'" stands.
- **The Playwright suite is plumbing, not a verdict on the UI.** Its 29 specs check the Membrane Map's mechanics: state surviving a reload, cards staying inside their membranes, stale URL state degrading cleanly, pixel-stable layout. The owner, 2026-09-28: "I didn't feel that the UI had been fully understood/worked-out enough to make _totally_ useful playwright tests. Still, I suspect that having the baseline plumbing to make it happen was valuable. I just don't want to give the impression that the playwright test suite is all figured out." Read a green run as "the client still draws what it drew", nothing more; the views are being redesigned.

## Engine

- **Ruby, C and PowerShell** still use hand-written scanners. No indexer is installed to measure Ruby (scip-ruby needs a Sorbet project) or C (scip-clang needs a compilation database), so they cannot be measured the way the other languages were. Either an indexer or a different oracle, such as what breaks when a symbol is removed, comes before rewriting them.

- **Openings not yet read** (2026-09-28, from [Openings](../../.mdmd/layer-3/openings.mdmd.md)): Web API convention routing (`MapHttpRoute` templates expanded per controller) and minimal APIs; WCF contracts by name when addresses differ; hostnames in configuration to confirm an HTTP match, in place of the home-and-away presumption; contract files (OpenAPI, WSDL, gRPC, GraphQL, AsyncAPI) as a second source of served openings, for which the survey names maintained parsers; lockfiles for resolved versions; SBOM files, the owner's first iteration of the built-on layer; infrastructure files for districts, tunnels and identities. Also the three estate edges no scan gives: a designer's fields to control ids, endpoint names built by concatenation at run time, a row type matched by result columns.

- **CRLF in the working copy.** 95 source files still carry CRLF line endings from before the 2026-09-27 normalization. Git normalizes them on commit and the generator no longer copies them into docs, so nothing is wrong in the repository; rewriting the working copy is a bulk checkout left to the owner, who rated it "Low priority" (2026-09-28).
