The [constant-size close-up](../../../Screenshots/2026-10-24/generator-near-constant.png) makes the connection field much easier to follow. However, the [constant-size far overview](../../../Screenshots/2026-10-24/overview-far-constant.png) illustrates why preserving some perspective is useful. These comparisons predate the complete resistance implementation, and their label placement still used the earlier sphere geometry; they cannot establish a finished label treatment. The root's temporary `resistance-balanced-arrival.png` and `resistance-balanced-close.png` were also inspected: partial node resistance preserves helpful scale differences while suppressing the most obstructive foreground spheres. Those temporary pictures are not durable evidence or a selected default.

At the close-up, the labels that stand out are mostly the subject's actual neighbours. This is consistent with the source: `positionNames` promotes every immediate neighbour of the focused file to priority 3, without a proximity threshold. Raising the contextual threshold alone will not remove most of those names. Their readability is useful; their combined occupied area and spacing, rather than their individual type size, are the variables to compare.

The selected-file arrival names the neighbourhood but does not by itself fade the rest of the network. In `updateAttention`, ordinary attention comes from pins, an explicit path or opened directories; hover supplies a temporary incident-edge view. Thus many bright wires across a labelled generator neighbourhood are expected under the current interaction model. Exercise Hover and Pin before treating every crossing as a missing attention feature. Changing Centre into a different attention operation would change semantics, not merely a visual coefficient.

The sidebar still describes blue/green bodies as Offers/Uses and blue/green wires, whereas the current Connections picture uses file-archetype body colours and white code-reference wires. The [October 23 review](../../../Screenshots/2026-10-23/README.md) and [current remediation checklist](../../../../.mdmd/layer-3/live-documentation-explorer.mdmd.md#remediation-work) already identify this mismatch. A truthful key would improve interpretation even if no geometry changes.

## Bounded comparisons worth making

| Variable | Existing value/rule at inspection | Candidate to compare | Tradeoff |
| --- | --- | --- | --- |
| Node zoom resistance | Perspective and invariant ends now available | Start around 0.45–0.6 | Keeps foreground nodes from obscuring neighbours while allowing distant clusters to contract. Judge overview and close-up together. |
| Wire zoom resistance | Invariant end available | Start around 0.8–0.9 | Preserves stable readability while retaining a small depth cue. Width and opacity must be judged together. |
| Separation between name rectangles | 5 CSS pixels | 9–12 CSS pixels | Gives names breathing room through the existing priority/collision policy. Some lower-priority names wait for space. Keep subject, explicit pins and path endpoints first; do not shrink type. |
| Ordinary context disclosure | Perspective radius 5px unscoped, 12px scoped | 6px and 14px, if ordinary context still dominates | Mildly delays unrelated names. It does not solve a dense set of direct-neighbour names. Continue using perspective radius for disclosure so increasing node resistance does not reveal all far-away labels. |
| Code-wire opacity | 0.2 active, 0.025 faded | Compare active 0.16 with faded unchanged | Lowers accumulated brightness in dense bundles while retaining every edge. Reject it if sparse, distant connections disappear. |
| Legend | Shared offers/uses key | A key for the actual Connections encodings | Name file archetypes, documented-reference wires, count-dependent width and exposed-surface body sizing. Use the actual palette; do not silently recolour nodes or imply undrawn direction. |

These are a small candidate set, not a request to expose every internal coefficient as another slider. First compare the sizing treatment with unchanged labels, then label spacing, so the reason for an improvement remains visible. Do not change camera framing or force parameters merely to compensate for a label-density issue.

## Measures that help without deciding the picture

Collect each reading at the same viewport, graph membership, camera bearing and scope; test an overview, a focused arrival, a closer view and a pulled-back view, plus a second orbit. Compare the main repository and the estate. Report a small vector of readings rather than a single aesthetic score.

- **Required identities and name load:** report which on-screen subject/pins/path endpoints have usable names, then placed names by priority and total label rectangle area divided by usable map area. Keep minimum font size and zero text collisions as constraints. A lower name count is not intrinsically better: it can hide the very identities the task needs.
- **Body separation and visibility:** report the fraction of on-screen nodes whose projected disc overlaps at least one other disc and the number of intersecting pairs, along with the fraction of on-screen nodes with a radius below one CSS pixel and the count fully covered by a nearer body. Break out the selected scope. An overlap-only score rewards making every node invisible; the visibility reading prevents that false win. Projected-disc overlap is an approximation, not pixel evidence of actual occlusion.
- **Possible false attachments:** for each projected wire, count intersections with the projected disc of a node that is neither endpoint, and the fraction of wires affected. Normalize by visible wire count, preserve endpoint identities and include width. This names ambiguous regions for inspection; it does not prove a false attachment, because actual depth, transparency and local context decide the painted result. Inspect the worst examples while orbiting.
- **Functional separation:** assess known groups from the docs (for example language adapters, Explorer, generator and history) against their actual interconnections. A nearest-neighbour same-group fraction can locate mixed regions, but directory membership is not functional ground truth. Heavy cross-group coupling may make a mixed cluster correct. Never add, remove or relabel edges to improve this measurement.
- **Continuity during movement:** sample visible label IDs and their chosen sides during a small slow orbit and a zoom round-trip. Count avoidable appearances/disappearances and side changes while the same body stays visible and there is still room. Current placement remembers a usable side but processes equal-priority labels alphabetically; a full disappearance discards that remembered side. Only add retention/hysteresis if the motion capture shows a problem.
- **Navigation contracts:** after adjusting appearance, the camera and node positions should be unchanged; after orbit and zoom, Fit should retain the bearing and recover the intended scope. Check hover, the gap to its action strip, Pin, Centre, inspection, and return from 2D at the new rendered sizes. A clear still image does not establish that picking follows the pictured node or wire.
