# Folded description space — November 10, 2026

Completed exploratory comparison, requested in [Turn 4](../../../ChatHistory/2026/11/2026-11-10.1.record.md#turn-4). Root judgment: compact folded rows improve close-reading focus, but this version is not suitable as the default because middle-scale names become too small and folding briefly crosses the footer. Main product behavior remains at `2a890e08`; no composition or default is adopted by this probe.

The owner welcomes the restored reading buttons and asks whether collapsing other symbols' description space would help identify the point being read. The present fixed-slot composition hides the prose but reserves its room. The existing growing composition reclaims that room, while also changing card width, typography and displayed facts. That is a useful whole-composition comparison, but cannot isolate the effect of spacing.

## Criteria recorded before the candidate

1. With the pointer away from the map, does the open description stand out among the other symbol names?
2. Do all names, necessary controls and connections remain readable, without shrinking type to obtain room?
3. Through opening, folding and changing the description being read, can the reader keep track of the card and the name they acted on? Inspect the motion as well as the settled picture.
4. Can two descriptions remain open independently, while pins and the map subject keep their meanings?
5. Does zoom preserve the card's underlying geometry and retain a useful outward-and-back journey?

The first comparisons use the same subject and whole-file pin at 1440×960, DPR one, with ordinary search and motion. The repository subject is [symbolAnchors](../../../../packages/explorer/src/client/views/symbolAnchors.ts), beginning with `normalizeSymbolIdentifier` and then `buildNormalizedAnchorKey`. The estate subject is [PaymentService](../../../../tests/integration/programs/csharp/estate/PaymentService/PaymentService.cs), whose class has prose while its two methods have signature facts but no Summary. Its empty rows are therefore a useful separate case.

## Scope of the isolated trial

Keep the current fixed-slot typography, width rules, controls, facts policy and two-line limit. Only symbol descriptions explicitly folded reclaim their allotted space; their names and connection ports remain. All-open remains the current reference. Keep the file Purpose slot unchanged in this first narrow comparison. Preserve independent all/none/subset choices; opening one description does not automatically fold another. Zoom alone must not alter the underlying box.

The trial was built in a detached worktree from `2a890e08`, with a separate preview on port 8918. Real geometry changes use the existing structural layout path, with measured ladder rooms and the headless card model kept consistent. The exact [eight-file patch](source/trial.patch), [source bytes](source/trial-source.tar.gz) and [build/source manifest](source/trial-manifest.json) are preserved. This implementation is retained as an experiment, not merged into main.

A narrow trial is needed before attributing the improvement to spacing alone.

**Close reading is better in the trial.** The open paragraph has a distinct place among a compact list of other names. Its type, width and two-line cap are unchanged. With one description open, the repository card becomes 398×330 map units instead of 398×477 (31% less height); the estate becomes 254×302 instead of 254×400 (25% less). The unused Purpose allotment still exists above the rows because this trial deliberately changed symbol slots only. It has not solved every empty area or the repeated blue emphasis.

[Two descriptions](pictures/repository-folded-two.png) can stay open independently; [folding the first](pictures/repository-folded-second-only.png) leaves the second open. The title and row order stay stable through the tested reading actions, and returning from eight outward steps restores the compact reading state on [repository](pictures/repository-folded-one-return-0.png) and [estate](pictures/estate-folded-one-return-0.png). No underlying card/row size change was recorded during zoom; the captures use integer DOM map-unit dimensions, not a claim of arbitrary subpixel precision.

**Middle zoom fails the legibility criterion.** The short rows offer much less room for the existing held-name behavior. Their names and controls recede toward the map's small scale, while the row whose description remains saved open retains its larger allotment and name. At that scale none of the prose is visible, so an old reading choice governs which neighboring names remain legible. The current picture already has problems at this scale; the compact trial adds another. A default should not make those other symbols this hard to identify.

**The fold also needs coordinated motion.** In actual frames from the repository recording, the footer and card edge have already reached their shorter layout while symbol rows are still travelling upward. Compare [before](frames/repository-14.2.png), [footer crossing rows](frames/repository-14.4.png), [partway through](frames/repository-14.6.png) and [settled](frames/repository-14.8.png). These are decoded frames from the original 25 fps recording around 14.2–14.8 seconds. The settled card is clean, but the intermediate overlap is real and is not excused as a sketch artifact.

Root recommends retaining compact folded rows as a candidate **reading composition**, then designing its transition to a connections composition that preserves readable names. This supports the earlier complete-appearance comparison rather than choosing an automatic accordion or merging this literal collapse unchanged. A production pass also needs the rows, footer and card boundary to resize together. The owner has not selected a composition.
