## The day's arc

For a reader who was there and lost the thread. The day had three movements, and they are easier to hold apart than its 5,200 lines of record suggest.

**1. An afternoon and evening of many builders (17:10 to 03:00 UTC), under the first root.** The five red cases were run down, none by raising a bound. The packet reached the owner: twelve questions as matched pictures, with alternatives built for five. Then the tool was **run cold on public code shaped like the owner's work** and would have embarrassed us: PowerShell scripts with no connections between them, a SQL reader that crashed and invented objects, .NET user controls that never reached their code-behind. That finding set the day's largest block of work: readers for SQL, PowerShell and .NET graded against Microsoft's own parsers, and an **engine round** (names that read back from a doc whatever characters they hold, one rule for a Markdown link's target, Windows text and the command line, Node 26) that landed at 00:56 UTC behind two independent reviews and a rebuild in which all 1,224 comparable commits came out identical. In the same evening the owner made the day's largest product decision: **the facts the tool derives may stop being stored as a Markdown doc for each file** ("I think it's time to try, eh?"), with Markdown exported on demand, a Markdown document allowed to be a node of the map, and the stored format to be chosen by research and measurement.

**2. A night on iteration speed (03:42 to about 13:00 UTC), under the second root,** which the owner had hoped for in [Turn 13](../2026-11-19/2026-11-19.1.record.md#turn-13). Measured first: where the browser suite's 43 minutes go, why the gate was slower in the main checkout (the scan walked 28 builders' worktrees that git ignores), and why a history rebuild is slow (one thread writes every commit's tree). Landed on `main` that night: the 3D focus fault mended at its cause, the audits' walk (17 s to 2 s), and Playwright moved to a version that installs under Node 26 and still reaches the graphics card. The whole browser suite then stood at 601 of 609 with one red, the nearest it has come to clean. A warm history run fell from a minute and a half to four seconds on a branch.

**3. A long day getting the history's speed-up through review (about 10:00 to 22:09 UTC).** Workers that live from commit to commit rebuilt the whole line in 33.8 minutes against about 71, every comparable commit identical. Independent reviewers then found, round after round, faults that no test and no byte-for-byte comparison on this repository could show: a warmed worker reads a more deeply nested file than a fresh process can, so a summary could depend on which worker made it; a file the generator fails on vanished from the history without a word; the scan disagreed with git about nested repositories. Root spent about five hours on a count of a file's nesting that three reviewers each broke within the hour, then measured the simple alternative in half an hour and took it: **every commit gets a fresh worker by default; keeping workers is a flag that is off.** That landed at 22:09 UTC with everything else of the night: the scan reading git's own listing, a rule that a machine's failure is never recorded as a property of a file, a cache key that no longer moves when an unrelated package is bumped. The safe default is about 1.4 times faster than the old way on recent commits; the flag is about 2.5 times.

What the day did not do: nothing of the readers' work for the December showing is on `main` yet; the packet and the open, close and pin proposal wait on the owner; the store's change is surveyed and not begun.
