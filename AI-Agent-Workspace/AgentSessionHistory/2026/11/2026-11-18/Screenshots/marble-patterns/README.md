# Marble Pattern: one pattern, or from its doc, how far it bends, and how its sketch turns

_Historical evidence, taken 2026-11-18 and 19 by the builder of the trial. The trial is described in [the Explorer design](../../../../../../../.mdmd/layer-3/live-documentation-explorer.mdmd.md); the owner's wish behind it is [Turn 20 of the November 18 record](../../2026-11-18.1.record.md#turn-20)._

**The setup.** This repository's Explorer, built from the trial's working tree. The marble sheets are drawn by `npm run marble:sheet` (`scripts/contact-sheet/marble-sheet.ts`). Node works out each marble from the bundle's graph using the Explorer's own modules. A loaded 3D page lends its renderer, its lights and the marbled spheres' material, so the shaders are the page's own. Each marble is a 96 × 64 sphere at 0.75 opacity on the 3D map's ground. The pattern and the Vein Bend are set for each row with the Tuning levers, as a viewer would set them. The 3D map pictures are drawn by `npm run contact:sheet -- --marble-pattern`. The graphics card drew every picture.

**Three rounds.**
- **The first (2026-11-18)** tried One Pattern, From Its Doc, and From Its Doc, Axis Too, where the axis came from the sketch as well. The sketch was the features' sum brought to unit length.
- **The second (2026-11-19)** dropped Axis Too: across files it looked no more varied than From Its Doc, since the path already scatters the bearings. `files-doc-axis.png` and the Axis Too row of `run-pathfind-unit-length.png` are the evidence. It added **Vein Bend** as a slider beside the pattern. Its fork sheet, now `fork-forceGraphView-unit-length.png`, showed that neither a marble from the doc nor one from the file's contents moved visibly from commit to commit: the unit length divided every edit by the file's size.
- **The third (2026-11-19)** replaced the unit length with a wrap. Each component of the sum becomes `0.5 · sin(sum / TURN)` (`SKETCH_STRENGTH` and `SKETCH_TURN` in `marbleSketch.ts`), so that one feature more turns each wave by the same amount in a file of any size. TURN was chosen at **4** from the two `turn-choice` sheets. Every other sheet here was then drawn again with it.

**Frames a second.** These were measured in the first round, for this repository's 3D map as a fresh page opens it, at 1440 × 900, at rest, with the page's own camera. The page's renderer drew the scene again and again, and each frame was waited out by reading back one pixel. Each figure is one of two rounds (a probe, not kept):

| Renderer | Marbles off | One Pattern | From Its Doc | From Its Doc, Axis Too (dropped) |
| --- | --- | --- | --- | --- |
| Software (SwiftShader), 8 frames each | 16.4, 18.1 | 12.3, 14.6 | 13.2, 12.1 | 13.1, 12.4 |
| Graphics card (RTX 3090 through D3D12), 30 frames each | 307, 309 | 320, 319 | 318, 284 | 298, 298 |

In software, From Its Doc costs about what the round-to-round noise is, some 5 % against One Pattern. On the card, nothing measured is distinguishable. The later rounds did not change the shader's work: the bend became a uniform, and the wrap is computed once per file in the page's script, not in the shader. So the figures were not taken again.
