# Marble Pattern: one pattern, from its doc, and from its doc with the axis too

_Historical evidence, taken 2026-11-18 and 19 by the builder of the trial. The trial is described in [the Explorer design](../../../../../../../.mdmd/layer-3/live-documentation-explorer.mdmd.md); the owner's wish behind it is [Turn 20 of the November 18 record](../../2026-11-18.1.record.md#turn-20)._

**The setup.** This repository's Explorer, built from the trial's working tree. The marble sheets are drawn by `npm run marble:sheet` (`scripts/contact-sheet/marble-sheet.ts`). Node works out each marble from the bundle's graph using the Explorer's own modules. A loaded 3D page lends its renderer, its lights and the marbled spheres' material, so the shaders are the page's own. Each marble is a 96 × 64 sphere at 0.75 opacity on the 3D map's ground. The three patterns are chosen in each row with the Tuning lever, as a viewer would. The 3D map pictures are drawn by `npm run contact:sheet -- --marble-pattern`. The graphics card drew every picture.

**Frames a second.** These are for this repository's 3D map as a fresh page opens it, at 1440 × 900, at rest, with the page's own camera. The page's own renderer drew the scene again and again, each frame waited out by reading back one pixel. Each pattern was chosen with the lever on the same page, and each figure is one of two rounds (a probe, not kept):

In software, the trial's two patterns cost about what the round-to-round noise is, some 5 % against One Pattern (12.7 against 13.4 on average). The marbles themselves cost more than that, as before. On the card, nothing measured is distinguishable. These are not the November 17 figures (4.4 against 5.3): those were the page's own loop while the picture settled.
