## Authored
### Purpose
Makes the repository dictate its own line endings: every text file is stored and checked out with LF, whatever a contributor's `core.autocrlf` says, while git's detection of binary files leaves those alone.

### Notes
_No reader handles this kind of file yet, so the generated sections are empty for that reason, not because the file exposes or uses nothing. Revisit this note when a reader arrives._

- Read by git alone: when it stages a file, which it normalizes to LF, and when it checks one out, which it writes with LF. The dev container's global git configuration sets `core.autocrlf=true`, which without this file gives a CRLF working copy on Linux.
- A working copy checked out before this file arrived keeps its CRLF files until each is rewritten. Git normalizes them on commit and reports them unchanged, so an edit that matches on line ends can still miss one; this checkout held 420 such tracked files on 2026-10-22. Rewriting them at once is a bulk checkout, which AGENTS.md forbids an agent to run.
- The history command checks old commits out with `core.autocrlf=false`, their line endings as stored (`packages/engine/src/live-docs/history/git.ts`), so that a person's setting never changes what the history reads; commits older than this file carry no `.gitattributes`.
- Added on 2026-09-27, when the CRLF working copy was making the agent's line-anchored edits miss. The agent proposed it and the owner chose it: "Feel free to go with a gitattributes, that's probably easier."
