## Authored
### Purpose
The PowerShell adapter: parses `.ps1`, `.psm1` and `.psd1` with the engine's own build of the tree-sitter PowerShell grammar and reports what a reading of PowerShell owes. Of a script or module: the functions it publishes with their comment-based help, the classes and enums it defines, the files and modules it loads (dot-sources, `Import-Module`, `using module`, `#requires -Modules`, scripts run by their path, through `Join-Path`, a variable or a folder listing where the text fixes the path), and the files whose functions it calls, by the rule "loaded, else unique"; a `.ps1` is the program's entry unless it is a library. Of a module manifest: the module it publishes, the modules and scripts it names, its root module as the `module` entry it declares, and the functions it offers from their origin files. A `.psd1` that is a data file is read for nothing.

The bundled grammar could not read three constructs an estate's scripts use daily; shown the choice between landing with those holes and building a grammar first, the owner asked for the durable shape, "What is the right final shape? Build that, and then commit it." ([Turn 4](../../../../../../../AI-Agent-Workspace/AgentSessionHistory/2026/10/2026-10-16/2026-10-16.1.record.md#turn-4)). The same day the grammar became the engine's own build ([`grammars/powershell`](../../../../../../../packages/engine/grammars/powershell/build.sh)) and the adapter took manifests, classes and enums, and resolution as Windows resolves.
- Symbols: every `function`, `filter` and `workflow`, nested ones included, under the name as written (`script:Get-LogPrefix` keeps its scope), at the line and column of the keyword, of kind `function`; every class and enum, of kinds `class` and `enum` as the C# adapter names them, at theirs; all in document order. A class's constructors and methods are not functions. A file that calls `Export-ModuleMember` publishes the functions its `-Function` patterns (or first argument) match, by PowerShell's wildcards and without regard to case. An `Export-ModuleMember` the grammar could not read in full, or one with a pattern not written out (`-Function $public`, a sub-expression), which only a run of the module could read, narrows nothing, so a misreading shows private functions rather than hiding public ones; the oracle's published list follows the same rule (settled on the evening of 2026-10-16 from that principle, which until then covered only a list the grammar misread). Classes and enums are not narrowed: a script reaches them through `using module`, which `Export-ModuleMember` does not govern.
- Help is found where PowerShell finds it: the comment block before the keyword with at most one blank line between, then each comment block opening the body, then the block before the closing brace. A block is help when every line outside a section is blank and every keyword is one PowerShell knows (`.SYNOPSIS text` on one line, or `.NET` at a line's start, makes it not help); `.SYNOPSIS`, `.DESCRIPTION` and each `.PARAMETER` become the summary, remarks and parameters, a parameter under the spelling the function declares; the other sections are read past. The rules were checked against PowerShell 7.5.4's parser on some fifty probe functions on 2026-10-16, with no disagreement; `powershell.test.ts` keeps the cases.
- `Import-Module` and `Export-ModuleMember` are bound by the cmdlets' signatures as PowerShell 7.5 declares them, so a switch takes no argument, `-ErrorAction Stop` names no module, and an abbreviated parameter is matched; `ipmo` and the `Microsoft.PowerShell.Core\` qualifier are recognised. A comma list of bare words (`-Function A, B`, over several lines too) is one argument of several strings. `using module` is read from the grammar's `using_statement` by name, string, module specification or path; `#requires -Modules`, a comment to the grammar, is read from the comment wherever it stands, by name, string or a hashtable's `ModuleName`.
- A path is resolved when the text alone fixes it: a string or a bare word written out (`$PSScriptRoot\..\lib\x.psm1` unquoted is one word), `$PSScriptRoot` or `${PSScriptRoot}` standing for the file's directory, a relative path taken from that directory, as if the script ran from where it lies (PowerShell resolves a relative dot-source or `Import-Module` path against the caller's location at run time, which no reading of the text knows). A module path may name a `.psm1`, a `.psd1` or a directory holding the module of its name. Each path is looked up in the workspace's file index, the generator's, as Windows finds a file: spelled exactly, or else the only file whose path differs in case alone, so `. .\Lib\Logging.ps1` finds `lib/logging.ps1` and a path that names two files differing in case alone stays unresolved. One case-folded map of an index is built per run. Without an index nothing resolves; a rooted path (a drive, a share, a leading separator) is outside what the workspace can say. A resolved path is the dependency's specifier; anything else keeps its text.
- Manifests: a `.psd1` whose table has a `RootModule` (or `ModuleToProcess`, its older name), a `ModuleVersion` or a `FunctionsToExport` is one. Its table is read through the grammar by a small reader of the data language, strings with their escapes, lists, `@()`, tables keyed without regard to case and numbers, anything else left unread. The module, named by the file's stem, is its one `package` symbol; each entry of its root module, `NestedModules`, `ScriptsToProcess` and `RequiredModules` that names a file from the manifest's folder (or a directory holding the module of its name) is a linked dependency, the oracle's rule too, and any other is external, `name@version` when a module specification writes a `RequiredVersion` (else a `ModuleVersion`); linked files come first in path order, then the externals sorted, as the other manifests write them. The root module is declared a `module` entry, so its doc says which manifest makes it one; the manifest itself is a `tooling` entry by the package it publishes, since its name cannot tell it from a data file.
- A file is decoded by its byte order mark, UTF-16 in either order, else UTF-8, as PowerShell reads it: measuring the grammar over the modules installed with `pwsh` on 2026-10-16 found two large ones in UTF-16, which a UTF-8 reading turns to noise. _(Since 2026-11-19 the file being analysed, and since the joining of 2026-11-21 ([the work item](../../../../../../../AI-Agent-Workspace/Work/readers-on-main.md)) every PowerShell file the workspace table reads, is read through the engine's one reading step, `sourceText.ts`, which also reads UTF-16 without a mark where it is certain and Windows-1252, what Windows PowerShell 5.1 writes; a failure of the machine's in the table's read is thrown on to the generator, never read as a file that defines nothing.)_
- Not followed: a module named rather than pathed, which a machine's module path finds, so a `RequiredModules` name stays external even when the workspace holds a module of that name; `Import-Module Name.psm1`, an extension without a separator, read as a name as the oracle reads it, where PowerShell takes it for a path from the current location; a path built any other way than below (a variable assigned twice, in a block or from a parameter, `Split-Path`, a `+`, `$env:`); a loop over a written-out list of names.
- Calls between files, since 2026-11-19 ([the probe](../../../../../../../AI-Agent-Workspace/AgentSessionHistory/2026/11/2026-11-19/Probes/powershell-wires/README.md); [the decision](../../../../../../../.mdmd/layer-3/architectural-decisions.mdmd.md#a-powershell-call-reaches-what-its-caller-loads-else-the-only-definition-recorded-2026-11-19)): a cold run on dbatools had found 1,947 of its 1,977 files with no wire, because a function one script defines and another calls was never drawn. Measured first, against PowerShell's own parser over five corpora and two readers of sampled wires, rule R, "loaded, else unique", drew 60 true wires of 60 where the other rules drew stubs and copies the caller never loads. Every PowerShell file of the workspace is read once per run, into a table kept per file index as the C# reader keeps its type table (`buildWorkspace`), whose facts the file's own analysis reuses when its text is the same, so each file is parsed once a run where it was parsed twice before. A call goes, by `calledFiles`, to the one file defining the function at its own level that the caller's loading reaches (its dot-sources, imports and `using module`, followed, and its modules' files and their loads; a script run by its path is not followed, since its scope ends with it); to none when the loading reaches several; when it reaches none, to the only file of the workspace defining the name, unless PowerShell itself ships a command of that name ([`powershell.builtins.ts`](./powershell.builtins.ts.mdmd.md)). A name the caller defines itself, at any depth, is its own. A definition inside a function, a script block (a test's `BeforeAll`, `Describe`, `InModuleScope`) or text the grammar could not read counts as none: the last because a test whose blocks the grammar lost stood its stubs at the file's own level, which drew 562 false wires on dbatools before it. A wire is a dependency on the file carrying the function's name as defined there, merged into a load of the same file.
- Loads the text fixes, the same day: a string or bare word as before; `Join-Path` of such, its `-Path`, `-ChildPath` and further children by name or position (named arguments first, the rest filling the positions left, as PowerShell binds them); a variable assigned exactly once in the file, by `=`, at its own level, from such; a `foreach` or `ForEach-Object` that dot-sources each item (`$f`, `$f.FullName`) of a `Get-ChildItem` whose folder, `-Filter`, `-Include`, `-Exclude` and `-Recurse` the text fixes, written in place, through such a variable or joined by `+`, a comma or `@()`, listing the `.ps1` and `.psm1` files beneath it as Windows finds them; a script run by its path after `&` or as a command's name. A load read only through `Join-Path` or a variable is drawn when it names a workspace file and otherwise by its text as written, if any.
- The evening of 2026-11-19, on the root's rulings after the build ([the probe](../../../../../../../AI-Agent-Workspace/AgentSessionHistory/2026/11/2026-11-19/Probes/powershell-wires/README.md#rulings-after-the-build-added-november-19-2026-late-evening)): a variable is fixed when it is assigned exactly once in the file, by `=`, before the load in the text, in the function or script block that holds the load or one enclosing it (a test's `BeforeAll` that sets `$scriptRoot` and loads by it), not only at the file's own level; `Split-Path` of the script's own path (`$MyInvocation.MyCommand.Path` or `.Definition`, `$PSCommandPath`) is its folder, of another fixed path its parent, unless it asks for a leaf, a qualifier or whether the path is absolute; a `foreach` or `ForEach-Object` over names written out (a string, a list, `@()`, or a variable assigned one) is read once per name with the loop's item standing for it; and the fallback to the only file defining a name passes over test files when the caller is not a test, by the archetype the product's naming conventions give (`resolveArchetype` with the default configuration: the adapter is not given the workspace's configuration, so its overrides and sample roots are not read here). _(Since the joining of 2026-11-21 the generator's file index carries the archetype under the workspace's own configuration, `archetypeOf`, by the lines [the probe](../../../../../../../AI-Agent-Workspace/AgentSessionHistory/2026/11/2026-11-19/Probes/powershell-wires/README.md#the-archetypes-test-folders-added-november-19-2026-night) gave for it, and the adapter reads that; an index made without the generator, as a test's, keeps the default configuration's answer.)_
- What a load draws nothing for is said, since the joining of 2026-11-21, as a notice on the generator's channel ([the work item](../../../../../../../AI-Agent-Workspace/Work/readers-on-main.md)): a dot-source or `Import-Module` whose path the text does not fix and no loop reads (`. $command`, `Import-Module $path`), as "dot-sources and imports whose path the text does not fix, left unlinked", each named by its line and command; and a load built with `Join-Path`, a variable or `Split-Path` whose path names no file of the workspace and has no text of its own to keep, as "loads whose path the text fixes but no file of the workspace holds, left unlinked", by the path. A dot-source of a script block (`. { … }`) loads no file and is said by neither. Until then both were dropped without a word.
- Whether the text a file's analysis is handed is the text the table read of it in the same run is told by its length and a 32-bit FNV-1a hash written in the file (`digest`), since 2026-11-21; until then a SHA-1 digest from `node:crypto`, a Node module the browser bundle of the engine has no stand-in for (the page scan, [the work item](../../../../../../../AI-Agent-Workspace/Work/readers-on-main.md)). It compares two readings of one path within one run, so nothing cryptographic is needed; the four PowerShell corpora score as before.
- Programs since 2026-11-19: a `.ps1` whose own level only defines functions, filters, workflows, classes and enums and otherwise only sets up its scope (dot-sources, `Import-Module`, `Set-StrictMode`, `Export-ModuleMember`, `Set-Alias`, `New-Alias`, `Add-Type`, `Update-TypeData`, `Update-FormatData`, `Register-ArgumentCompleter`, assignments that call nothing on either side) does nothing when run and is a library, not the program's entry; one holding text the grammar could not read at its own level stays a program. On a seeded sixty it erred only toward calling a library a program: a helper that imports inside an `if`, and an include that only assigns a variable.
- A manifest's `FunctionsToExport` offers each name it writes out from the one file of the module (its root and what that loads) that defines it at its own level, as a TypeScript barrel offers what it re-exports (`reExportedSymbols`, rendered as `Re-Exported Symbol Anchors` with a link to the origin), not as a wire; a wildcard, or a name the module does not define once, is not offered.
