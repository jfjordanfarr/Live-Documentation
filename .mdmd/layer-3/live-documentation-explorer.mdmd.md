# Live Documentation Explorer

_Current as of 2026-10-20._

## Metadata

- Layer: 3
- Archetype: component

## Authored

### Purpose

Describe the static Explorer that renders the canonical Live Doc graph and authored boards. The existing Local Map provides file and symbol detail; the native Force Graph provides a three-dimensional perspective on file connectivity. Their independent exploration pins and selected identity are shared. Navigation has three views: Knowledge Sources, World Map and Local Map. The Local Map owns directory browsing and both 2D and 3D representations.

### Independent exploration

The 2D/3D setting is independent of the active navigation view. Browser storage remembers it when leaving and returning; `view=local&mode=2d` or `mode=3d` shares it explicitly. Old `view=force` links open Local Map in 3D; `membrane` and `circuit` links open it in 2D. Compressed version 1 links migrate their selected file, pins and deepest opened directories. A path restores before first paint without overriding the chosen representation.

Direct file links, pinned branches and paths share the directory-aware layout from their first drawing. A file link discloses a neighborhood without storing implicit pins. A shared path is resolved before first paint, and clearing the destination restores the exploration and its camera. The [owner’s October 12 walkthrough](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-12.1.record.md#turn-3) exposed and retired the separate initial and path renderers. Scrolling zooms within the chosen perspective; the controls say 2D and 3D, with full names in their tooltips and no density suggestion.

The map subject, retained pins, inspected evidence and camera frame are separate. Clicking a file, symbol, directory or related document opens its evidence without changing the subject, pins, path or camera. Direct Pin controls retain a file or symbol in one action; Centre deliberately moves the map subject, and directory Open discloses its contents. These are the owner's [October 19 inspection and direct-Pin decisions](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-19.1.record.md#turn-24), completed in [the October 20 continuation](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-20.1.record.md#turn-2). More, right-click and a stationary hold offer contextual commands. Movement, multiple pointers, cancellation and Escape cancel a hold. Local Map double-click navigation is omitted; Centre and Open are explicit controls.

Pinning retains connections without removing other pins. The map displays the union of those neighborhoods and every relationship between retained files, beside the subject's neighborhood while the subject holds no pin of its own. A whole-file Pin retains all its symbols; a symbol Pin narrows a whole-file pin to that symbol; further symbols add; pressing an already pinned symbol releases it; releasing the file's last symbol leaves the file pinned whole. A file's Pin pressed again releases that file's pins and nothing else, so a Pin undoes itself; the card's close and the tray are what release a file under the subject policy. A pin never moves the subject. In 2D the acted-on symbol row or directory stays under the pointer through the resulting movement, and keyboard focus returns to its control. The subject moves by Centre, a search choice or its release policy. Taps, clicks and Enter activate the same visible controls; hover only previews, and 2D pan and pinch use pointer events. Cycles are broken at feedback references, drawn as laces with their route on hover; skipped ranks use reserved lanes between cards. Counts identify connections outside the disclosure, including those hidden by filters. Explicit pins and the selected file remain visible through filtering. Perspective controls preserve the selected identity’s screen position; manual camera gestures end automatic tracking.

The evidence reader overlays an unchanged canvas. At narrow or short viewport sizes it fills the viewport, makes the background inert and carries its own Back, Forward and Close controls. At wider sizes the map controls stay in the uncovered area. Links inside evidence inspect their target; file, symbol, directory and bundled-document fragments travel independently in the share link and remembered place. Back between evidence targets leaves the map DOM and camera intact. Old links without an inspection target open with the reader closed; stale evidence is discarded without replacing the map subject. Escape closes the reader unless something above it, the search field, a menu or the ancestry chooser, takes that Escape first, and the World Map behind the reader never acts on a key the reader used or one typed in the full-screen reader. Closing evidence returns focus to its opener, or to that opener rebuilt by a render, or else to the map itself, never to a text field. Internals remains a file-level endpoint with its own pin, without inventing private-symbol documentation.

The lower-right pin tray lists explicit directory, file and symbol selections newest first, in an order preserved by shared links. Its focus action brings an item into view without adding a pin. Releasing a directory removes only its own opening; independently opened descendants and file/symbol pins survive. The separate **Clear pins inside** action releases the directory and contained selections together, while outside pins can still require some of its files. Clear all includes directory openings and removes pin-driven focus. With no retained selections or selected file, 2D shows the scan root's immediate files and closed child directories without manufacturing a root pin; 3D restores normal visibility. The owner approved these distinctions in [the October 14 implementation request](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-11--pin-management-approved-ancestor-disclosure-and-directory-hubs).

Membrane names inspect their directory. Open (Close, once open) and More stand together at the label's right end, in a column of their own beside the name and count, as card actions stand in a card's corner, so the caption stays one text flow. A separate ancestry control unfolds ancestor choices at viewport text size, with a temporary enclosure around the currently drawn members on hover or keyboard focus. Choosing an ancestor opens its immediate contents. This provides access to the root while keeping single-child ancestor chains compressed in the main picture.

### Competing layout preferences

**Compact / Relaxed** is one packing preference for both representations, selected beside 2D/3D. Compact favors a smaller footprint; Relaxed spends space on clearance and regularity. Advanced controls under Tuning expose the values behind both profiles. Changed packing values read as Custom; coupling and symbol-size controls remain independent and survive preset switches. Settings persist locally, travel with shared links and can be exported as JSON. Older links without layout settings keep the viewer's preferences. The owner approved this grammar and its advanced controls in [the October 13 implementation request](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-6--shared-presets-and-advanced-tuning-approved-for-implementation).

The representation controls sit at the bottom center. Compact and Relaxed are named icon buttons with pressed states; the tuning button identifies a customized layout and opens the existing advanced controls. The pin tray occupies its own lower-right surface and coordinates with the Details drawer.

The 2D layout prices wire distance, crossings, picture height, ordering churn, membrane evenness, row alignment and boundary-step count together. Membrane Evenness prices the distance a boundary rises or falls; **Membrane Simplicity** prices each nonzero step, so several small changes can lose to fewer larger ones. Compact uses narrower column/card/directory gaps and a stronger height cost. Relaxed uses stronger shape preferences, with simplicity 200, evenness 2 and row levelness 2; Compact uses 100/1/0.25 respectively. Both value alignment, while Relaxed permits a greater wire-length tradeoff for composition, as the owner clarified in [the review](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-8--relaxed-should-spend-wire-length-on-composition). These are preferences in a local competition, not guarantees that every individual signal improves in every scene.

In 3D, one line represents a file pair, with its documented reference count on hover. Imports and signature references count once each; multiple documented references sharing visible endpoints carry multiplicity, while the canonical graph retains all evidence. More coupling shortens the preferred surface gap logarithmically, bounded by size-aware collision clearance. Sphere volume grows from public-symbol count plus one baseline unit. Both presets retain the same coupling and size meaning: position suggests coupling, size suggests exposed interface, and the preset controls packing. These counts describe documented structure, not runtime call frequency or complexity. Related-document overlays use the same projection in the browser and command.

**Gravity and Repulsion Reach** (2026-10-17) are the 3D picture's restoring levers. Before them the simulation had a spring on each pulling link, a repulsion of every sphere on every other with no bound on its reach, a collision, and a centring that only kept the whole picture's mean at the origin, so two clusters that shared no link had nothing between them but repulsion and every change pushed them further apart, which the owner saw as "the microgalaxies drift further apart" under repeated type toggles. Gravity pulls every sphere toward the picture's centre in proportion to its distance, so the picture has an equilibrium it returns to; the reach bounds how far a sphere's repulsion acts. Both ride in saved and shared settings and sit under Tuning's 3D group. The shipped gravity is 0.05 and the reach unbounded, the layout lab's `drift` measure's reading of 2026-10-17: the smallest force that held every measured shape within a tenth of its settled extent over five membership changes, cutting the unchanged spheres' move to a fifth at about half of the former spread ([the decision](architectural-decisions.mdmd.md#the-3d-picture-has-gravity-a-restoring-force-in-place-of-held-hubs-recorded-2026-10-17); [the lab record](../../AI-Agent-Workspace/Probes/2026-10-17/layout-lab/README.md)); the owner's eye decides the final value from the pictures.

**Spring Strength** (2026-10-18, the owner's ask after their first look at the gravity: "Can you just give me those sliders in the tuning panel and I can just tweak it until it's good to my eye?") is how hard a wire's spring pulls its two files together, as a multiple of D3's own rule, which gives each link one over the smaller of its two ends' link counts so that a file with many wires is pulled less by each; one is the picture as it was, zero lets the wires go slack. With Gravity, Repulsion Reach and Repulsion beside it under Tuning's 3D Layout group, the pull to the centre and the pull between connected neighbours are both in the owner's hands, persisted and carried by share links, and the Export layout settings button writes the numbers out.

**Update Energy** (2026-10-18) is how much a change to what is shown stirs the 3D picture: a pin that brings a filtered file in, a filter toggled, a layout switched, and later a step of history all pass through one update path, which carries every sphere that stays, seats a new one beside what it is wired to (a hub at its members' centroid, a file at its hub's or its references' spring length in a direction its id seeds) and feeds the simulation by the energy. In D3 a reheat is one number, the alpha the simulation starts from, so the lever is that number: at 1 the full reheat the library makes of every change, three hundred ticks to the settled alpha; at a fraction a reheat to that alpha, cooling at the library's rate to the same stillness and so stopping sooner; at 0 placement alone, no tick. The library reheats to one on every change and exposes no alpha of its own, so the fraction is the share of alpha the spring, the repulsion and the gravity see, read at every tick (the collision ignores alpha). The shipped default is 0.1, the lab's and the builder's reading of 2026-10-18: the unchanged spheres stir about a quarter as much as under the full reheat on this repository's bundles, the extent holds, a type toggle leaves the picture recognisably itself while the gaps close, and the switch into the structure layout still forms the tree ([the lab record](../../AI-Agent-Workspace/Probes/2026-10-18/layout-lab/README.md); [the pictures](../../AI-Agent-Workspace/Screenshots/2026-10-18/README.md)); the owner's choice among the pictured settings is open, as it is for gravity. The link objects are kept by pair across a change, as the node objects are by id, so the library keeps every line it drew where before it rebuilt them all. The first picture always warms up in full; a change of the forces reheats fully; a sphere dragged by hand acclimates the picture with all of alpha; and the engine stops when the layout has settled, with no time ceiling, so a slow renderer shows a settled picture later rather than an unsettled one. The plan's ticket C2 holds the design ([Change over Time](change-over-time.mdmd.md#open-questions)).

**History** (2026-10-18) is the 3D Local Map's rendering of change over time, ticket C4 of [the plan](change-over-time.mdmd.md#open-questions): when the bundle carries a history (the sequence the history command computed, carried beside the data by the exporter's choice), a History button stands beside Connections and Structure, for now, until the consolidation pass the owner expects, and opens a scrubber along the bottom of the picture, fetching the sequence then and not before, so that a page without history is no slower. The scrubber draws one tick per step from a pure tick model (`history/tick-model.ts`): with nothing pinned every step is a major tick; with pins, the engine's `ticksFor` marks the steps that changed the shape of what is pinned as major and the steps in which the version control saw a pinned file's content change alone as minor (the owner's words, 2026-10-17: "the kind of quantum leap events are major ticks and the update-only changes are minor ticks"), followed through the pins' renames; the rest are faint and a drag passes through every one. The granularity (every step, days, weeks, months, the salient steps alone, or an automatic choice by the number of steps within a budget) and the axis (evenly by step, or by date, so that a quiet half-year reads as a gap) are levers under Tuning's History group with the play rate, the view's half of the granularity seam (C14). The arrows move a step, Page Up and Page Down between the major ticks, Home and End to the ends; the date and the commit's subject are the slider's spoken value, the date and the hash its readout; a ruler of dates runs beneath the ticks. A move materializes the step from the sequence (a cursor that applies the deltas forward and seeks back from the nearest keyframe) and feeds the picture through the one update path: the renamed files and hubs keep their objects under their new ids, re-keyed before the draw, a born file is placed by the carry rule, and nothing is held in place. While the thumb drags each frame places the steps it crossed without a tick, coalesced to one per frame so that the thumb never lags (a median 9 ms of script a step at 1,099 spheres on 2026-10-18); at rest the picture is fed at the tuning's energy. Beside the picture a step panel says what the step changed, the subject, the hash, the date and, by a toggle beside the scrubber that rides the address, the author (C8), then the files born, dead, renamed and resized with their archetype and symbol count at the step, the directories renamed whole, the wires that came, went and changed their count, and the files whose content changed alone, each file a button that pins it where it still exists today and "gone since" where it does not. The address carries the commit, so a link to a moment opens on it, the sequence fetched before the first picture; a pin whose file does not stand at the moment is said "not yet born" in the tray and never dropped; the last step is today, where the picture is today's docs; leaving 3D for 2D or another view returns the picture to today and closes the control. A history cut at its beginning, a shallow clone or a window an export carries, gets a hatched band before its first tick and the panel says why; a bundle without history shows no control, and the Knowledge Sources panel says so in one line naming the command to copy. The pictures of the day are in [the history folder](../../AI-Agent-Workspace/Screenshots/2026-10-18/history/README.md); `tests/e2e/history-scrubber.spec.ts` holds it over the scripted sample.

**Connections or Structure** is the 3D Local Map's layout, a choice inside 3D shown beside its button and remembered like the perspective (2026-10-14). In the connections layout the documented references pull and are drawn: the emergent network of what the code does. In the structure layout every file and related document hangs from its directory's hub and every hub from its parent's, up to the scan root, by one containment link each: the emergent tree of what the file system declares; a hub holding nothing but one child collapses into it, as the 2D bands collapse such chains. Hubs are amber, and a hub's volume is the sum of its members' volumes, so that size means exposed surface at every scale. Only the links of the chosen layout are given to the spring force; the other kind stays in the data, pulls nothing and counts for nothing. Containment is drawn as the structure it is; a reference is drawn in the structure layout only on demand, for the hovered file, within and out of the hovered hub's subtree, among the retained files, and along a path. Switching layouts keeps every file where it stands and starts each new hub at the centroid of its members, so the simulation folds the network into the tree before the eye, and unfolds it on the way back. Directory hover reveals its members; clicking inspects it, Open retains its contents (Close, once open, as the 2D label offers), and Centre frames the hub with its members. The owner chose this separation after seeing hubs inside the connectivity layout ([Turns 3 and 4 of the October 14 record](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-14.1.record.md#turn-3)). There are no 3D enclosing volumes.

Hover in 3D temporarily reveals the hovered file's incident connections, including a file outside the retained scope. Leaving restores the current pins, directories or path. One application pick of the rendered spheres decides hover, click and hold alike, so a fast entry, a camera move under a still pointer or a lifted finger cannot leave a stale preview behind; the graph library's own hover callback, which reports only changes between objects, no longer decides it. A control the mouse pressed may keep keyboard focus without keeping its file's preview, while keyboard focus on a sphere's actions, or an open menu, keeps it. Wheel zoom preserves the inspected point's projection and never reverses a gesture to enforce a distance limit reached through another input method. In 2D, matching wires retain their SVG elements through re-layout and through every frame of a move: since 2026-10-16 the drawing keeps each wire's, lace's and bundle run's element by its key and writes its geometry in place from the measured page, where before it built the SVG anew each frame and reconciled it by key, which cost a frame 41 ms at 418 wires against 11.5 after ([the probe](../../AI-Agent-Workspace/Probes/2026-10-16/explorer-performance/README.md)). Entering wires fade with their endpoint cards, and frame redraws do not reset the layer's opacity. A perspective transition captures that current wire presence too.

After the initial ordering starts, the continuing search alternates ordering trials with proposed joins of neighboring flat boundary runs. Each join re-solves cards, wire slots and containing membranes under the same padding, separation and overlap constraints. A proposal wins only if its complete score improves; the browser measures it again before adoption. Search pauses during animated moves, and changing a weight starts a new search while preserving the displayed subject. Since 2026-10-16 the search also runs only while the Local Map is the view shown and the page visible: leaving the map for another view or another tab pauses it where it stands, and a return resumes it; a render asked for while another view is shown is owed until the map is shown again, so a return to an unchanged picture draws nothing (before, the search went on behind the other view and the return drew the picture again and began the search anew). ### The search bar

One search serves the whole Explorer (2026-10-14): a field at the top of every view, reached by Ctrl+P, in place of the earlier dialog and the FROM/TO toolbar. A few typed words find directories by their name, files by name, path and symbols, and the symbols themselves; the results are grouped the way the declared structure reads, directory, then file, then the file's matched symbols, five at a time with a fold that lists the rest. Choosing a row pins what it names: a directory is opened, a file retained with all its symbols, a symbol retained alone, in the Local Map, which opens if another view was showing. The chosen thing is the newest pin, and the field shows the newest pin as the person goes on pinning by clicking, so the field reads as "where a path would start". Once anything is pinned a map marker and a second field appear for the end of a path.

The second field offers only what a path from the newest pin can reach (the owner's ask the same evening, 2026-10-14): one breadth-first walk from the pin's files, forward along dependents, which the map draws, and in reverse along dependencies, which the reverse question offers. Each offered file says how far, "4 files" when the path would draw and "4 files, the other way" when only the reverse question would come; a directory offered by its name says what its nearest file says, one the map can draw to before one the other way; symbols sit under their file. The files the words match but no path connects are folded under a count, "3 more files match, but no path connects them", and open into faded rows marked "no path" that can still be asked, so that a typed name is never silently absent. When nothing connects to the pin, the field's placeholder says so. The walk is the engine's, the one under the CLI's searches, and `inspect --reachable` lists the same files with their hops.

### Pathfinding Rendering

The Local Map supports **path mode** once a destination is chosen in the search bar's second field: the path is asked at once, from the newest pin to what was chosen, a file, one symbol of a file, or a directory, in which case the search leaves from, or arrives at, any file inside it. The current implementation renders a single shortest path through the same optimized scene as a file neighborhood or retained exploration. Its files remain ordered from provider to consumer, inside their directory membranes, with compact rows for the path’s references. Pathfinding uses BFS with a single-parent map (`Map<string, string>`), so when multiple shortest paths exist, only one arbitrary path is returned. Since 2026-10-03 the default search depth is the graph's simple-path bound rather than an arbitrary ten hops, so the estate's thirteen-file route from an Oracle table to a Portal page is found; callers may still pass an explicit limit. A path's address is the pins and the destination in the compressed snapshot.

A path is drawn only in the direction the map reads. Inside a system what a file offers leaves on the right and what it uses enters on the left, so the start must offer and the end must use: the path is found by walking the start's dependents, and every wire leaves the earlier file's blue pin and enters the later file's green pin. When the two files connect only the other way (the start depends on the end), nothing is drawn: the status says no path runs that way and offers the reverse question as a link, which pins the destination, newest, and draws the way back. This is the owner's rule of 2025-12-18, "like a google search with an obvious typo, we should show no results and offer the reverse (via hyperlink)... rather than draw the crazy connectors which span their entire nodes, reaching backwards"; the drawing had run against it since, and the still-picture instrument measured every wire backward on 2026-10-01. A reference between two files of the path that runs against it (an earlier file depending on a later one) is not drawn either; the status counts them so that the picture says what it leaves out. Choosing a new subject in the bar while a destination stands asks the path again from it; an explicit retention action on the picture, such as pinning a symbol of a hop, leaves the path into exploration and forgets the destination; inspecting a hop preserves the path, and clearing the destination does the same, the pins kept.

Three historical proposals address this limitation; they remain open rather than authorized work in the October 2 pass (see `AI-Agent-Workspace/Notes/multi-path-visualization-design.md` for full specification with ASCII diagrams):

1. **All-Shortest-Paths Merged DAG** — Replace the single-parent BFS with a multi-parent variant (`Map<string, Set<string>>`) to reconstruct every shortest path. Where paths diverge, the hop column stacks multiple cards vertically. Connections fan out and converge across the DAG.

2. **Near-Miss (+1) Paths** — After finding shortest paths at depth _k_, continue BFS one additional level to collect paths of length _k_+1. These render with dashed borders, reduced opacity, and dashed connection lines. A toolbar toggle controls visibility (default off).

3. **Symbol-Divergent Paths Through Same File** — Port the CLI's symbol-aware BFS (`pathfind-symbol.ts`) to the Explorer client. When two shortest paths traverse the same file sequence via different symbols, multiple connection lines route through distinct symbol anchors on the same card. Each chain gets a unique color; hovering highlights the full chain end-to-end.

These proposals were originally described against the multi-hop rendering architecture in `AI-Agent-Workspace/Notes/multi-hop-local-map-architecture.md` (dynamic column count, hop-aware anchors, HopChain data model). The truncating exploration renderer was retired on October 2, 2026; explicit pathfinding remains, using one card and one anchor identity per file. Any implementation must be reconsidered against the current independent-branch model.

> **Note (2026-03-22)**: Multi-path pathfinding may be reimplemented on the [Membrane Map](membrane-map.mdmd.md) spatial substrate rather than the current column layout. The later October 12 correction uses the Local Map’s common directory-aware scene; it does not implement this separate historical proposal.
