# Live Documentation Explorer

_Current as of 2026-10-24. The remediation checklist below distinguishes completed repairs from accepted unfinished outcomes; other sections describe the shipped design unless explicitly dated as history._

## Metadata

- Layer: 3
- Archetype: component

## Authored

### Purpose

Describe the static Explorer that renders the canonical Live Doc graph and authored boards. The 2D Local Map combines the directory browsing and file/symbol detail developed in the former Membrane Map and Local Map. The 3D Local Map provides a spatial perspective on file connectivity and declared directory structure. The two representations share independent exploration pins and selected identity. Navigation has three views: Knowledge Sources, World Map and Local Map. The Local Map owns directory browsing and both 2D and 3D representations.

### Notes

- Created 2025-11-21 when `visualize-explorer.ts` was refactored into a modular `packages/explorer` structure with client and shared modules.
- The shared layer (`explorer/shared/`) builds the static bundle: the derived graph index from `packages/engine` plus the related markdown, with the HTML/CSS/JS assets. `graph.ts` there is the projection from the graph index to the node-and-link payload the views render; the client runs it on load (since 2026-09-28).
- The HTTP server (`explorer/server/`) was retired on 2026-03-09 in favour of static-only distribution. `graph.ts` and `buildAssets.ts` were relocated to `shared/`. The client paths that still fetched from it went on 2026-09-28.
- The client (`explorer/client/`) renders these views:
  - **Knowledge Sources**: the graph’s inventory, the entry points and what a walk from them reaches, related documentation and exports. Since 2026-10-15 the panel lists the entry points the docs declare, grouped by reason (programs, commands, modules, openings served, tooling inputs, declared files, tests) with a sample program's entries folded under its root, then what no entry reaches, by archetype, the files no reader handles yet apart as "Not read" (since 2026-10-22, [the decision](architectural-decisions.mdmd.md#every-file-gets-a-live-doc-but-the-kinds-never-documented-documents-are-linked-not-documented-recorded-2026-10-22)), and what only a test reaches, from the engine's one walk that `inspect --reachable` prints. A "Reachable from" field, the search bar's field over the whole bundle, walks from any file or directory instead (the owner's thought: "the system inferred one sits in an omnisearch textinput ready for the user to adjust"); the choice is exploration state in the share link, and beside it the line that would declare the file in `.live-docs.config.json` is offered to copy, since a static page cannot write the file. The landing follows the same lines: the one program, command, module or declared entry outside the sample roots is the first subject, several land on the root with nothing pinned, and the guess by file name remains only for docs that declare no entry at all ([the decision](architectural-decisions.mdmd.md#entry-points-are-written-on-the-entry-and-what-they-reach-is-one-walk-recorded-2026-10-15)).
  - **Local Map**: the file-scale view improved in place since 2026-10-02: one file with what it uses on the left and what uses it on the right, any number of files retained by their pins with every reference among them, their directories as bands behind the cards, paths asked through the search bar and drawn only in the map's direction, and explicit 2D/3D controls for changing perspective. See "Independent exploration" below.
  - The Local Map’s **3D representation**: force-directed file connectivity, one counted line per file pair over the canonical references, camera focus on a requested file that keeps the viewing direction, the same pins and selection as the Local Map, and the explicit return to it with the subject held in place.
  - **World Map** _(since 2026-09-28; the landing view when the bundle carries a board)_: the outside of everything. A board's things drawn by their kind, regions around what they hold, doors, wires with their basis and their evidence, declared crossings, and what things stand on, read from the board text the bundle carries and the graph, by the engine's `board.ts` and `boardGraph.ts` in the browser. `views/worldMap/` holds the camera, the geometry and the model as pure modules with tests, and one module that draws. The design is in [Boards](boards.mdmd.md) and the decisions log under "The World Map in the Explorer". A thing opens, by the wheel past half the view, a double-click or the link in its pinned panel, into the Local Map focused on its folder, in the remembered representation (2026-10-12). A hover peeks and a click pins; in a pinned panel every name is a link, a thing's name pinning it and a file opening in the Local Map, so that every claim a panel makes can be traced (2026-09-29). What a thing stands on is another thing's code built in, a dotted line on the board to that thing, and what its manifests name, the strands beneath it. Labels keep off each other: a thing's name stays put, its second line goes when it would cover another label, and a region's label, a crossing's tag and a token's label step up or down until clear, after every camera move; Playwright's design audit checks it, and the estate sample under `samples/estate/` with it.
- The [October 12 walkthrough](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-12.1.record.md#turn-4) consolidated the views. As the owner clarified on [October 23](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-23.1.record.md#turn-3), the former Membrane Map and Local Map merged into the **2D Local Map**; Membrane Map is a legacy name. The Circuit Board was retired. The [former Membrane Map design](membrane-map.mdmd.md) remains historical provenance, not a separate destination or a proposed successor.

### Independent exploration

The 2D/3D setting is independent of the active navigation view. Browser storage remembers it when leaving and returning; `view=local&mode=2d` or `mode=3d` shares it explicitly. Old `view=force` links open Local Map in 3D; `membrane` and `circuit` links open it in 2D. Compressed version 1 links migrate their selected file, pins and deepest opened directories. A path restores before first paint without overriding the chosen representation.

Direct file links, pinned branches and paths share the directory-aware layout from their first drawing. A file link discloses a neighborhood without storing implicit pins. A shared path is resolved before first paint, and clearing the destination restores the exploration and its camera. The [owner’s October 12 walkthrough](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-12.1.record.md#turn-3) exposed and retired the separate initial and path renderers. Scrolling zooms within the chosen perspective; the controls say 2D and 3D, with full names in their tooltips and no density suggestion.

The map subject, retained pins, inspected evidence and camera frame are separate. Clicking a file, symbol, directory or related document opens its evidence without changing the subject, pins, path or camera. Direct Pin controls retain a file or symbol in one action; Centre deliberately moves the map subject, and directory Open discloses its contents. These are the owner's [October 19 inspection and direct-Pin decisions](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-19.1.record.md#turn-24), completed in [the October 20 continuation](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-20.1.record.md#turn-2). More, right-click and a stationary hold offer contextual commands. Movement, multiple pointers, cancellation and Escape cancel a hold. Local Map double-click navigation is omitted; Centre and Open are explicit controls.

Pinning retains connections without removing other pins. The map displays the union of those neighborhoods and every relationship between retained files, beside the subject's neighborhood while the subject holds no pin of its own. A whole-file Pin retains all its symbols; a symbol Pin narrows a whole-file pin to that symbol; further symbols add; pressing an already pinned symbol releases it; releasing the file's last symbol leaves the file pinned whole. A file's Pin pressed again releases that file's pins and nothing else, so a Pin undoes itself; the card's close and the tray are what release a file under the subject policy. A pin never moves the subject. In 2D the acted-on symbol row or directory stays under the pointer through the resulting movement, and keyboard focus returns to its control. The subject moves by Centre, a search choice or its release policy. Taps, clicks and Enter activate the same visible controls; hover only previews, and 2D pan and pinch use pointer events. Cycles are broken at feedback references, drawn as laces with their route on hover; skipped ranks use reserved lanes between cards. Counts identify connections outside the disclosure, including those hidden by filters. Explicit pins and the selected file remain visible through filtering. Perspective controls preserve the selected identity’s screen position; manual camera gestures end automatic tracking.

In 3D, readable names are placed beside their spheres in priority order: subject, explicit pins and path endpoints, then retained directories/files and contextual neighbours. A name keeps its reading size; when it cannot fit without colliding with text, controls or an equally important sphere, it waits for more space. Duplicate basenames receive distinguishing path suffixes, and titles carry the full path and counts. Clicking a name inspects it through the same commands as its sphere. Structure names the directory hubs as well as files.

A first 3D arrival frames the requested file and its immediate neighbours, a selected directory and its members, or the unselected root. The camera accounts for sphere radii and keeps the viewing direction. **Fit current scope** recovers, in order, the current path, retained files/directories, the subject neighbourhood, or the whole scene. It changes neither pins nor the question. Automatic following stops on a manual camera gesture; clearing a later selection does not re-run the initial root fit.

Repeated spheres, projected wires and arrows share GPU instance buffers while their original objects preserve interaction identity. Node drawing, picking, name offsets and perspective snapshots use the same resistance-adjusted sizes. Wires use round-capped strokes with endpoint widths derived from camera depth; clipping and picking follow those visible strokes. Conservative culling includes their width, and unchanged camera and scene inputs retain the painted frame. Perspective snapshots stop at hidden subtrees while preserving computed styles of visible content. Potential energy remains available as a deferred diagnostic of the sampled positions.

The evidence reader overlays an unchanged canvas. At narrow or short viewport sizes it fills the viewport, makes the background inert and carries its own Back, Forward and Close controls. At wider sizes the map controls stay in the uncovered area. Links inside evidence inspect their target; file, symbol, directory and bundled-document fragments travel independently in the share link and remembered place. Back between evidence targets leaves the map DOM and camera intact. Old links without an inspection target open with the reader closed; stale evidence is discarded without replacing the map subject. Escape closes the reader unless something above it, the search field, a menu or the ancestry chooser, takes that Escape first, and the World Map behind the reader never acts on a key the reader used or one typed in the full-screen reader. Closing evidence returns focus to its opener, or to that opener rebuilt by a render, or else to the map itself, never to a text field. Internals remains a file-level endpoint with its own pin, without inventing private-symbol documentation.

The lower-right pin tray lists explicit directory, file and symbol selections newest first, in an order preserved by shared links. Its focus action brings an item into view without adding a pin. Releasing a directory removes only its own opening; independently opened descendants and file/symbol pins survive. The separate **Clear pins inside** action releases the directory and contained selections together, while outside pins can still require some of its files. Clear all includes directory openings and removes pin-driven focus. With no retained selections or selected file, 2D shows the scan root's immediate files and closed child directories without manufacturing a root pin; 3D restores normal visibility. The owner approved these distinctions in [the October 14 implementation request](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-11--pin-management-approved-ancestor-disclosure-and-directory-hubs).

Membrane names inspect their directory. Open (Close, once open) and More stand together at the label's right end, in a column of their own beside the name and count, as card actions stand in a card's corner, so the caption stays one text flow. A separate ancestry control unfolds ancestor choices at viewport text size, with a temporary enclosure around the currently drawn members on hover or keyboard focus. Choosing an ancestor opens its immediate contents. This provides access to the root while keeping single-child ancestor chains compressed in the main picture.

### Competing layout preferences

**Compact / Relaxed** is one packing preference for both representations, selected beside 2D/3D. Compact favors a smaller footprint; Relaxed spends space on clearance and regularity. Advanced controls under Tuning expose the values behind both profiles. Changed packing values read as Custom; coupling and symbol-size controls remain independent and survive preset switches. Settings persist locally, travel with shared links and can be exported as JSON. Older links without layout settings keep the viewer's preferences. The owner approved this grammar and its advanced controls in [the October 13 implementation request](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-6--shared-presets-and-advanced-tuning-approved-for-implementation).

The representation controls sit at the bottom center. Compact and Relaxed are named icon buttons with pressed states; the tuning button identifies a customized layout and opens the existing advanced controls. The pin tray occupies its own lower-right surface and coordinates with the Details drawer.

The 2D layout prices wire distance, crossings, picture height, ordering churn, membrane evenness, row alignment and boundary-step count together. Membrane Evenness prices the distance a boundary rises or falls; **Membrane Simplicity** prices each nonzero step, so several small changes can lose to fewer larger ones. Compact uses narrower column/card/directory gaps and a stronger height cost. Relaxed uses stronger shape preferences, with simplicity 200, evenness 2 and row levelness 2; Compact uses 100/1/0.25 respectively. Both value alignment, while Relaxed permits a greater wire-length tradeoff for composition, as the owner clarified in [the review](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-13.1.record.md#turn-8--relaxed-should-spend-wire-length-on-composition). These are preferences in a local competition, not guarantees that every individual signal improves in every scene.

In 3D, one line represents a file pair, with its documented reference count on hover. Imports and signature references count once each; multiple documented references sharing visible endpoints carry multiplicity, while the canonical graph retains all evidence. More coupling shortens the preferred surface gap logarithmically, bounded by size-aware collision clearance. Sphere volume grows from public-symbol count plus one baseline unit. Both presets retain the same coupling and size meaning: position suggests coupling, size suggests exposed interface, and the preset controls packing. These counts describe documented structure, not runtime call frequency or complexity. Related-document overlays use the same projection in the browser and command.

**Wire Thickness and Zoom Resistance** were selected through the [October 24 comparisons](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-24.1.record.md#turn-11). Code-reference width is the baseline times `min(3, 1 + 0.375 × log2(count))`, independent of current spring length; containment uses the baseline and citations half of it. Separate node and wire resistance sliders span ordinary perspective at 0, constant CSS-pixel sizing at 1 and softened perspective between. If projected scale doubles, apparent size changes by `2^(1-resistance)`. The defaults are **node resistance 0.45, wire resistance 0.9 and thickness 0.9**. These controls preserve physical positions and camera, persist and travel with shared/exported settings, and survive packing preset changes. Name disclosure still follows proximity, so invariant sizes do not reveal every distant name. Connections uses ordinary wire alpha 0.16 and faded alpha 0.025; names reserve 10 CSS pixels between rectangles.

The active Local Map legend follows its representation and the filtered graph at the historical moment shown. The 3D key names actual file archetype colours, public-symbol size and reference-count width, adding document/containment meanings when present. The 2D key retains its offer/use grammar; neither key appears in Knowledge Sources or the World Map. This repairs the legend mismatch, but dependency direction and projected-crossing ambiguity remain open under the remediation item above. The [Connections tuning pass](../../AI-Agent-Workspace/Probes/2026-10-24/connections-tuning/README.md) judges overview, neighbourhood and motion; Structure visual tuning remains deferred.

**Gravity and Repulsion Reach** are the 3D picture's restoring levers. Gravity pulls toward the origin in proportion to distance; the reach bounds the distance over which spheres repel. The shipped gravity is **0.025**, selected in the October 24 Connections pass, and the reach is unbounded. The owner's October 18 gravity 0.01 and the October 22 probe's proposed 0.05 remain dated comparison points, not current defaults. Settings persist and travel in share links.

**Spring Strength** scales the restoring pull of connected neighbours; the shipped value is **0.5**, selected with gravity 0.025 and tether 0.02 in the October 24 Connections pass. It sits with Gravity, Repulsion Reach and Repulsion under Tuning's 3D Layout group, and Export layout settings writes the numbers out. The conservative field pulls both ends of a spring equally; descriptions of D3's unequal degree-based division of motion are historical. The [October 22 probe](../../AI-Agent-Workspace/Probes/2026-10-22/3d-tuning/README.md) exposed a degree-dependent integration defect under strong springs; correcting its integration is separate from judging Structure's appearance.

**Update Energy** is the constant strength at which a membership change eases under the motion introduced on October 21; its default is **1**. One update path serves pins, filters, layout changes and history steps. It preserves node and link objects, places newcomers beside what they connect to, and moves the picture through its own conservative field with damping and no cooling. Zero requests placement alone. A lower positive energy approaches much the same rest more slowly; it is not a shorter cooling schedule or a promise of less total displacement. A first picture, a hand and a force change ease at full strength. The engine stops by measured motion, without a time ceiling. The previous alpha-share model and its 0.1 default are historical ([the decision](architectural-decisions.mdmd.md#the-3d-picture-eases-until-still-one-motion-through-a-conservative-field-tethered-to-where-it-stood-recorded-2026-10-21)); [C2 in the history plan](change-over-time.mdmd.md#open-questions) records the succession.

**Tether** (2026-10-21) is how strongly each sphere is held to where it stood when the picture last began to move: a change of what is shown and a hand are held from where the spheres stand, so that a change keeps a person's bearings; a first picture, a layout switched and a change of the forces unfold freely until they calm and are held there. Without it a large picture never came to rest, its loose files and islands travelling round the main mass and its branches swinging about their joints for thousands of ticks. The default is **0.02**, selected in the October 24 Connections pass; the original 0.01 and its measured settling times remain in the [October 21 record](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-21.1.record.md#turn-5). Its rest is not the forces' own, so a picture that moves again is let a little further toward that.

**Reveal** (2026-10-28) is how a 3D picture enters: in pieces. The first piece, the subject, the path, the pins and what they retain, and their nearest by the links that pull, up to 300 spheres, warms hidden by the library's hundred ticks as every first picture did; then a tenth more enter at every tick, ten at the least, each sphere placed beside what holds it as it enters, until every file is in, and only then does the picture come to rest. A membership change keeps what is shown and brings the newcomers the same way. The order is by distance from the attention set, nearest first, ties and the unreached by connections, so that what a person asked about is on screen first and the context grows around it; with nothing retained the picture grows from its most connected sphere. The owner chose the gradual reveal for 3D and not for the 2D Local Map, whose membership is bounded by the question ([Turn 2 of the October 28 record](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-28.1.record.md#turn-2)), and the growth is a fixed share with a floor so that the map always completes ([Turn 3](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-28.1.record.md#turn-3)); the frame rate is the pacing's to hold. The constants are the starting values of that day, to be measured in the layout lab and judged by eye ([the day's pictures](../../AI-Agent-Workspace/Screenshots/2026-10-28/README.md)); the headless easing and the lab's spatial report reveal the same way. `tests/e2e/force-graph-reveal.spec.ts` holds the sizes the picture passes through to the rule's.

**History** (2026-10-18) is the 3D Local Map's rendering of change over time, ticket C4 of [the plan](change-over-time.mdmd.md#open-questions): when the bundle carries a history (the sequence the history command computed, carried beside the data by the exporter's choice), a History button stands beside Connections and Structure, for now, until the consolidation pass the owner expects, and opens a scrubber along the bottom of the picture, fetching the sequence then and not before, so that a page without history is no slower. The scrubber draws one tick per step from a pure tick model (`history/tick-model.ts`): with nothing pinned every step is a major tick; with pins, the engine's `ticksFor` marks the steps that changed the shape of what is pinned as major and the steps in which the version control saw a pinned file's content change alone as minor (the owner's words, 2026-10-17: "the kind of quantum leap events are major ticks and the update-only changes are minor ticks"), followed through the pins' renames; the rest are faint and a drag passes through every one. The granularity (every step, days, weeks, months, the salient steps alone, or an automatic choice by the number of steps within a budget) and the axis (by date, the default since 2026-10-22, linear time in which a quiet half-year reads as a gap, the owner's preference in [Turn 10 of the October 21 record](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-21.1.record.md#turn-10); or evenly by step, which gives a busy stretch more room) are levers under Tuning's History group with the play rate, the view's half of the granularity seam (C14). The arrows move a step, Page Up and Page Down between the major ticks, Home and End to the ends; the date and the commit's subject are the slider's spoken value, the date and the hash its readout; a ruler of dates runs beneath the ticks. A move materializes the step from the sequence (a cursor that applies the deltas forward and seeks back from the nearest keyframe) and feeds the picture through the one update path: the renamed files and hubs keep their objects under their new ids, re-keyed before the draw, a born file is placed by the carry rule, and nothing is held in place. While the thumb drags each frame places the steps it crossed without a tick, coalesced to one per frame so that the thumb never lags (a median 9 ms of script a step at 1,099 spheres on 2026-10-18); at rest the picture is fed at the tuning's energy. Beside the picture a step panel says what the step changed, the subject, the hash, the date and, by a toggle beside the scrubber that rides the address, the author (C8), then the files born, dead, renamed and resized with their archetype and symbol count at the step, the directories renamed whole, the wires that came, went and changed their count, and the files whose content changed alone, each file a button that pins it where it still exists today and "gone since" where it does not. The address carries the commit, so a link to a moment opens on it, the sequence fetched before the first picture; a pin whose file does not stand at the moment is said "not yet born" in the tray and never dropped; the last step is today, where the picture is today's docs; leaving 3D for 2D or another view returns the picture to today and closes the control. A history cut at its beginning, a shallow clone or a window an export carries, gets a hatched band before its first tick and the panel says why; a bundle without history shows no control, and the Knowledge Sources panel says so in one line naming the command to copy. The pictures of the day are in [the history folder](../../AI-Agent-Workspace/Screenshots/2026-10-18/history/README.md); `tests/e2e/history-scrubber.spec.ts` holds it over the scripted sample. Since 2026-10-20 ([Turn 9](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-20.1.record.md#turn-9)) a moment draws, when Show Related Docs is on, the related documents its files' authored words linked to then, and a document today's bundle lacks says so in its label and opens nothing; the step panel lists the documents linked and unlinked, each a button that reads today's version where the bundle carries it; while a past moment is shown the reader says that it reads today's version, and the scrubber ends at the reader's edge, its ruler placed again at the narrower width.

**Connections or Structure** is the 3D Local Map's layout, a choice inside 3D shown beside its button and remembered like the perspective (2026-10-14). In the connections layout the documented references pull and are drawn: the emergent network of what the code does. In the structure layout every file and related document hangs from its directory's hub and every hub from its parent's, up to the scan root, by one containment link each: the emergent tree of what the file system declares; a hub holding nothing but one child collapses into it, as the 2D bands collapse such chains. Hubs are amber, and a hub's volume is the sum of its members' volumes, so that size means exposed surface at every scale. Only the links of the chosen layout are given to the spring force; the other kind stays in the data, pulls nothing and counts for nothing. Containment is drawn as the structure it is; a reference is drawn in the structure layout only on demand, for the hovered file, within and out of the hovered hub's subtree, among the retained files, and along a path. Switching layouts keeps every file where it stands and starts each new hub at the centroid of its members, so the simulation folds the network into the tree before the eye, and unfolds it on the way back. Directory hover reveals its members; clicking inspects it, Open retains its contents (Close, once open, as the 2D label offers), and Centre frames the hub with its members. The owner chose this separation after seeing hubs inside the connectivity layout ([Turns 3 and 4 of the October 14 record](../../AI-Agent-Workspace/ChatHistory/2026/10/2026-10-14.1.record.md#turn-3)). There are no 3D enclosing volumes.

**Cited By** (2026-10-22) is the other direction of a file's related documents. The documents a file's authored words cite have been the purple Related Docs since January; the documents whose own links name the file are now its doc's `Cited By` section, which the generator writes and the bundle reads back ([the decision](architectural-decisions.mdmd.md#related-documents-run-both-ways-a-docs-cited-by-section-is-generated-from-the-documents-own-links-recorded-2026-10-22)). In the 3D Local Map the two kinds have filters of their own, Show Related Docs and Show Citing Docs, both off by default; a citation is drawn as a thin violet line from the one who cites to the one cited, with an arrow at the cited end, a citing document's line lighter than a cited document's; and a citing document's spring pulls by Tuning's Citing Pull, a share of a documented reference's, one by default and zero to draw the line without pull, since the owner asked to see the pull before deciding on it. The reader lists a file's citing documents under Cited By, each a link that opens the document where the bundle carries it. A moment of the history draws what the files cited then; the documents that cited them are not in the sequence yet.

Hover in 3D temporarily reveals the hovered file's incident connections, including a file outside the retained scope. Leaving restores the current pins, directories or path. One application pick of the rendered spheres decides hover, click and hold alike, so a fast entry, a camera move under a still pointer or a lifted finger cannot leave a stale preview behind; the graph library's own hover callback, which reports only changes between objects, no longer decides it. A control the mouse pressed may keep keyboard focus without keeping its file's preview, while keyboard focus on a sphere's actions, or an open menu, keeps it. Wheel zoom preserves the inspected point's projection and never reverses a gesture to enforce a distance limit reached through another input method. In 2D, matching wires retain their SVG elements through re-layout and through every frame of a move: since 2026-10-16 the drawing keeps each wire's, lace's and bundle run's element by its key and writes its geometry in place from the measured page, where before it built the SVG anew each frame and reconciled it by key, which cost a frame 41 ms at 418 wires against 11.5 after ([the probe](../../AI-Agent-Workspace/Probes/2026-10-16/explorer-performance/README.md)). Entering wires fade with their endpoint cards, and frame redraws do not reset the layer's opacity. A perspective transition captures that current wire presence too.

After the initial ordering starts, the continuing search alternates ordering trials with proposed joins of neighboring flat boundary runs. Each join re-solves cards, wire slots and containing membranes under the same padding, separation and overlap constraints. A proposal wins only if its complete score improves; the browser measures it again before adoption. Search pauses during animated moves, and changing a weight starts a new search while preserving the displayed subject. Since 2026-10-16 the search also runs only while the Local Map is the view shown and the page visible: leaving the map for another view or another tab pauses it where it stands, and a return resumes it; a render asked for while another view is shown is owed until the map is shown again, so a return to an unchanged picture draws nothing (before, the search went on behind the other view and the return drew the picture again and began the search anew). This is deterministic local search, not a global optimum claim for step count. A zero simplicity weight disables alignment proposals; disabling continuing search or forcing one ordering seed disables all continuing trials.

The layout lab's `refine` command runs the same competition from captured card measurements and exports initial/final geometry and every trial. The measurement cache preserves the renderer's resolved endpoint identity, including duplicate symbols and file/asset hubs, so pricing cannot improve by omitting a visible connection. The [browser regression](../layer-4/tests/e2e/local-map-simplicity.spec.ts.mdmd.md) compares final browser and headless geometry exactly on the estate and warehouse.

It supports test, asset and related-documentation filters and `--layout connections|structure`; its report says of every link whether it pulls in that layout, and containment carries no documented-reference count. `refine`, `verify` and `spatial` accept the page's exported settings through `--config @file`. ### The search bar

One search serves the whole Explorer (2026-10-14): a field at the top of every view, reached by Ctrl+P, in place of the earlier dialog and the FROM/TO toolbar. A few typed words find directories by their name, files by name, path and symbols, and the symbols themselves; the results are grouped the way the declared structure reads, directory, then file, then the file's matched symbols, five at a time with a fold that lists the rest. Choosing a row pins what it names: a directory is opened, a file retained with all its symbols, a symbol retained alone, in the Local Map, which opens if another view was showing. The chosen thing is the newest pin, and the field shows the newest pin as the person uses the separate Pin actions, so the field reads as "where a path would start". Once anything is pinned a map marker and a second field appear for the end of a path.

The second field offers only what a path from the newest pin can reach (the owner's ask the same evening, 2026-10-14): one breadth-first walk from the pin's files, forward along dependents, which the map draws, and in reverse along dependencies, which the reverse question offers. Each offered file says how far, "4 files" when the path would draw and "4 files, the other way" when only the reverse question would come; a directory offered by its name says what its nearest file says, one the map can draw to before one the other way; symbols sit under their file. The files the words match but no path connects are folded under a count, "3 more files match, but no path connects them", and open into faded rows marked "no path" that can still be asked, so that a typed name is never silently absent. When nothing connects to the pin, the field's placeholder says so. The walk is the engine's, the one under the CLI's searches, and `inspect --reachable` lists the same files with their hops.

### What the page may reach

The page reads only its own site (2026-10-21, [the decision](architectural-decisions.mdmd.md#the-explorer-reads-only-its-own-site-held-by-its-policy-and-a-browser-test-recorded-2026-10-21)). Its Content-Security-Policy admits its own script, styles, images and fonts and its own site for data. The reader shows a doc's raw HTML as text and an image as a link to it; `?data=` and the history file must be on the page's site. A control in the template is wired by a listener, never by an `on…` attribute, and a test that puts script into the page serves it as a file of the page's site. [The no-network spec](../layer-4/tests/e2e/no-network.spec.ts.mdmd.md) fails on any request to another site and on any refusal by the policy.

### Pathfinding Rendering

The Local Map supports **path mode** once a destination is chosen in the search bar's second field: the path is asked at once, from the newest pin to what was chosen, a file, one symbol of a file, or a directory, in which case the search leaves from, or arrives at, any file inside it. In 2D the current implementation renders a single shortest path through the same optimized scene as a file neighborhood or retained exploration. Its files remain ordered from provider to consumer, inside their directory membranes, with compact rows for the path’s references. Both representations share a readable report above the map: success names the ordered hops, reverse-only results offer the reverse question, and disconnected results explain the absence. Each hop is a keyboard-accessible inspection button, with its full file path in its accessible name and hover title. Long routes scroll horizontally; long names wrap without shrinking. The report is bounded in height so the map retains space. Every newly asked outcome opens Local Map; ordinary navigation away hides the report while keeping the question for a return. Clear removes the path, keeps the pins and, when activated by keyboard, returns focus to the destination field. Pathfinding uses BFS with a single-parent map (`Map<string, string>`), so when multiple shortest paths exist, only one arbitrary path is returned. Since 2026-10-03 the default search depth is the graph's simple-path bound rather than an arbitrary ten hops, so the estate's thirteen-file route from an Oracle table to a Portal page is found; callers may still pass an explicit limit. A path's address is the pins and the destination in the compressed snapshot.

A path is drawn only in the direction the map reads. In the 2D drawing what a file offers leaves on the right and what it uses enters on the left, so the start must offer and the end must use: the path is found by walking the start's dependents, and every wire leaves the earlier file's blue pin and enters the later file's green pin. When the two files connect only the other way (the start depends on the end), nothing is drawn: the status says no path runs that way and offers the reverse question as a link, which pins the destination, newest, and draws the way back. This is the owner's rule of 2025-12-18, "like a google search with an obvious typo, we should show no results and offer the reverse (via hyperlink)... rather than draw the crazy connectors which span their entire nodes, reaching backwards"; the drawing had run against it since, and the still-picture instrument measured every wire backward on 2026-10-01. In 2D, a reference between two files of the path that runs against it (an earlier file depending on a later one) is not drawn either; the shared status counts these references and explicitly names their omission in 2D. The 3D drawing remains a file-pair picture, not a symbol-level route. Choosing a new subject in the bar while a destination stands asks the path again from it; an explicit retention action on the picture, such as pinning a symbol of a hop, leaves the path into exploration and forgets the destination; inspecting a hop preserves the path; clearing the destination returns to exploration with the pins kept.

Alternative shortest routes, near-miss paths and distinct symbol chains were explored in the [historical multi-path proposal](../../AI-Agent-Workspace/Notes/multi-path-visualization-design.md). None is selected for this remediation. Its old renderer-specific prescriptions remain there as provenance; the current 2D Local Map uses one directory-aware scene for paths, file neighbourhoods and retained exploration. Making today's path result usable in both representations does not depend on adopting that proposal.
