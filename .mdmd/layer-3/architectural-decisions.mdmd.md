## Authored

### Purpose

Record the key architectural decisions made during Live Documentation development in an ADR-light (Decision / Rationale / Alternatives Considered) format so future contributors and context windows can understand **why** the system is shaped the way it is, not just what it does.

### Notes

- Decisions are listed chronologically by when they became relevant.

## Decisions

### Diagnostic Architecture _(Superseded 2026-02-18)_

- **Original decision**: A Node.js language server, coordinated by a thin VS Code extension, owning graph construction and lint diagnostics.
- **What happened**: The diagnostics subsystem was removed on 2026-02-18 (see the audit trail below). The server shell was removed on 2026-09-27 and the generator moved to `packages/generator`; the extension is being rescoped (see "Explorer Panel in the Editor").

### Symbol Ingestion Strategy _(Superseded; see "Link Sources")_

- **Original decision**: Prefer VS Code's built-in `execute*Provider` commands and language-server diagnostics before falling back to custom parsing.
- **What happened**: With the diagnostics subsystem gone, all relationships come from source analysis in the CLI; the editor is a host for the result, not a source of it.

### Workspace Indexing & Change Detection _(Superseded; see "Explorer Panel in the Editor")_

- **Original observation**: VS Code delivers incremental file events, so an LSP needs no bespoke polling.
- **What happened**: The constraint that survives is about cost, not plumbing: a file watcher may notify and debounce, but must never trigger a cold CLI regeneration on every save.

### Link Establishment Strategy

- **Decision (updated)**: Treat link relationships as an indexable projection rather than user-authored metadata. Default to auto-inferred links derived from language/intelligence providers (definitions, references, diagnostics) and optional external knowledge graphs. Allow explicit overrides via lightweight manifests only when inference fails.
- **Rationale**: Mirrors VS Code's workspace indexing philosophy — indexes are cached artifacts regenerable on demand, avoiding brittle front matter. Aligns with user preference to "ride" official tooling.
- **Alternatives Considered**: Mandatory front matter or CLI registration (rejected: high friction, hard to keep in sync); heuristic-only without override capability (rejected: lacks control for edge cases).

### Graph Rebuild & Freshness _(Updated 2026-09-28)_

- **Decision**: Live Docs themselves serve as the canonical graph representation. Dependency relationships are encoded as markdown links and queried via `live-docs:inspect --from/--to`. No separate SQLite cache or external feeds are needed. Since 2026-09-28 the graph is derived from the docs into one index (below), which is never committed and never a cache: every reader derives it afresh.
- **Rationale**: "Live Docs ARE the database" — eliminates cache invalidation complexity.

### Link Sources _(Updated 2026-09-27)_

- **Decision**: Relationships come from deterministic source analysis only. TypeScript and JavaScript use the compiler API. C# uses tree-sitter (since 2026-09-27): each file's syntax tree yields its declarations and every name it uses, and names are resolved against a workspace-wide table of qualified type names the way the compiler resolves them (enclosing types, enclosing namespaces from the inside out, `using` directives and aliases), including members a partial class declares in a peer file. Python uses tree-sitter too (since 2026-09-27): a module's symbols are its classes, functions, assignments and class members, and imports resolve the way the interpreter resolves them, with a `from` import followed through a package's re-exports to the file that defines the name, an aliased module import followed through the attributes used on it, and imports inside functions or under `TYPE_CHECKING` counted like any other. Java uses tree-sitter as well (since 2026-09-27): every type name a file uses is resolved as javac resolves it (nested types, the same file, single-type imports, the same package, on-demand imports) against a workspace table built from `package` declarations. Go uses tree-sitter as well (since 2026-09-27): a file uses the declarations of the other files of its package without qualification, `pkg.Name` resolves through the nearest `go.mod` to the file that declares `Name`, and a name declared inside the function shadows both. Rust uses tree-sitter as well (since 2026-09-27): each Cargo crate root owns the module tree its `mod` declarations reach, and a path is resolved through that tree as rustc resolves it, `use` re-exports followed to the item they name. The other languages still use hand-written scanners; tree-sitter replaces them next.
- **Rationale**: Deterministic, offline, no external runtime.
- **Descoped**: LLM inference via Ollama or `vscode.lm` (removed 2026-02-17: dormant, zero production callers; users bring their own assistants). VS Code's workspace symbol index as a second source (gone with the diagnostics subsystem).
- **Observation**: each language's code is split across `languages/{lang}.ts` and `live-docs/adapters/{lang}.ts` (a third directory, the benchmark-only heuristics, was removed on 2026-09-27). An abandoned January 2026 note proposed one folder per language; whether to do that is decided with the tree-sitter work, not here.

### Accuracy Measurement _(Updated 2026-09-27)_

- **Approach** (as stated in the vision): measure the shipped analyzers against oracles that share no mechanism with them: a compiler's own resolution (SCIP indexes), what actually breaks when a symbol is removed, and small hand-verified fixtures for dynamic patterns. Cross-language parity over the Rosetta fixtures guards against regressions in any one adapter. The details are undesigned.
- **Ground truth is never filtered**: whatever produces the expectations, its output is not trimmed to fit the analyzer. (In the January 2026 benchmark that meant the union of SCIP and tree-sitter output.) Adapter blocklists may remove only true framework or builtin names. A filter that can only raise false negatives is a bug. The roles stay separate: adapters are the product, oracles are the ground truth, and nothing grades itself.
- **Where this stands (2026-09-27)**: the oracle exists under `scripts/oracle/`. `oracle:index` runs the SCIP indexer a fixture's project file selects (`scip-dotnet`, `scip-go`, `rust-analyzer`, `scip-java`, `scip-typescript`, `scip-python`) over a temporary copy and writes every compiler-resolved file-to-file edge, with the symbols that carry it and every document the index held, to the fixture's `expected/compiler-edges.json`. `oracle:compare` runs the shipped generator over the fixture and prints the disagreements as a list, never a score. Every sample program whose language has an indexer carries expectations, 17 of 21; C and Ruby have none installed. Among them `csharp/estate`, the owner's payment chain in miniature (WebForms and Web API 2 portal, Web API 2 gateway, WCF hub, WCF service on Entity Framework 6, SQL Server procedure, Oracle linked server), also carries hand-verified edges for the hops no compiler sees. First measurement, of the regex adapter this replaced: 0 of 37 compiler edges on the estate and 0 of 2 on WebForms, because it recorded `using` namespaces as text and never resolved a type to the file that defines it; 3 of 20 hand-verified hops (markup to code-behind, markup to script, script to markup). The tree-sitter C# adapter, landed later the same day, matches 37 of 37 and 2 of 2 compiler edges with nothing extra, and finds 8 of the 20 hand-verified hops. The 12 still missing are hops the adapter does not attempt: HTTP routes between deployments, endpoint addresses matched across configuration files, endpoint names computed at runtime, a connection-string name built in `base("name=" + …)`, and everything inside SQL, which has no adapter. `oracle:compare` is the record; rerun it after touching an adapter. Two facts about the oracle itself are recorded in the converter: `scip-dotnet` names a type by its innermost namespace only, so a portal and a gateway that both declare `Controllers.PaymentsController` collide, and the converter resolves collisions by project visibility (a file sees its own project and the projects it references, transitively) and lists whatever stays ambiguous; and `scip-dotnet` misreports its own version inside the index, so the CLI's version is recorded instead. A third, of `scip-go`: it indexes the test binaries it generates in the build cache, so the converter lists documents from outside the fixture under `outside` and gives them no edges. A fourth, of `rust-analyzer`: it names every crate root of a Cargo package `crate/`, so the library, the binary and each integration test define one symbol; the converter reads the crates from Cargo's conventional layout (the library owns every other file under `src/`) and narrows a `crate::` reference to the referencing file's own crate root, since that is what `crate` means.
- **Baseline of the other scanners (2026-09-27)**: measured the day the oracle reached their languages. TypeScript, which uses the compiler API, matches 24 of 24 edges over its three programs. The hand-written Python and Java scanners match 21 of 21 and 43 of 43: on programs this small, a line scanner over `import` statements finds every file-to-file edge. Go matches 12 of 13; the missing edge is `pipeline_test.go -> main.go`, carried by the package symbol alone, because scip-go attributes a package's definition to one of its files and every other file's `package` clause references it, and the test file uses nothing `main.go` declares. Rust matches 28 of 33; all five missing edges are `crate/`, a `use crate::…` path being a reference to the crate root, which the scanner does not resolve, and the scanner also emits specifiers cut mid-brace (`models::{create_record,`). The file-level score cannot tell a line scanner from a parser on these programs. What the tree-sitter move buys is symbol-level links, honest symbol lists, and resistance to the shapes real code takes: multi-line imports, nested declarations, names inside strings and comments. Each language gets a program that exercises those before its adapter is rewritten, as the estate did for C#.
- **Python (2026-09-27)**: `python/ledger` was written to defeat a line scanner: barrel re-exports, relative and multi-line imports, aliased module imports, imports inside functions and under `TYPE_CHECKING`, a wildcard import, and import text inside a docstring and a comment. The scanner found 7 of its 25 compiler edges, with 1 extra. The tree-sitter adapter finds 24 of 25 with 1 extra, and 2 of 2, 7 of 7 and 12 of 12 on the other three Python programs. The missing edge needs type inference: `cli.py` calls `account.balance()` on an object a repository lookup returned, which only a checker that knows the return type can attribute to `account.py`. The extra is `account.py -> util/__init__.py` from `from ..util import money`: the adapter counts the package named in a relative import as a dependency, as it does for an absolute one, while scip-python emits no occurrence for a relative module name.
- **Java (2026-09-27)**: `java/warehouse` was written in the Maven layout with the shapes the scanner got wrong: the same package split across `src/main/java` and `src/test/java`, on-demand and static imports, a fully qualified name with no import, nested types named through their outer type, an annotation type of the workspace, two top-level types in one file, and class names inside strings and comments. The scanner found 16 of its 33 compiler edges, with 1 extra from a `@see` inside a Javadoc comment. The tree-sitter adapter finds 33 of 33 with nothing extra, and every edge of the other three Java programs.
- **Go (2026-09-27)**: `go/depot` is a module with a domain path whose packages spread over files that use each other's declarations, with an internal and an external test package, an aliased import, a directory whose package name differs from its name, a dot import, a blank import of a package with an `init`, a struct embedding a type from another package, a generic constraint from another package, a local variable that shadows a sibling file's function, and names inside strings and comments. The scanner found 20 of its 37 compiler edges. The tree-sitter adapter finds 30 with nothing extra. Six of the seven still missing are the package-symbol artifact: scip-go attributes a package's definition to its alphabetically first file, so every other file of the package, and every importer, references that file even when it uses nothing in it (`format.go -> count.go`, `quantity.go -> item.go`, `inventory.go -> base.go` and their like). The seventh needs type inference: `main.go` calls `Listen` on a `*Memory`, a method promoted from the embedded `store.Base`, which only a checker that knows the receiver's type can attribute to `base.go`. On `go/rosetta` the adapter finds 12 of 13; the missing one is the same artifact.
- **Rust (2026-09-27)**: `rust/stockroom` is a package with a library and a binary, a module file with a submodule directory and a `mod.rs` directory, `pub use` re-exports, `crate::`, `super::` and bare child-module paths, a glob import, a trait implemented for a type of another module, a generic bounded by another module's trait, an inline `#[cfg(test)]` module, an integration test crate, and names inside strings and comments. The scanner found 10 of its 44 compiler edges as first indexed; 8 of those 44 were the wrong crate roots that the crate rule above removes, leaving 36. The tree-sitter adapter finds 34 of 36 with 2 extra, and every edge of the other three Rust programs. Missing: `report.rs -> item.rs` through `item.describe(...)`, a method call on a value whose type only inference knows; and `quantity.rs -> lib.rs` through `crate/`, which comes from the expansion of `format!` (the adapter reads a macro invocation's tokens, not its expansion). Extra: `main.rs -> lib.rs` and `tests/report.rs -> lib.rs`, because a path that starts with the package name names the library's root module and the adapter counts every module a path names, while rust-analyzer emits no occurrence for that segment.
- **History**: the AST accuracy benchmark was retired on 2026-09-27. It scored a benchmark-only inference path rather than the shipped adapters, its ground truth was the union of SCIP output and that same tree-sitter path, and its per-fixture thresholds had been lowered as far as 15% precision and 5% recall until it passed. `live-docs:report`, which compared the analyzer to a re-run of itself, went the same day. The earlier self-similarity mode was removed in early 2026. Note that Rosetta parity counts a C# edge as present when a namespace name appears in the Dependencies text, which is weaker than the resolved link the graph needs; the oracle measures the link.
- **Candidate scenarios from the earlier product** (dictated by the owner on 2025-10-21 for the diagnostics tool and lost when the ripple suites were removed; kept as candidates, not commitments): a negative case where JavaScript reuses the variable name `data` in increasingly local scopes and nothing should be reported; `web.config` XSLT transforms from .NET Framework WebForms, to see how metaprogramming is handled; and a rename or move of a source file. Whether each still matters is decided when the benchmark is rebuilt.

### Edge Storage _(Recorded 2026-09-27; in effect since 2026-01-12)_

- **Decision**: Each edge is stored once, on the source file's Live Doc, in its `Dependencies` section. Inbound relationships are derived by the graph loader and never written.
- **Rationale**: Tests and other high-fan-in files would otherwise bloat every doc they touch; one direction keeps the mirror deterministic and regeneration cheap.
- **What an edge carries** is decided under "The Live Doc Grammar" below. A January 2026 design that was never built sketched one shape for evidence and tiers (kind, provenance, source location, unresolved targets kept rather than dropped, disagreements surfaced rather than merged); it stays recorded as prior art.

### The Live Doc Grammar _(Recorded 2026-09-27)_

- **Decision**: one module, `document.ts`, defines what a Live Doc is: a model of everything the file says, a renderer that writes it, and a parser that reads it back and refuses anything else. The two are inverses. Parsing a rendered model gives the model back, and rendering a parsed doc gives the text back; the round-trip suite proves the second on every committed doc and on everything the generator writes for the sample programs. Every consumer reads docs through this parser: the generator, lint, the graph behind the Explorer and `inspect`, and the oracle. Nothing else pattern-matches markdown.
- **Rationale**: "markdown is a lightweight AST" was a slogan until it was a property with a test. The old parser recovered a fraction of what the renderer wrote, so each consumer grew regexes of its own, and nothing could say whether a doc was well formed. With a grammar, the derived index is a serialization of the parsed model and cannot disagree with the docs.
- **What an edge carries**: a dependency line names its target, a doc and, when known, a symbol anchor, and ends with a parenthesised list of qualifiers, today `re-export` and `type-only`. Every edge within a folder is observed from source, so no evidence word is written until an edge of another kind exists; when configuration-observed or declared edges arrive they take a qualifier, and the parser already reads any. Source locations are not written on dependency lines: the symbol headings already carry line numbers, and a second set would move every doc on every edit for nothing a picture needs.
- **What strictness found**: the `inspect` integration suite had run over twenty-four Live Docs written by hand in November 2025 and committed inside its fixture workspaces, with invented anchors in an appendix after the generated regions. The parser refused them. The suite now generates each fixture's docs into a temporary copy and inspects those, and every path it expects is one the shipped generator finds; the hand-written docs are gone. Doing so exposed that the PowerShell adapter looked for its parser script inside the workspace being documented, fixed the same day.
- **Format**: the grammar first reproduced every committed doc byte for byte, proving it described what the generator had always written. Two lines then went, because nothing read them: `Live Doc ID`, an identifier scheme derivable from the path and the archetype, and the provenance comment, whose timestamp duplicated `Generated At` and whose input hash no consumer checked. A doc's metadata is now its layer, its archetype, its code path and when its generated sections last changed.

### The Derived Graph Index _(Recorded 2026-09-28)_

- **Decision**: one module, `graph.ts`, derives the graph from parsed docs, and every consumer reads that shape. A file of the graph is its parsed doc, exactly as the grammar returns it, plus what only the corpus can say: for every dependency line and every linked type reference, an edge naming the file the link lands on and the symbol it names; and the inbound and outbound adjacency, which no doc stores. The generator writes the graph to `<root>/index.json` after every run, pretty-printed for readers outside this code base, and the file is gitignored: "So would you make the 'index' gitignored by default...? Yep! Hot diggity!"
- **Rationale**: the markdown stays the one representation; the index is that representation with its links resolved. It is not a cache. Parsing every doc of this repository takes about 15 ms, reading them from disk about 300 ms when read in parallel, so a consumer derives the graph fresh rather than checking a file for staleness, and the owner's "one multipurpose representation, not a document shape and a separate render shape" holds without a freshness protocol.
- **Who reads it**: `inspect` and its pathfinding, which now follow edges by symbol slug at both ends; `live-docs:lint`, which derives the graph from the docs it has just validated and skips the connectivity check when any doc fails the grammar rather than crashing on it; `oracle:compare`, which counts the dependency-line edges; the static Explorer builder, which puts the graph in `explorer-data.json` in place of a separate node-and-link payload plus a copy of every doc's markdown; and the Explorer client, which projects the graph into the payload its views were written against and renders a doc back to markdown for the detail panel and the downloads. The client's regex split of a doc, the last reader outside the grammar, went with this.
- **What went with it**: the earlier in-memory graph builder in `packages/scripts`; the bundle's symbol index, whose symbol kinds were guessed from name casing; the bundle's provenance stamp, whose analyzer versions were a hard-coded string; the precomputed Local Map JSON files (`--local-maps`), which nothing read; the viewer configuration hint, which nothing wrote; and every client path that fetched from the HTTP server retired on 2026-03-10. The bundle for this repository shrank from 4.4 MB to 2.6 MB.
- **Edge shape**: `kind` is `import` or `re-export` for a dependency line and `returns`, `parameter`, `extends`, `implements` or `constraint` for a type reference; `to` and `toSymbol` name the resolved target and its anchor; `from` names the referencing symbol's anchor; `link` keeps what was written, so an external module (no link) and a link nothing answers to (link, no target) are told apart. A type reference to a symbol of the same file resolves to the file itself; the adjacency lists exclude such self edges.

### Package Names _(Recorded 2026-09-28)_

- **Decision**: `packages/shared` became `packages/engine`, the word the vision uses for what it holds: configuration, the language adapters, the analysis of a source file, the grammar of a Live Doc, and the graph derived from the docs. The markdown-audit library that lived under its `tooling/` folder (SlopCop's link, asset and symbol checks, and the documentation-link enforcer) moved beside the scripts that are its only callers, under `scripts/slopcop/` and `scripts/doc-tools/`, as the oracle's converter already did; `tooling/` keeps the path and slug helpers the engine itself uses. An unused `uri/` module went. `packages/scripts` became `packages/explorer`, holding only the Explorer: the static bundle builder under `shared/` and the browser client under `client/`, no longer nested under a `live-docs/explorer/` folder inside the package. The `inspect` modules that lived beside them split by what they are: the breadth-first searches over the graph, by file and by symbol, are engine code (`live-docs/pathfind.ts`, pure, so the Explorer can use them next); what the CLI accepts and prints sits beside the CLI under `scripts/live-docs/inspect/`. Entries above this one name the old paths as they were.
- **Rationale**: the owner deferred both renames until the index step "decides where things live" (2026-09-27). With the index in the engine and every consumer reading it, the boundary is clear: the engine is everything that turns source into docs and docs into a graph, and nothing that only audits this repository's markdown.

### Type References Resolve Home First _(Recorded 2026-09-28)_

- **Decision**: a type name used in a file links to that file's own declaration when it has one, whatever other files declare under the same name. A name the file only re-exports links to the file that declares it, among files of the same language: a declaration before a barrel that re-exports it, then the nearest file. A name never resolves into a file of another language.
- **What was wrong**: the resolver preferred any other file over the file itself, a stand-in for "origin over barrel" that was right only when the file being rendered was the barrel. `connection-geometry.ts` linked the `PathResult` it declares to the unrelated `PathResult` in `localView/state.ts`; `syntax.ts` linked the `LanguageSyntax` it declares to the barrel that re-exports it; and because the workspace symbol index is keyed by bare name, a Go `Quantity` linked to a Java `Quantity` and a Rust `Record` to a Java one. In this repository's own graph 45 type-reference edges pointed away from a declaration in the same file and 18 crossed languages; after the fix, 0 cross languages and the 12 that still leave their file are barrels linking to the origin and a Java field named like a type. The TypeScript extractor now marks a symbol an `export` declaration merely re-exports, so the index can tell a declaration from a re-export.
- **How it was found**: by looking. The Local Map for `connection-geometry.ts` drew a wire from `state.ts` into `computeBezierPath` that no code justifies. It was the first thing the Explorer caught over the graph index, as the vision asks of this repository, and the oracle could not have caught it: `oracle:compare` measures dependency-line edges, and type references are not measured by anything yet.
- **What remains**: dependencies are resolved by each language's own rules, but type references are still resolved by bare name from a workspace-wide index, so two C# projects that both declare `PaymentsController` will still collide. Having each adapter resolve type references the way it resolves imports is the next step for their accuracy, together with an oracle that measures them.
- **Found alongside**: the generator copied `@example` code into docs verbatim, carriage returns included, so a source file that still has CRLF line endings in the working copy produced a doc with CRLF inside its example blocks, which git normalized on commit and nobody saw. Example code is normalized now. 95 source files in the owner's working copy still carry CRLF from before the 2026-09-27 normalization; git normalizes them on commit, and rewriting them is a bulk checkout this repository's rules leave to the owner.

### Three Probes in Depth _(Recorded 2026-09-28; findings, not decisions)_

- **What ran**: three disposable three.js pages over the real graph index, built in parallel from one brief on 2026-09-28: the Local Map's cards with depth (file scale), directories as translucent volumes (folder scale), and the payment-chain fixture as systems on a canvas with three tiers of wire (system and zone scale). The record, with each builder's findings and nine screenshots, is `AI-Agent-Workspace/Probes/2026-09-28/`. The pages are not committed.
- **What depth bought**: at file scale, the corset lace drawn for real behind the card and a hub of 38 neighbours on one screen ordered by coupling; at folder scale, a corridor for cross-folder wires that pierce the wall at pins, and a transition that keeps landmarks and font size; at system scale, little beyond zones as volumes. Free orbit breaks the left-to-right law within 30 degrees at file scale and within one perspective at system scale; recession from a resting camera does not.
- **What every builder converged on**: text never resizes across a transition; the wall pin is the junction shared by adjacent scales; landmarks stay, dimmed; the next scale's summary at the edge is the pull; a wire that would cross a card or run backwards dips behind it, the corset principle at every scale.
- **What the docs cannot carry**, the growth list, grouped in the record by what it takes: generator gaps the extractor already knows (a barrel's re-export rows, their kinds, barrel versus origin), new facts (the consuming symbol of an import, calls inside a file, a folder as a thing, a home for externals, packages and versions, routes at both ends, endpoint addresses, connection-string and procedure and table names, a tier and evidence on every edge), adapters that do not exist (SQL, project and solution files), and what a person declares (zones, the tunnel, provenance).
- **Doctrine it touched**: on this repository 80 of 95 wires into `packages/engine/src/live-docs/` bypass its barrel, so "barrel equals membrane boundary" is not what the data shows; one wall pin per neighbouring folder with a count reads where the reverted hover arcs did not; and the law applied unchanged to systems reads Oracle to Portal, provision left to right, which the builder and the agent judged truer than call order.
- **Rounds 2 to 4, the same day**: the owner called the round-1 screenshots "pretty mid" and set the rule "2D inside the black box of a software system, and 3D outside of one". The file and folder probes stopped; the estate page went four more rounds, a second page two, each round judged by a critic against a rubric of the owner's words. The interior became a real HTML panel in the Local Map's card design placed in the scene by CSS3D, so text is crisp and never resizes; the world gained a floor, light, two zone slabs, a tunnel as a tube, cruft with counts and guts visible through the faces; the wall pin held as the junction between the world and the panel. The record carries both pages' final shots and ten forks in all; the four added by these rounds are what a click on a card does (re-layout, or nothing moves), the composition of the canvas (a row, or zones stacked in depth), what a wire does when it would cross a card (corset stubs, or a pass behind the card), and which page to carry forward.
- **The board, the same afternoon**: the owner rejected both estate pages ("I did not love those at all") and reset the frame: nothing inside a box shows until a seamless transition to a new view; no left-to-right law at the outer scale, since the third dimension exists because ordinal space is insufficient; "3D seems good when your universe is big and your nodes and connections are many. 2D seems good when you're trying to work with UI elements"; faked, isometric depth; the feel of "plopping pieces down on a board game"; and the probe built by the agent itself, because the subagents "lacked sufficient familiarity with my user intents and the overall vision". The board (`black-boxes` in the record) is plain SVG: pieces of one size floating above a white or dark board, doors on the faces the viewer sees, wires in the air from the caller's blue door to the server's green door with the request's flow, strands of references beneath each piece, a layer of tokens for shared references, declared districts and tunnel, quarter-turn rotation and a top-down projection, and a lid that unfolds into the folder map with the doors as wall pins. Its findings list eight forks and the builder's own residual critique. The owner's verdict, the same evening: "this is exactly the direction I'm looking for." They asked for the force graph's freedom of movement with an orthographic camera "so it still feels isometric even when panning and things stay sane sizes", a higher-contrast light mode, plainer hover text and a question mark in a corner in place of on-screen tutorial text; all four went in that evening, with a five-step walkthrough behind the question mark. They also asked whether a directory's outside dependencies can be known in general; the answer recorded in the probe's findings is that the docs already carry unresolved imports for the languages whose adapters emit them, that the C# adapter drops framework namespaces, and that package versions live only in manifests, which would need a Live Doc of their own.
- **Where the verdict went** (2026-09-28): the picture the owner approved is written into the vision as its own section, the World Map outside and the Local Map inside, reached by zooming, with the names on trial; eight of the record's twenty forks are closed by their words and ten stayed open, listed at the end of the record's README; nine after the manifests fork closed under the entry on openings. The doc format's growth list, now in the vision's step 3, is what the World Map needs before it can be drawn from the docs instead of from the estate's hand-verified file.

### Openings and the Basis of an Edge _(Recorded 2026-09-28)_

- **Decision**: the facts the World Map needs beyond imports are carried by the Live Docs, not read at render time. An opening a file serves is a public symbol with a kind that says which: `route`, `address`, `procedure`, `table`, `view`, `function`. A call is a dependency line linking to that symbol, with a qualifier for how the edge was observed: `contract` when both sides carry the same name, `configuration` when both carry the same address, none when observed from source. The graph edge carries it as `basis`. A call nothing serves stays as the opening's name, external. What a project stands on is the Live Doc of its manifest: `.csproj`, `packages.config`, `package.json`. The grammar did not change shape: the qualifier slot was open and the vocabulary grew.
- **Why**: the board probe drew its doors, wires and beard from the estate's hand-verified file and its project files, which the documentation rules call a side channel. Growing the doc format is the rule. The vision's tiers were named `basis` because tier is a word the owner's day job uses for deployments.
- **Where the matches are made**: at generation, through the workspace symbol index, which the adapters now receive on the main pass, exactly as imports and type references resolve. The one presumption is home and away: a script's route call is served at home, a C# client's away, when both serve it. Recorded in [Openings](openings.mdmd.md) with everything not covered.
- **Measured**: `oracle:compare` on the estate went from 8 to 17 of 20 hand-verified edges, with the compiler's 37 unchanged, and gained a bucket for project references, 3 of 3. The three left are the ones no scan of the files gives: a designer's fields, endpoint names built at run time, a row type matched by result columns.
- **What it changes upstream**: `.sql`, `.csproj` and `package.json` files now get Live Docs under the default globs, so this repository's five package manifests and the sample programs' project files and scripts have docs; a `package.json` is read as a manifest, not as configuration keys.

### Generator Gaps Noted by Earlier Specs _(Recorded 2026-09-27; unprioritised)_

Requirements written in 2025 and never implemented, kept as observations rather than commitments:

- A failure part-way through a run should not overwrite existing generated sections; today `generator.ts` has no per-file recovery.
- Renaming or moving a source file should carry its authored `Purpose` and `Notes` to the new doc; today the generator refuses to prune a doc that has authored content, so the old doc survives as an orphan (`live-docs:orphans` lists them) and nothing carries its text forward.
- Writes could be atomic (temp file, then rename) so a crash cannot leave a half-written doc.

Settled in September 2026: derived views (the graph index, the Explorer bundle) are regenerated on demand and never committed; only the per-file mirror is.

- **Faked symbol anchors in authored notes** _(found and closed 2026-09-27)_: ten Live Docs under `tests/integration/fixtures/` carried hand-written headings of the form `#### Name {#symbol-name}` in their authored Notes so that generated links to element ids, configuration keys and a reflection-resolved class had somewhere to land. The cause was adapters that linked to names they did not publish. It is closed: the markup adapter publishes element ids, the `.config` adapter publishes settings, connection strings, endpoints and services, the JSON adapter publishes key paths, and the C# adapter links reflection targets by their real symbol. The fakes are gone; the symbol audit would catch their return.

### Related Documentation Bridge _(Recorded 2026-09-27; in effect since 2026-01-06)_

- **Decision**: Existing markdown (READMEs, ADRs, design notes) is never rewritten or moved. A document joins the graph only because a Live Doc links to it, renders as a related-document node, and can be kept out of the bundle by pattern (`bundleExclude`).
- **Rationale**: "Do we throw out all their work?" For brownfield adoption the answer is no: bridge, don't replace.

### Explorer Panel in the Editor _(Recorded 2026-09-27)_

- **Direction, not yet designed**: a VS Code extension is expected to return as a panel that hosts the same static Explorer and re-renders it as files change; the earlier extension shell was removed on 2026-09-27 rather than carried. What is settled is the portability rule: the editor is a host, not a second renderer, and nothing may work only there.
- **Known cost, to re-measure**: in February 2026 a `--changed` regeneration took about 12 seconds for zero files, almost all of it `tsx` start-up, which is why the earlier design had the watcher notify rather than regenerate. Whether that still holds once the CLI is compiled is untested; the panel's refresh strategy is undecided.

### Testing Approach _(Updated 2026-09-27)_

- **Decision**: Vitest for unit and integration tests, as two projects in one config; Playwright for the Explorer. The integration project runs the real generator and CLI over fixture workspaces and imports sources directly, so no build precedes it.
- **Rationale**: Fast feedback; visual behaviour verified in a real browser rather than jsdom.
- **Retired 2026-09-27**: the VS Code Electron harness (`@vscode/test-electron` plus mocha) that hosted the integration suites. None of them used the VS Code API, and the harness cost a compile step, an 8 GB download cache, and `xvfb` on every Linux run.
- **Lint covers the tests again (2026-09-27)**: ESLint had ignored every `*.test.ts` and `*.spec.ts` "temporarily" because the typed rules crashed on files outside a tsconfig project. The typed rules now apply to package sources only, the untyped rules to everything, and the ignore is gone. Lifting it found import order, needless escapes and unused imports in the tests, nothing else.

## Descoped Decisions (Audit Trail)

The following decisions were explored and explicitly removed from scope during the Dev Day 70–72 codebase cleanup (February 2026). They are retained here for architectural traceability.

- **Baseline Inference & Fallbacks** _(Descoped 2026-02-17)_: GraphRAG-style LLM fallback for graph construction when native language-server signals are missing. Removed because the system relies exclusively on deterministic polyglot analyzers.
- **LLM Augmentation & Ingestion** _(Descoped 2026-02-17)_: Optional `vscode.lm` API integration for deeper change impact analysis. Removed because all modules were dormant with zero production callers; users bring their own AI assistants.
- **LLM Ingestion Pipeline** _(Descoped 2026-02-17)_: GraphRAG-style pipeline with chunking, edge extraction, and confidence calibration. Removed alongside the LLM augmentation decision.
- **SQLite GraphStore** _(Removed 2026-01-12)_: replaced by the mirror itself; "Live Docs ARE the database."
- **Language Server and Diagnostics** _(Removed 2026-02-18; the remaining LSP shell and the extension package removed 2026-09-27)_: the original ripple and diagnostics subsystem. Type-safe languages already have their own lint and IntelliSense; in-editor polyglot change detection was not mission-critical, and the tool's value moved to generating and showing the map. What survived until September was a 60-line server that answered no requests and a 78-line extension that registered one command.
- **Spec-Kit** _(Retired 2026-02-23)_: the bootstrapping scaffolding. Its specs, plans and task lists were migrated into `.mdmd` and have since been retired in turn.
- **Explorer HTTP Server** _(Removed 2026-03-10)_: the static bundle does everything the server did except open files in the editor.
- **AST Accuracy Benchmark, Benchmark Reports and Telemetry** _(Retired 2026-09-27)_: the mocha benchmark suite, the per-mode markdown reports under `reports/`, the manual benchmark workflow, the report builder and the inference-accuracy tracker. See "Accuracy Measurement" above for why. One observation from the November 2025 TypeScript oracle is worth carrying into the new one: it classified each edge as a runtime or a type-only binding, a distinction SCIP output does not make on its own.
- **Benchmark-only Inference Path and Fixture Oracles** _(Retired 2026-09-27)_: `packages/shared/src/inference` (regex heuristics plus a tree-sitter import extractor) was what the benchmark scored, but the shipped generator never called it. The C and Ruby "oracles" were in-repo regex scanners, so those two languages never had independent ground truth; SCIP covered TypeScript, Python, Rust, Java, C# and Go. The rebuilt oracle needs its own answer for C and Ruby. Three lessons carried forward: linking every C# partial-class peer flooded a Roslyn slice with false positives in November 2025, and only generated peers (`*.designer.cs`, `*.g.cs`) were linked after that; the shipped C# adapter has no partial-peer handling at all, and WebForms code-behind depends on controls declared in the designer file, so the tree-sitter adapter must cover it. A C oracle that scanned only `.c` files silently dropped every header-to-header include; headers are nodes. And the WebForms overrides file removed a real SCIP edge (`Default.aspx.cs → Default.aspx.designer.cs`) "to fit the heuristic", which is exactly the filter the Correctness rules forbid; it is recorded here as the cautionary case.
- **System Layer and Co-activation Clustering** _(Retired 2026-09-27)_: on-demand Layer-3 markdown that grouped files by statistically significant co-activation. The vision's "a system is a folder" supersedes finding systems by clustering, and the owner found the output noisy. The method, as dated history: a degree-corrected configuration model as the background, edges weighted per symbol, a Poisson tail test with Benjamini-Hochberg correction, validated against the fixtures cluster as a positive control. Two findings outlive it. Barrel re-export hubs inflate node degree until the graph's architectural signal disappears, which is why the package-level barrel was deleted on 2026-01-17 while module-level barrels stayed. Git co-change was rejected as a signal on 2025-11-10 because users' local trees differ and the output would not be deterministic. The owner's principle stands regardless of method: "It shouldn't be possible for our software to spit out useless or misleading statistical analysis. Do it the right way by default."
- **Headless Harness, Precision Report, Technical-debt Detector, Network Audit** _(Retired 2026-09-27)_: the headless harness replayed per-language fixtures through the generator and is covered by the Vitest integration project. `live-docs:report` compared the analyzer with a re-run of itself. `tech-debt` flagged files by size and age. `audit:network` and `safeFetch` guarded a network path the product no longer has; `SECURITY.md` now describes verification by inspection and by running the suites with no network stack.
- **Test Evidence Sections and the Target Manifest** _(Retired 2026-09-27)_: `Observed Evidence` on implementation docs, `Targets` and `Supporting Fixtures` on test docs, the evidence bridge that filled them from a generated manifest (`live-docs:targets`), coverage summaries, waiver files, and the lint rules and `evidence.strict` setting around them. A test's targets were its imports, already stored as its dependencies, so the sections wrote inbound edges a second time, which the edge-storage decision forbids; and because the manifest was generated and never committed, docs changed without their source changing. No coverage summary or waiver existed in the workspace when they went. Which tests exercise a file is read from the graph: a test file's outbound edges. The retiring commit removed `data/live-docs/` from `.gitignore` instead of deleting the last manifest, so `data/live-docs/targets.json` stayed tracked for a day and was rewritten by the package renames before anyone noticed; it was deleted on 2026-09-28.
- **Vendored Benchmark Fixtures** _(Retired 2026-09-27)_: seven pinned clones (ky, libuv, Newtonsoft.Json, mux, OkHttp, Requests, log) kept only their expectation JSON in the repository and were cloned on every gate run. The in-repo fixture corpus stays; see [Sample Programs](sample-programs.mdmd.md). Two dynamic patterns from the vendored code are candidates for hand-verified fixtures later: Requests' module aliasing (`requests.packages`, `requests.compat`) and rust-lang/log's macro-generated `$crate::__private_api` edges; neither is visible to a static scanner.
- **Copilot-era Steering and Planning Documents** _(Retired 2026-09-27)_: vendor-specific instruction files, daily-summary prompts, the capability-ID vision, the requirement, roadmap and backlog documents, and the falsifiability requirements were replaced by `AGENTS.md`, the rewritten vision, and the entries above. The chat archive was excluded from the Explorer bundle the same day.
